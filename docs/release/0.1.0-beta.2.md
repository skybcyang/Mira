# Mira v0.1.0-beta.2 Release 基线与分支迁移记录

- 状态：已标记的 prerelease 基线；分支迁移完成，当前 `main` 已继续演进
- 日期：2026-09-01
- 基线：`v0.1.0-beta.1`
- 结果：产品版本统一，完整产品线已迁移回 `main`

> 当前解释：`v0.1.0-beta.2` 已固定在提交 `8880a07`，不得移动。`main` 在 2026-09-01
> 已有后续提交并领先该 tag；仍显示相同 package version 不表示 tag 自动包含后续能力。
> 本文的变化范围只描述已标记的 Beta.2，最新源码能力以产品文档、用户手册和新鲜验证报告为准。

## 版本契约

- 根 `package.json` 的 `version` 是唯一产品版本源，当前为 `0.1.0-beta.2`。
- Desktop staging 从根包读取产品版本和 Electron 精确版本，不再维护独立版本常量。
- 私有 `packages/mira-bridge` 不声明产品版本；它与当前仓库源码一起构建。
- Git tag 必须使用 `v${package.json.version}`，已有 `v0.1.0-beta.1` 与 `v0.1.0-beta.2` 都不移动、不覆盖。
- “Desktop internal Alpha”描述分发成熟度，不建立第二套 SemVer。

## 相对 Beta.1 的变化

- 用户可以从 App bar 填写计划名称、最终成果和至少一个有序步骤，在画布预览并显式绑定起始内容。
- 直接计划与方法应用共享 Card、Transformation、Run 和零自动运行语义。
- 新增 macOS Electron 44 thin shell、原生 workspace 选择、临时 loopback 凭据和双架构打包。
- Desktop 仍未签名、未公证、没有自动更新，只用于内部验证。

## 发布门禁

合并、迁移 `main` 或创建 tag 前必须在对应提交上运行：

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm build
pnpm build:bridge
git diff --check
pnpm desktop:make:arm64
pnpm desktop:smoke:packed:arm64
pnpm desktop:make:x64
pnpm desktop:smoke:packed:x64
```

可见桌面 UI 与 `390x844` 响应式检查必须无横向溢出，浏览器 console warning/error 为零。
测试和打包使用临时 workspace，不提交或改写用户 Board、Run、Workflow 数据。

## 分支迁移结果

1. Beta.2 候选通过 PR 合入 `main`，GitHub 默认分支和 `origin/HEAD` 均指向 `main`。
2. 已在合并提交 `8880a07` 创建 `v0.1.0-beta.2` tag。
3. 后续功能继续从最新 `main` 使用短期 `codex/<task>` 分支并通过 PR 回主干。
4. `v0.1.0-beta.1` 与 `v0.1.0-beta.2` 均保持不可移动；新功能需要新的版本与发布门禁，不能回写旧 tag。

当前工作区中的真实 `boards-v2/`、`runs-v2/`、`workflows-v2/` 不属于迁移提交。分支切换、
合并与验证必须在干净 worktree 或 GitHub PR 上完成。

## 回滚

- PR 合并前直接关闭 PR；不重写远端历史。
- `main` 迁移后若发现阻断问题，从最后一个已验证 tag 建立 `hotfix/<issue>`，修复后通过 PR 回主干。
- 不回退或移动 `v0.1.0-beta.1` 或 `v0.1.0-beta.2`；不因代码回滚删除已经产生的用户数据。
