## 1. 设计结论与交付边界

| 编号 | 本轮建议 | 用户获得的变化 |
| --- | --- | --- |
| D1 | 顶栏保留画板与高频命令，左侧用可收起的五项导航 | 内容区域从顶栏下面直接开始；工具入口位置稳定 |
| D2 | 一个详情任务支持普通、展开和来源核对 | 连续写作时扩大空间，查来源后回到原光标位置 |
| D3 | 待比较结果进入独立宽比较窗口 | 完整阅读两份正文，明确增删和采用对象 |
| D4 | 灵感池默认静态摘要浏览，可切换紧凑列表 | 先扫读再选择，筛选时保留已选顺序 |
| D5 | 统一三个宽度档及任务互斥规则 | 小屏不叠多个操作层，保存、返回和采用始终可达 |

视觉沿用 Studio 的灰绿、细网格、系统字体与轻边框；Editorial、Blueprint 的浅深两套继续使用各自 tokens。本轮不重新设计卡片类型、执行机制、文件能力或画板生命周期。

现有顶部选择工具栏、底部成果目标、详情展开、来源预览和版本恢复都继续复用；变化集中在位置、层级、占用空间、比较阅读和返回路径。导航、展开和浏览密度不写 Board、不进入 CanvasHistory。

## 2. 页面结构与尺寸

### 2.1 区域分工

```text
顶栏：Mira · 当前画板       搜索卡片或命令       撤销 / 重做 / 新建内容
┌───────┬──────────────────────────────────────┬──────────────┐
│ 工作  │ 顶部：来源选择工具栏 / 选择工具栏 / 快捷入口 │ 共享任务槽位 │
│ 导航  │                                      │              │
│       │           当前画布                    │ 内容 / 关系  │
│       │                                      │ 版本 / 运行  │
│       │ 底部：来源顺序 + 下一份成果目标          │ 或方法等任务 │
└───────┴──────────────────────────────────────┴──────────────┘
```

顶栏说明“在哪个画板”；导航说明“打开哪项工具”；画布承载“正在处理什么”；右侧承载“当前阅读或编辑任务”。不增加画板大标题区、统计概览或第二套工作模式。

### 2.2 布局参数

本节保留首版尺寸决策；已测量的浏览器尺寸与覆盖边界见实施验证，未测组合不推定通过。

| 参数 | Desktop ≥1100px | Compact 720–1099px | Mobile <720px |
| --- | --- | --- | --- |
| 顶栏 | 高 58px | 高 58px；搜索收为图标 | 高 52px；板名、搜索、新建；更多在底部导航 |
| 导航 | 默认 84px，可收为 54px | 固定 54px 图标导航 | 底部五项，高 60px + 底部安全区 |
| 普通内容详情 | 右侧占位 392px | 右侧覆盖 392px | 全宽任务 sheet |
| 展开内容详情 | `min(800px, W - N - 360px)` | `min(800px, W - N - 32px)` 覆盖 | 同一全宽任务；隐藏展开按钮 |
| 比较窗口 | 宽 `min(1120px, W - 64px)` | 宽 `W - 32px` | 全宽全高 |
| 灵感窗口 | 宽 `min(1040px, W - 64px)` | 宽 `W - 32px` | 全宽全高 |
| 非全屏模态高度 | 不超过 `H - 64px` | 不超过 `H - 32px` | 以动态可视高度为边界 |
| 内容内边距 | 普通详情 20px；展开 24px | 20px | 16px |

`W/H` 是应用可视尺寸，`N` 是实际导航宽度。桌面右侧占位后，选择工具栏、dock、缩放与 minimap 都以剩余画布为边界；保持原 viewport 的平移与缩放值，不在开关面板时调用全图适配。

| 示例宽度 | 实际导航 | 展开详情 | 画布情况 | 来源呈现 |
| --- | --- | --- | --- | --- |
| 1440px | 84px | 800px | 剩余 556px | 并列 |
| 1280px | 84px | 800px | 剩余 396px | 并列 |
| 1100px | 84px | 656px | 剩余 360px | 同层往返 |
| 1024px | 54px | 800px 覆盖 | 原画布在背后，不重置坐标 | 并列 |
| 390px | 底部导航 | 全宽 | 任务期间背景不可交互 | 同层往返 |

Compact 和 Mobile 的任务覆盖层约束焦点、使背景不可交互；点击遮罩关闭仍走离开保护。Desktop 占位详情为非模态，可以继续查看和操作画布；切换编辑对象必须经过离开保护。

### 2.3 画布上方与下方的互斥

画布顶部按优先级只显示一类上下文工具：

1. 正在点选步骤来源：显示现有 SourcePickerToolbar；确认、取消与来源顺序优先。
2. 普通选择了 Card：显示现有 CanvasSelectionToolbar；整理、颜色、分组等仍按能力禁用。
3. 无选择：显示紧凑的“新建内容 / 多选”入口；窄屏新建已在顶栏时只保留多选。

显式多选的结束入口必须在选择工具栏可达，不能因为隐藏快捷入口而困住多选状态。来源选择期间隐藏普通 Context dock；其余状态继续复用来源 chips、最多三条建议和目标草稿。

Desktop 的 dock 最大宽 760px，距离可用画布左右至少 16px、底部 16px；宽度不足先压缩目标输入周边留白，再让来源 chips 独立横滚，不隐藏提交命令。工具栏内部横滚不能推动整页。

Mobile 的 dock 位于底部导航上方；收起态显示来源数与“想得到什么？”，展开时容纳目标输入。打开全屏任务后，底部导航和 dock 一并退出可交互层。软键盘出现时，当前表单命令跟随可视高度，不留下第二排悬浮命令压住正文。

## 3. 顶栏与导航

### 3.1 顶栏

按从左到右固定为品牌、当前画板、保存状态、搜索、撤销/重做、新建。Desktop 搜索建议宽 220–280px，空间不足可缩到 180px；Compact 与 Mobile 使用有可访问名称的搜索按钮。

板名一行截断，完整名称可通过选择器及辅助技术读取。移动端可省略 Mira 字标，不缩小板名、搜索或新建的触控命中区。保存状态保持单行紧凑，错误除状态点外必须有可读消息入口；不能仅用绿色点表示保存成功。

搜索继续使用当前命令面板，保持 Cmd/Ctrl+K、中文输入法保护、当前画板范围与取消不移动视口。命中 Card 仍只定位和选中；新导航项同时出现在命令列表，不产生第二个搜索实现。

### 3.2 五项导航的具体行为

| 入口 | 打开什么 | 返回与状态 |
| --- | --- | --- |
| 画布 | 收起当前可关闭任务，回到现有画布 | 草稿先经过离开保护；不清选择、不 fitView、不更换 Board |
| 灵感池 | 当前 workspace 的灵感选择器 | 模态打开；关闭恢复原触发焦点和画布上下文 |
| 方法 | 现有方法库，占用同一右侧任务槽位 | 使用方法继续原 PlanDraft 绑定流程；不会自动运行 |
| 文件 | 现有文件选择器 | 按宿主能力打开；不具备能力时给出现有不可用解释 |
| 更多 | 搭计划、画布版本、管理画板、模型设置、外观 | 复用原入口与权限；菜单关闭回到按钮 |

这些是工具按钮，不伪装成五个路由页签。“灵感池”名称统一替代入口处的简称“灵感”；正文仍使用“记录灵感”。活动工具用背景、图标与名称同时表达；“画布”不与打开中的工具同时标成当前工具。

桌面导航的收起按钮放底部，保留 44px 命中区与“收起导航 / 展开导航”名称。Compact 强制收起只是布局派生，不覆盖桌面偏好；回到宽屏恢复用户选择。Mobile 五项保留文字，更多菜单不得从屏幕底部向外溢出。

“更多”使用分组菜单而非设置仪表盘：工作（搭计划、画布版本）、管理（管理画板）、偏好（模型设置、外观）。打开子任务前先处理原任务离开意图。保留方向键、Home/End、Escape 和触发焦点恢复。

## 4. 完整阅读、编辑与来源核对

### 4.1 内容任务的结构

从上到下依次是任务标题与展开/关闭、四个原有详情页签、内容的“阅读 / 编辑”分段、状态提示、正文、固定命令区。标签与出处保留现有编辑能力，视觉上低于正文；错误、冲突与未保存提示优先于普通元数据。

任务标题使用当前摘要名称；完整 Markdown 保持原样渲染。摘要与正文首个标题可能重复，第一版通过弱化任务标题处理，不裁剪原文首行。文件引用仍只读，不显示编辑切换，也不增加样机中的假文件预览能力。

阅读字体沿用 body 字体，详情正文建议 14px / 1.75，长文行宽上限约 72ch；代码使用现有 meta 字体，代码块和表格局部横滚。画布内正文保持现有字号，不随本次详情调整改变卡片排版。

### 4.2 展开与来源

展开按钮只切换当前任务尺寸；正文编辑器不重新挂载，保留文字、标签草稿、光标、选区和滚动。阅读模式显示本地草稿时明确标“未保存”；切换阅读不保存 Version。

来源从现有有序来源入口打开；来源顺序和来源编辑继续由关系详情管理。预览中的来源名称、版本、当前/历史身份可读；历史快照与当前来源不能混用。链接失效或文件无法读取时在来源区说明，不用空白替代成功状态，也不阻塞原正文编辑。

| 条件 | 呈现 | 返回 |
| --- | --- | --- |
| 详情外框宽度 ≥736px | 正文与 240px 来源栏并列；间距 16px，正文剩余宽度至少约 432px | 来源栏自己的关闭按钮只关来源；主标题关闭按钮关闭整个任务并检查草稿 |
| 详情外框宽度 <736px | 来源替换同一任务的正文视区，显示“返回正文” | 返回后恢复原编辑焦点、选区与滚动，草稿不卸载 |
| 从窄变宽或从宽变窄 | 同一来源上下文在两种布局之间迁移 | 保留来源版本与阅读位置，不重新请求后自动换成最新内容 |

打开来源时记住原来的展开状态，临时扩展以便并读；关闭来源后恢复该状态。若用户在来源打开期间显式调整展开状态，以最近的用户选择为准，不能在返回时跳回过时宽度。

来源正文仅供核对；“管理来源”进入既有关系任务，属于任务切换，要检查未保存修改。不在来源预览里新增直接改依赖的拖拽行为。

### 4.3 保存与离开状态

| 状态/动作 | 显示与反馈 | 保留与写入边界 |
| --- | --- | --- |
| 干净阅读 | 当前版本、编辑入口 | 关闭零写入 |
| 有修改 | “未保存”；保存与保存并新建可达 | 绑定开始编辑时的 baseVersionId；外部刷新不替换草稿 |
| 保存中 | 原位置显示“正在保存…”；互斥正文提交 | 不把请求期间的新输入误标为已保存 |
| 保存成功 | 版本号更新，“已保存” | 正文新增 Version；标签独立保存，不新增“保存全部”事务 |
| 保存冲突/失败 | 保留编辑器，显示错误和下一步 | 不自动用新 Head 重试；保留本地内容 |
| 关闭、换卡、换页签、切板、换工具 | 共用“继续编辑 / 放弃修改”确认 | 继续则撤销离开意图并回到原焦点；放弃后才执行原意图 |
| 展开、切阅读、看来源、切主题 | 不弹离开确认 | 同一个任务、同一份草稿；零保存 |

“保存并新建”继续遵守核心规格 §4.4.4 的顺序与不确定结果处理，布局不改变该流程。底部命令区从布局中占位，不用覆盖正文末尾的悬浮按钮；较窄时主次按钮分行，每个触控目标至少 44px。

## 5. 待比较结果

### 5.1 入口与阅读空间

Card、Transformation 与运行详情都保留“查看待比较结果”入口。运行详情先展示生成状态和简短摘要，完整比较打开一个宽模态；只有用户显式查看才打开，后台完成不抢焦点。存在待离开的编辑草稿时先走统一离开保护。

顶部显示“比较生成结果”、目标内容摘要、当前比较的版本；右上关闭。下方是“并排阅读 / 查看差异”，底部固定“稍后处理”“丢弃结果”“采用为最新版本”。关闭、Escape、遮罩和稍后处理都只退出比较，Candidate 仍通过原入口可达。

内容容器宽度 ≥900px 时左右并读，左为“当前版本 · vN”，右为“生成结果”；低于该宽度时按这两个标签纵向排列，模式名称相应显示“完整阅读”。各侧保留完整正文，状态与命令不插入正文段落之间。

桌面两侧独立滚动，首次顶端对齐；不默认按滚动百分比联动，避免不同长度文本错位。模式切换分别记住阅读位置，按钮焦点不跳走。窄屏使用一个纵向滚动区及固定底部命令；能明确到达两份正文，不截成摘要后直接要求采用。

### 5.2 固定比较基线

打开比较后形成页面内比较上下文：Board、目标 Card、Run、打开时的 Head ID（可为空）、该 Head 正文与 Candidate 输出。当前栏显示的是这次已读版本，后台刷新只显示“当前内容已更新”，不偷换其正文或采用基线。

用户选择“重新比较”才重新载入当前 Head、更新标签并回到新比较内容顶部。采用请求显式携带已读 Head ID；若服务器检测不一致，显示冲突并刷新事实，但必须由用户重新比较后再次选择采用。关闭重开属于一次新的比较。

比较锁针对该次决策共享：提交采用或丢弃后，两种动作同时禁用，明确显示进行中的动作。提交期间不允许另一条决策，也不通过关闭窗口取消已经发出的写入；保留窗口并提示“正在处理结果…”。终态或可处理错误返回后恢复关闭能力。

若结果已被处理，刷新后展示实际终态并撤掉决策按钮；未知传输结果先核对 Run/Head，再决定是否允许重试，不能把超时直接解释为采用失败。迟到成功仅更新原对象事实，用户已转到其他画板/任务时不重新打开比较窗口。

采用成功后，在原任务意图仍有效的条件下关闭比较并显示目标的版本视图，提示“已采用为 vN”；丢弃成功回到原运行详情。保留此前的画布位置与选择，不自动全图缩放。更详细的原子性以核心规格 §6.3 为准。

### 5.3 差异呈现与大内容

阅读模式复用统一 Markdown 组件。差异模式比较完整原始 Markdown：增加用 `+ / 新增`、减少用 `− / 删除` 并配合现有 accent/danger 语义色；保留行号与前后归属。浅深色都不能只靠红绿区分。

首版复用 [diffLines](../../src/v2View.ts) 的逐行结果与 [cardVersions](../../src/v2/cardVersions.ts) 的历史比较语义，不复制样机的段落算法。修改表现为删除和新增，不宣称语义改写、移动识别或字词级精确比较。两侧相同明确显示“正文没有差异”，仍保留完整阅读入口。

当前逐行算法使用二维矩阵，不能无条件处理大正文。首版设计上限为两侧合计不超过 200,000 字符且 `(左行数 + 1) × (右行数 + 1) ≤ 1,000,000`，计算前检查；超过时显示“内容较长，请使用完整阅读比较”，不在主线程启动该 diff。阈值需在实施验收中测量，调整要同时更新测试与本节。

阈值只影响差异视图，不截断存储正文、不把无法计算显示为“无差异”，也不新增采用限制。大 Markdown 的渲染仍需独立压力验证；不能用 diff 降级掩盖阅读卡顿。

### 5.4 与普通版本历史的关系

历史页保持时间线、来源信息和选中历史版与当前 Head 的比较；不因视觉复用而增加“采用 Candidate”按钮。恢复继续明确说明将新增一个版本。可以共用正文阅读与差异组件，但历史恢复和候选决策使用不同的动作、基线与状态。

## 6. 灵感池

### 6.1 稳定浏览与有序选择

首访默认摘要视图：结果区域使用静态摘要单元，标题来自正文投影、正文摘要三行、最多两个标签及剩余数量、更新时间。它不是完整 ContentCard，不提供连线、移动或几何字段；不使用漂浮动画、随机排序或瀑布流。

结果区域内部宽度至少 600px 才用两列摘要，其他情况单列；单元从左到右、从上到下，DOM 与视觉次序一致。紧凑列表复用同一数据顺序，每行两行摘要。视图切换记住首个可见条目，有序选择不变；不自动清空查询。

每项主体是选择按钮，显示编号与 `aria-pressed`；“阅读全文”是相邻独立按钮，避免按钮嵌套。全文在同一窗口的阅读视区打开，返回后恢复查询、筛选、顺序与焦点；不增加第二层弹窗。

Desktop 右侧已选栏 240px；空间不足时采用“结果 / 已选（N）”分段切换。已选栏使用短摘要、版本标识、上移、下移、移除，排序按钮触控可用。筛选隐藏已选条目时，已选栏仍保留它，不能提交时重排成检索结果顺序。

关键词、标签组合与选择快照的语义沿用核心规格 §4：关键词不区分大小写，多标签取交集；重新载入池不静默替换已选的版本。摘要与列表只是密度偏好，不扩大到跨工作区搜索。

### 6.2 记录与添加

“记录灵感”在同一窗口替换检索主体，沿用正文、常用/自定义标签与独立保存；保留原检索和已选上下文。输入法组合状态、未提交自定义标签和失败保留草稿按现有契约处理。

从有修改的记录表单返回或关闭，使用同层离开确认；继续编辑恢复焦点，放弃后才返回。确认不是第二个模态。Escape 先处理当前表单/确认，再返回检索，不在一次按键中同时关闭整个窗口。

| 状态 | 呈现与动作 |
| --- | --- |
| 池加载中 | 固定结构的加载提示；已选快照保留，来源未就绪时不提交 |
| 池为空 | “还没有灵感”，提供“记录灵感” |
| 检索无结果 | “没有找到匹配的灵感”，提供清除筛选；已选仍可查看 |
| 无选择 | “添加到当前画板（0）”禁用，记录功能独立可用 |
| 添加中 | 锁定该批选择与提交；显示“正在添加…” |
| 添加成功 | 关闭窗口，提示“已添加 N 条灵感到当前画板”；原选择、草稿、详情和视口保留，不自动定位新卡 |
| 添加失败 | 保留查询、标签、顺序及快照，显示错误；按现有传输策略决定能否重试 |
| 当前画板不可写或未打开 | 禁用添加并说明原因；允许独立记录灵感 |
| 记录成功 | 保持窗口打开、刷新结果、清空已保存正文；不自动选中新记录 |

本轮不增加“添加后自动作为来源”选项。需要新卡参与推进时，用户回到画布显式选择；添加命令本身遵守 INSP-08。

## 7. 状态所有权、焦点与反馈

### 7.1 状态寿命

| 状态 | 保存位置与寿命 | 切换规则 |
| --- | --- | --- |
| 导航展开偏好、灵感浏览密度 | 本机 UI 偏好；新增值需命名及版本约定 | 不写 Board/备份；存储不可用时退回默认，不影响内容命令 |
| 详情展开、来源阅读位置 | 当前页面的当前详情任务 | 关闭任务后重置；只改宽度不重置 |
| 内容与标签草稿 | 既有草稿 owner | 不新增跨刷新草稿持久化；切对象走统一离开意图 |
| 检索、有序灵感快照、记录草稿 | 当前灵感任务 | 子视图往返保留；真正退出按确认结果清理 |
| 比较模式、两侧滚动与已读基线 | 当前比较会话 | 更新事实不换基线；重新比较显式开启新基线 |
| 选择、目标草稿、视口与 CanvasHistory | 现有 Canvas Store | 导航布局不额外清空；Board 切换按现有契约处理 |

独立编辑器、来源预览和模态层不各自保存一份“当前 Card”真值。UI 状态只引用 Board/Card/Run 的稳定身份，所有异步回写继续校验原 Board 与原任务意图。

### 7.2 焦点与键盘

1. Desktop 导航使用普通按钮顺序；图标模式有完整名称和悬停/聚焦提示，活动状态可被辅助技术读取。
2. 非模态详情不圈住键盘；模态比较、灵感和窄屏任务使用焦点约束，背景不可点也不可 Tab 到。初始焦点放标题或首个阅读控件，不默认放“采用”或“丢弃”。
3. Escape 只处理最上层当前意图：组合输入/编辑局部状态 → 同层确认或菜单 → 来源子视图 → 当前任务。一次按键不得连关两层。
4. 关闭返回实际触发按钮；若已卸载，依次回到所属任务的稳定标题/入口，再到对应导航按钮。不能聚焦不可见旧节点。
5. 正文选字、链接、代码滚动与输入框撤销维持原生规则；画布删除、全选和撤销不能穿透编辑区或模态。
6. 触控命中至少 44px，包含收起导航、排序、关闭、来源返回和尺寸按钮；视觉图标可保持 16–18px。
7. 200% 浏览器缩放按实际 CSS 可用宽度重新布局；焦点环不能被面板裁切，键盘焦点位置进入可视区域。

### 7.3 反馈文案与动效

| 场景 | 建议文案 | 强调方式 |
| --- | --- | --- |
| 展开详情 | 展开阅读区 / 收起阅读区 | 图标 + 可访问名称 |
| 来源返回 | 返回正文 | 可点击文字，不仅左箭头 |
| 草稿离开 | 有未保存的修改；继续编辑 / 放弃修改 | 共用确认，默认保留草稿 |
| 比较基线变化 | 当前内容已更新，请重新比较后再采用 | 固定提示 + 重新比较 |
| 比较暂未处理 | 稍后处理 | 普通次要按钮；不改结果状态 |
| 差异过大 | 内容较长，请使用完整阅读比较 | 行内说明，不冒充错误或相同 |
| 添加成功 | 已添加 N 条灵感到当前画板 | polite 通知，不抢焦点 |
| 请求结果未知 | 正在核对处理结果，请稍候 | 暂锁重复命令；允许读取结果状态 |

布局切换建议 160–200ms，优先简单尺寸/淡入过渡；不做卡片飞入、结果漂浮或自动巡游。用户设置减少动态效果时直接切换。状态消息按事件播报一次，不把计时器每秒更新都送入 live region；失败用 alert，普通保存/添加成功用 polite。
