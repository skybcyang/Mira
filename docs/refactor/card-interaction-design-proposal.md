## 先看这五个决定

阅读本节约 2 分钟。D1-D5 已获确认并同步权威文档；下表保留设计时的取舍。

| 决定 | 建议 | 需要明确的边界 |
| --- | --- | --- |
| D1 文字与卡片操作 | 标题栏拖卡，正文选字；单击仍选卡，Enter/编辑按钮进入编辑 | 原生文本复制与 Mira 内部卡片复制分开，不新增应用级系统剪贴板能力 |
| D2 阅读与编辑 | 卡内保留可滚动正文；同一个详情任务支持扩展宽度、阅读/编辑与来源查看 | 宽度与阅读视图变化不卸载草稿、不另建内容对象；窄屏同层往返 |
| D3 尺寸与整理 | 固定字号、尺寸预设、所选对齐/等距；一次整理一次撤销 | 尺寸撤销是新增历史契约，须与原子基线校验一起交付 |
| D4 连续记录 | 保留普通新建，编辑器另提供“保存并新建” | 先保存成功再建下一张；两次写入不伪装为原子事务，不自动清除空卡 |
| D5 推进可见性 | 来源预览、历史来源对照、可选的运行影响预览，步骤修改仍进入原关系详情 | 不新增执行引擎、全局 run-all、自动上下文、自动方法安装或普通关系线 |

## 1. 目标与范围

1. 在三张不同长度的材料之间阅读、选字、修改与移动，不误触另一类命令。
2. 编辑成果时可以核对来源，离开预览后仍保留草稿、光标与滚动位置。
3. 内容、状态、工具栏变化不改变 Card 外框；用户整理的范围可预测、可撤销。
4. 用户执行之前可以查看预计路径，明确来源、更新原因和执行终点。
5. 保持统一 Card、普通 Transformation 与现有版本/Run/Candidate 安全语义；沿用现有六套外观和 Lucide 图标，不做全站换肤。

暂不增加语义卡片类型、普通关系线、PDF/图片内容格式、外部摘录采集、系统剪贴板导入、全图自动布局、推导链折叠或后台执行。已有 Markdown/file-reference 区分保持不变。

## 3. B1 操作边界

### 3.1 卡片命中区

| 区域 | 点击/按键 | 拖动 | 规则 |
| --- | --- | --- | --- |
| 标题栏空白与标题 | 单击选卡；Shift/显式多选追加或移除 | 移动卡片；已选集合内拖动维持整组 | 标题不进入原生文字选区；开始拖动后不再把松手当点击清空多选 |
| 正文 | 无文本拖选的单击沿用选卡；链接保留独立激活行为 | 原生选字，不移动 Card | 完成文本拖选不改 Card 选择、来源顺序或 dock 草稿 |
| 正文在显式多选/Shift 下 | 选择卡片 | 不启动文字选区或移动；框选仍从画布空白发起 | 来源编号与现有规则一致 |
| 阅读、编辑、版本、状态按钮 | 执行自身命令 | 不拖卡、不连线 | 不冒泡触发 Card 选择；先走既有离开意图保护 |
| 连线/尺寸把手 | 保留各自操作语义 | 发起步骤/调整尺寸 | 互相错开；连线仍不接受普通 Card 到 Card 直连 |

新建、编辑与连线入口都保留可点击按钮，不要求用户发现双击、右键或快捷键。双击正文使用浏览器选词，不再增加一个隐含编辑动作；Enter 在无正文选区、无输入焦点且单卡选中时继续编辑。

### 3.2 键盘、文本与滚轮

1. textarea、输入框与编辑视图中的全选/复制/撤销保持原生行为；不触发画布历史。
2. 有源自卡片正文或来源阅读区的非空原生文本选区时，复制走浏览器文本复制；删除、粘贴、方向键、重复创建等画布命令不执行。点击标题栏或空白解除该选区后，才恢复卡片快捷键。不能只检查 event.target 是否为 input。
3. 阅读区有焦点时，全选限定当前阅读内容，不选择全部 Card；没有阅读焦点/文本选区时，沿用画布全选和内部剪贴板。应用不调用 Clipboard API，不将外部剪贴板解析成 Card；权威 UX 需明确原生文字复制不等于画布复制。
4. 鼠标/触控板位于有溢出的正文内时滚动正文，到边界不连带平移画布；在标题栏/画布空白区域使用既有画布导航。编辑器的 Esc、输入法 composition 和离开确认继续遵循现有规则，不在本次改成静默提交。
5. 触屏标题区及动作命中至少 44px，正文支持原生长按选字和滚动；选择多张卡使用常显多选入口。低缩放时可以先定位到可读比例再操作，不无限扩大把手导致跨卡重叠。

## 4. B2 卡片阅读与完整读写

### 4.1 画布卡片结构

| 部位 | 首版建议 |
| --- | --- |
| 标题栏 | 桌面 32px、触屏 44px；现有摘要标题一行截断，完整标题在阅读详情显示；右侧固定阅读/编辑命令，不显示固定材料/成果类型标签 |
| 正文 | 原始 Markdown 渲染，13px / 1.7；保留完整正文的内部滚动，不用 AI 摘要代替；首版允许与摘要标题重复，不用字符串裁剪移除正文首行 |
| 标签区 | 最多两个标签与溢出数量，沿用既有规则；有/无标签都预留同高槽位，避免切换标签挤动正文 |
| 底栏 | 固定高度，版本入口、必要状态和运行操作；非必要操作可降低强调，但不能移除占位导致正文尺寸变化 |
| 溢出提示 | 正文确有未读下方内容时在固定边缘显示继续阅读标记；它不盖住文字，不依赖渐隐蒙层；完整阅读命令始终可达 |

保留当前默认 `312 x 208`；窄/矮旧卡不自动回写尺寸，必要时精简元数据并保留展开入口。文件卡仍展示文件名与路径，展开后按现有能力读取，不冒充 PDF 或图片预览。代码长行只在代码区横向滚动，普通长词换行；本次不引入富文本块编辑器。

Loading、错误、空卡、Run、Candidate、stale 不改变外框。多个异常共存时保留可访问的完整状态，在底栏显示最高优先项及其余数量；待比较和活动运行的查看/停止命令不能被“更多”隐藏。标题、字号、按钮尺寸沿用现有 tokens，保持六套外观一致。

### 4.2 同一个详情任务

阅读按钮进入只读正文；编辑按钮与 Enter 直接进入编辑。内容视图内部使用“阅读 / 编辑”分段控件，不增加第五个对象页签。file-reference 只读，不出现可编辑选项。

1. 阅读/编辑切换只改变呈现，同一个草稿持续存在。编辑后看阅读视图时展示草稿并标记“未保存”，不是已提交 Head；不自动提交、不创建 Version。
2. 顶部 Maximize2/Minimize2 扩展或收回同一个 drawer。Desktop 普通宽度仍为 392px；扩展宽度为 `min(760px, 可用视口宽度 - 360px)`，给画布保留至少 360px；不自动 fitView、不改 viewport 值。Compact 使用距视口左右至少 16px 的同层覆盖面；Mobile 使用全宽内容 sheet。
3. 扩展、收回和来源预览不重新挂载编辑任务，保留正文、标签草稿、光标选区与滚动位置。侧栏换为方法/设置、切卡、切板或关闭仍走同一个 dirty guard。
4. 草稿绑定打开时的 Card/Head 基线；异步 Head 变化只能提示，不重设草稿基线。保存使用该草稿基线并处理冲突，不能把“提交时最新 Head”当作用户已审阅基线。取消修改是明确放弃当前草稿，保持既有确认与 Esc 契约。
5. 保存正文与标签仍为独立命令，不新增模糊的“保存全部”。正文命令固定在可视底部，软键盘打开时可达；迟到保存响应不能把用户新输入的字标记为已保存。

## 5. B3 尺寸与整理

### 5.1 用户命令

1. 单卡选中时显示边/角尺寸把手；只改外框与换行，不改字号。保留已有拖动吸附和对齐线，不另建第二套算法。
2. 选择工具栏的“整理”菜单提供宽度预设 `312 / 440 / 560px`、高度预设 `208 / 320 / 480px`，并可展开数值输入。建议新操作范围为宽 `280..960px`、高 `208..960px`，不以新范围拒绝或重写旧 Board；取消和冲突恢复旧尺寸，即使旧值在建议范围外。
3. 多卡支持同宽、左/右/顶/底对齐、水平/垂直等间距；同宽以前面明确选中的第一张为基准，菜单显示基准值，不重排来源。等间距至少三张，保持两端位置，按相应轴排序、ID 作为稳定同位次序；总空间不足时禁用等距，不自动推开端点。
4. 对齐、等距与尺寸命令只操作选中 Card；分组外框依实际成员更新，归属不变。组标题选择不隐式展开成来源选择；完整组移动仍走现有组命令，不在此偷偷移动跨组步骤。独立转化块位置保持不变，连线随端点重绘。
5. 把手拖动只做本地预览，松手提交一次，Esc 取消预览。预设点击提交一次，多卡必须全部成功或全部失败；保存未完成时暂锁同类整理命令。允许用户明确造成空间重叠，但不自动移动未选对象；边界、内容和命中框保持一致。

### 5.2 尺寸历史提案（D3，需先确认）

现有规格不承诺 resize 撤销。本草案建议把尺寸作为有限会话整理历史的一部分，与尺寸 UI 同批交付，而不是先上线不可撤销的批量同宽。

| 项目 | 提议契约 |
| --- | --- |
| 命令 | 扩展现有 `PATCH /boards/:boardId/organization`，可选 `sizes` 数组，每项显式携带 `cardId / width / height / baseWidth / baseHeight`；不创建尺寸对象或新资源 |
| 校验 | 数组 1..100、ID 唯一、Card 存在、目标/基线为合法几何；在同一 Board 写锁内比较尺寸。对齐位置沿用已有 positions 基线；不因界面推荐范围破坏旧值恢复 |
| 冲突与失败 | 沿用 `ORGANIZATION_INVALID` / `ORGANIZATION_CONFLICT` 与 lifecycle 门禁；整批零半写。新操作失败重新读取已提交几何，不把旧预览盖回其他窗口的新状态 |
| 历史 | 一次提交一条 organization 历史，反转 sizes 前后值；仍最多 50 条、切板/刷新清空，不增加持久撤销；确定失效移出、暂时失败保留 |
| 副作用 | 不修改正文、Version、Run、stale 或绑定文件；只保存现有 Card 几何及 Board revision。删除回执仍按批次计数，不能受尺寸历史扩展影响 |

上述请求字段是待确认接口草案，不宣称当前 API 已支持。确认后在核心规格、领域校验、Store 和故障注入测试中统一落实。

## 6. B4 工具栏与命令层级

继续使用一个固定顶部选择工具栏，不增加跟随鼠标的第二套工具栏；底部 Context dock 仍只负责推进。

| 状态 | 首层命令 | 其余入口 |
| --- | --- | --- |
| 单卡 | 数量、颜色 swatch、整理图标、复制、副本、更多、取消选择 | 更多含分组、删除和已有多选命令；粘贴在内部剪贴板有内容时显示 |
| 多卡 | 数量、颜色、整理、复制、更多、取消选择 | 副本/分组/删除沿用同一批量契约；模型来源编号不变 |
| 仅有内部剪贴板 | 已复制数量、粘贴、清空 | 不因切换 Board 丢失粘贴入口 |
| 删除确认 | 数量、取消、确认删除 | 原位替换工具栏；沿用引用预检与精确回执，不直接删除 |
| 触屏/390px | 数量、颜色、整理、更多；固定 44px 命中 | 复制/副本/粘贴/删除/取消选择均从同一菜单可达，不横向撑出页面 |

键盘进入 Card 时阅读/编辑/版本入口可见；运行停止常显。工具栏状态转移不移动卡片，关闭菜单将焦点还给真实触发按钮；若目标已删除，焦点回到画布容器。按钮使用已有图标加 tooltip/accessibility name，不用新的文字胶囊表示工具。

## 7. B5 连续建卡

保留 App bar、空白双击与现有新建快捷键。新增命令位于 Markdown 编辑器保存区的次级菜单：“保存并新建”；只对正文非空、无未解决基线冲突且未提交中的编辑任务启用。普通“保存正文”仍为默认，不添加全局快捷键。

1. 命令启动时冻结当前 Card、草稿正文与基线；本次提交期间锁定相关编辑/提交入口，防止后续键入被当作本次已保存内容。先使用普通正文保存；正文已保存且非空时跳过重复 Version。
2. 只有取得明确成功回执后才创建下一张空 Markdown Card。它继承当前卡的宽高，以原卡下方 24px 为意图位置并使用现有碰撞避让；不继承标签、颜色、分组、文件绑定、Version、出处或 Transformation。
3. 新卡成功后进入同一内容编辑器，聚焦空正文。只在原创建意图仍有效时定位新卡；用户切板、切换任务或主动导航后不得抢焦点。单次命令最多创建一张，不做批量空卡预创建。
4. 保存失败：停在原卡并保留草稿。保存成功但新建失败：原成果继续有效，显示“正文已保存，新卡未创建”，重试只重试创建，不追加相同 Version。响应不确定时先核对写入回执，不盲目重复创建；若现有创建契约无法对账，先补显式命令幂等性再上线此快捷动作。
5. 新建已提交空卡后退出，保留普通空卡，不因关闭或 Esc 自动删除；要删除使用现有确认命令。普通空卡创建仍不单独进入历史，首次正文仍按内容历史处理；这是两条正常命令的组合，不承诺跨保存/新建回滚。

尚未确认的体验差异集中在 D4：首版不引入“未落盘空卡草稿”或自动清理，避免新增一套对象创建规则。

## 8. R1 来源预览

### 8.1 入口与布局

1. Context dock 的来源标题变为明确的只读预览按钮；前移、后移和移除仍是独立按钮。关系详情来源行、内容视图的“查看来源”也复用同一阅读呈现，不通过改变 selectedCardIds 来打开预览。
2. 没有活动内容任务时，来源阅读占用既有详情槽位。有成果编辑任务时，预览作为同一任务中的辅助内容：扩展面宽度至少 680px 时采用两列，成果至少 320px、来源至少 280px，中间 16px；每列独立滚动，不嵌套 Card。
3. 宽度不足时，“查看来源”临时切换同层内容为只读来源，顶部 ArrowLeft 返回成果；原编辑器草稿、选区与滚动仍保留。Mobile 同一 sheet 内往返，不叠第二个 modal，不让软键盘挤压两栏。
4. 如果当前槽位是其他任务（方法、设置、运行等），预览进入该任务的临时只读子视图，关闭后原任务完整恢复；存在未确认的离开操作时先完成/取消该操作，不绕过现有 dirty/focus 保护。此子视图与成果辅助阅读共用一种上下文，不产生任意嵌套导航栈。
5. 预览没有编辑来源、恢复版本、运行或自动加入选择命令；需要编辑来源时走明确“打开来源卡”并触发现有离开确认。R6 的步骤设置也不在预览内复制一份。

### 8.2 内容与请求边界

| 来源 | 展示与更新 |
| --- | --- |
| 当前 Markdown | 打开时读取对应 Head 内容并显示 vN；阅读中 Head 改变则提示“来源有更新”，点击刷新后换内容，不静默跳动。实际运行仍取运行时 Head，不表示锁定了历史输入 |
| 当前 file-reference | 点击后才使用现有读取能力；标明“当前文件内容”及读取时间，不能只靠路径 Version 宣称与历史相同；加载、缺失、读取失败都有固定区域与重试 |
| PlanDraft 绑定 | 展示明确绑定的 SourceRef；绑定已过期时显示差异并仍要求用户按现有流程重新确认，不暗中换绑 |
| Run 历史输入 | 读取该 Run 的冻结 sourceSnapshot，不重新读取文件或用当前 Card 替代历史正文 |
| 对象变化/切板 | 请求绑定 Board、对象、版本和当前预览代次；旧响应不能覆盖新预览，删除时显示不可用而不自动定位其他同名对象 |

打开/关闭预览不清空自定义成果文案。来源实际变化时仍保留用户已输入的目标草稿并提示重新核对；建议刷新可以独立发生，不能覆盖人工目标。此项需与当前 ContextDock 草稿重置策略一起验证。

## 9. R2 来源版本与变更辨识

关系详情默认比较“最近已采用运行的输入”和“当前来源”，不是“最近尝试”；Run 详情默认看用户指定的那一次执行。目标被人工改写后，不把最近已采用运行的输入误称为当前正文的全部依据。

1. 摘要区显示比较的 Run、时间、来源数量与变化类别；当前来源按其顺序列出，历史来源按快照顺序列出。新增、移除与重排分别表示，不先按当前顺序重排历史来掩盖变化。
2. 点击一个来源进入正文对照：宽面左右分栏，窄屏使用“当时 / 当前”分段控件；保留标题、版本、文件读取时间与差异摘要。R1/R2 共用只读阅读器和请求代次，不另建比较用 Card。
3. Markdown 比较实际内容并区分“版本变了但正文相同”；stale 仍遵循既有规则，不能因 diff 为空私自清除 stale。文件比较当时 resolvedContent 与本次按需读取的实际内容，未知不能显示为相同。
4. 没有已采用 Run 时明确“尚无已采用结果”；历史 Card/Version 已删除仍可读 Run 快照，版本序号无法解析则只显示已有 ID/时间，不编造 vN。opaque 包外出处保持不可本地解析，不能因 ID 同名绑定本机对象。
5. 对照只读、不采用、不恢复、不运行；待处理模型结果仍进入现有 Candidate 对比，文件同步冲突仍进入绑定处理，两者不与来源差异混成一个按钮。

## 10. R3 运行影响预览

### 10.1 入口与展示

在步骤的运行命令旁增加 ListChecks 图标“查看运行范围”，点击后展开可选预览；正常 Play 仍直接执行现有“运行到这里”，不增加必经确认。关系详情可常显一行简要预估，不在每张步骤块预加载所有文件或历史。

预览使用既有详情槽位/同层 sheet，列出具体终点及上游顺序，每行显示“预计生成 / 保留 / 待检查 / 阻塞 / 尚未到达”。生成原因区分空目标、已有 stale、上游预计变化；不写出虚假的精确费用或用时。列表过长只在自身滚动，终点和已有执行/停止入口保持可达。

### 10.2 推导规则

1. 复用真实依赖顺序与单步决策。以只读推导记录预计会变更的目标：如果上游预计生成，下游空来源可标记“等待上游生成”，不直接误报永久缺材料；有已采用基线的下游标记条件更新，不预造 Version 或模型结果。
2. 已有人工正文且从未产生已采用 Run 的目标仍保留，不因上游预计变化强行重写，也不把其下游都标为必定变化。正文相同仍可能产生新 Version，不能假定上游重跑不影响下游。
3. 缺失 Run、无法读取文件、数据尚未载入、循环或消失对象显示待检查/阻塞，不伪装成保留。file-reference 未确认实际内容时不能仅凭 Head 相同承诺跳过；不为消除未知自动扫描全部 workspace 文件。
4. 遇到 Candidate、活动 Run 或不可用来源，标明具体停点及其后的未评估步骤。预览不改变现有执行门禁：如执行本来可能先生成阻塞前的上游，预览须明示，不承诺整条零写入；若要改成全路径预检再运行，需独立产品决策。
5. 任何 Board/Run/来源变化使预估过期，页面重算或显示待刷新；预览不成为持久计划。点击运行和每一步启动仍按最新状态重查，遇到失败/停止/Candidate 不推进到终点之后。

### 10.3 最小推导验收

| 情况 | 预期 |
| --- | --- |
| 全部为空，起始材料可用 | 上游预计生成，下游等待相应上游；不把中间空卡误报为原始材料缺失 |
| 上游 stale、下游原本最新 | 显示上游预计生成，下游因预计上游变化可能更新 |
| 上游更新，但中间是从未有已采用 Run 的人工成果 | 中间保留；后续按其真正来源是否变化判断，不传播虚构的新 Head |
| 第三步有 Candidate，前两步之一 stale | 显示可能先生成的范围、第三步阻塞，后续尚未到达；不显示全路径成功预估 |
| 文件内容未知或历史 Run 缺失 | 明确待检查；实际运行仍依已有安全门禁，不用预估授权执行 |

## 11. R6 步骤修改路径

成果 Card 的更多菜单提供“修改生成步骤”，直接进入对应关系的已有编辑表单，并将焦点放到目标说明。没有生产关系的手工材料不显示该命令；如果出现多个可选生产关系，不按数组首项猜测，先要求用户选择明确步骤。

1. 复用同一 Transformation 编辑、基线冲突与保存命令，不在 Card 上持久化 instruction/model。
2. 已有正文草稿时，先走离开确认；不自动保存正文再修改步骤。返回时定位原成果，不能隐藏未处理 Candidate。
3. 活动 Run、Candidate、只读 Board 等状态与原关系编辑入口一致；禁用项给出原因，不让快捷入口绕过服务门禁。
4. 修改只保存步骤，不启动 Run；已有“已调整计划”与模板不变提示继续保留。
5. 菜单命令不改变选择顺序或画布布局；键盘和移动端可达，不依赖节点旁常驻额外按钮。

## 12. R5 方法展示与示例

方法库继续是侧栏列表，不做新的落地页或模板市场。首行显示方法名、最终成果（来自最后一步 label）与步骤数；下一行显示具名输入槽及数量约束。完整步骤在同一行展开区查看，使用动作始终进入现有 PlanDraft。

1. 先制作三个候选示例：访谈材料到产品建议、技术资料到方案比较、零散笔记到文章草稿。作者须实际走完各步骤并人工核对成果，不能只填非空文本就宣称有效方法。
2. 每个示例都展示材料、逐步成果和方法提取结果，且使用脱离用户数据的临时 workspace；不包含密钥、真实个人材料或伪造的成功 Run。
3. 首版通过现有严格 BoardArtifact 导入提供“示例画板副本”，不新增示例自动安装器。导入只创建新身份，方法出处不安装；用户要保存方法时仍在副本中显式提取。
4. 示例内容与 WorkflowTemplate 分离，示例不是用户打开空画板时自动塞入的内容，也不提前绑定用户材料。正式方法仍通过正常验证、使用与删除入口。
5. 验收让新用户从一个示例辨认所需材料与最终成果，再在另一组材料上完成显式绑定；仅有图文说明不算方法复用交付完成。

## 14. 验收与未完成事项

1. 在临时 Board 用短笔记、长文章、文件材料完成选字、拖卡、多选、链接、滚动、复制、撤销；同一动作只影响正确对象，输入法操作不误触提交。
