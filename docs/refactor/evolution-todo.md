### B6 首版范围与开发要点

文本首版已完成以下用户流程与开发契约，规格以[核心规格 §4.4.5](../specs/core-specification.md#445-文本提取清单与拆卡2026-09-12)为准。[本批验证报告](../validation/2026-09-12-content-extraction-validation.md)分别记录产品、浏览器、两次真实 Kimi 输出和工程证据。差异对照、更多真实材料质量验证和原生设备验收分开继续。

#### 首版用户流程

- [x] **明确发起提取**：选中内容卡或文件卡后，通过「提取为多张卡片…」进入现有右侧任务面板，确认来源并自由填写提取要求。输入默认留空，不预选观点/章节等维度、不提供自动推荐，不要求先指定数量。此入口不增加全局模式或导航。
- [x] **添加步骤与运行分离**：添加提取步骤只创建普通 Transformation 和一个空目标 Card，保持零 Run；用户明确运行后，模型直接生成已划分条目的结构化清单。清单作为可见普通成果 Card 的版本保存，不生成一大段正文后按长度机械切割，也不把多目标运行塞进现有单目标契约。
- [x] **预览并确认拆卡**：清单卡提供「拆成卡片…」。同一个右侧任务面板用平铺列表显示标题、正文摘要、可用出处、总数与选中数，支持全选/取消、编辑标题正文、查看依据和调整顺序。初始全选；取消勾选仅表示本次不创建。编辑属于本次拆分草稿，不静默改写素材或清单；确认按钮明确显示「创建 N 张卡片」，选择为零时不可提交。
- [x] **创建与回到画布**：确认后整批创建有独立身份的普通 Markdown Card，不再调用模型，不自动创建 Transformation、分组或普通卡间连线。按用户顺序碰撞避让落位，保留可追溯出处；保持可读缩放并尊重用户在请求期间的新导航。成功提示数量，并纳入受现有引用检查和会话窗口约束的批量创建撤销。
- [x] **重新运行延续同一路径**：显式重跑同一提取步骤只追加清单版本；运行期间 Head 改变仍进入 Candidate，采用后才用该结果拆卡。再次打开拆分面板可查看此前创建的批次/卡片及对应清单版本，提示本次将创建新卡片；用户再次选择并确认。已有卡片、人工修改及其后续步骤不被覆盖、删除或自动重跑。

#### 开发契约与边界

- [x] **结构化条目契约**：定义格式版本、条目身份、标题、正文、顺序与可选来源定位；列表与普通可读/可编辑正文如何共存只有一个版本真相，不创建第二套隐藏内容对象。手工编辑、恢复旧版本和采用 Candidate 后必须重新验证可拆分结构；不能凭任意编号 Markdown 猜出条目。空条目、重复标识、畸形输出与截断需明确反馈，保留实际结果，不静默修复为“成功”。
- [x] **读取与数量边界**：先支持普通文本及已经可靠解析的文件；章节可利用真实标题边界，观点按用户维度由模型提取。视频观点依赖可核对的字幕/转录和真实时间定位；无对应读取能力时明确不可用，不能声称已理解画面。明确长度、条目与请求大小上限；现有单次 Card 批量创建为 `1..100`，不能循环分批写入却声称整次原子成功，也不套用手动分支的 `2..16` 限制。超限应提示缩小范围或选择更少条目，不静默截断。
- [x] **版本与出处**：定义新卡对清单 Card/Version、版本内条目与创建批次的出处，以及向原 Run 冻结素材快照的追溯路径；页码、段落或时间定位只记录实际可核对的信息。file-reference 的路径版本不等于文件正文快照，重跑必须使用当次解析并冻结的内容。首版条目身份仅保证该清单版本内稳定，不承诺跨重跑匹配；卡片初始 Version 的 origin/sourceRunId 规则必须明确，不能伪造“模型直接运行到该拆分卡”。
- [x] **预览并发与生命周期**：预览绑定明确清单版本；Head 变化时保留草稿并提示，不偷换基线。提交时服务端复核来源/条目、选中顺序、合法内容、数量和 Board 可写状态；确定旧版是否仍可显式拆分及缺失来源/版本的错误策略。活动 Run、Candidate、清单删除、切换 Board 与过期异步回包均有明确处理，不绕过原有安全门禁。
- [x] **原子提交与防重复**：复用 Board 锁、整批预检和原子持久化；本批 Card、初始 Version、出处与必要批次记录一起成功或零写入。按钮防连点之外，还需定义响应丢失后的结果核对/请求去重机制；不盲目重试建卡，同一提交重试与用户明确再次拆卡是不同意图。失败保留预览草稿；不将生成清单和之后拆卡伪装成一个跨阶段事务。
- [x] **撤销与可移植性**：一次拆卡对应一个当前会话 create history，撤销只处理该批新卡，保留清单与 Run；已有结构引用时沿用拒绝规则，重做不重复创建或丢失出处。明确复制、删除、BoardArtifact 导入导出、备份和 Checkpoint 对条目/批次出处的保留及 ID 重映射；历史缺失/包外出处不可碰巧解析为本地同名对象，旧数据继续合法，不扩大引用文件正文的备份范围。
- [x] **复用现有运行边界**：提取设置与输出格式在重跑时仍有效，实际模型与材料快照随 Run 记录。核对「运行到这里」会跳过最新结果与显式「重新生成」的区别，不能靠伪造 stale 强制执行。若方法模板需要保留提取格式，先补模板保存/应用契约；拆卡确认不变成 Workflow 自动执行步骤或动态分支。

### 接入时必须解决的问题

- 读取工具负责取得内容，skill 指导一步怎样完成，WorkflowTemplate 保存已经走通的步骤组合。Mira 当前默认模型适配器是普通文本请求，没有自动加载 `SKILL.md` 或工具调用循环。
- 第一版优先内置少量已审阅的指导与读取工具；第三方 skill 先作为评估材料，不自动安装、执行其脚本或扫描用户其他技能目录。通用技能格式与工具运行环境分开评估。
- 明确技能选择、加载失败、上下文长度、版本与有效指令记录方式，以及 Run 历史、模板引用、导入导出/备份的兼容规则；不得让以后更新的 skill 改写旧 Run 的解释。
- 读取后的内容、出处与定位如何冻结，需要与现有 snapshot 对齐；引用文件正文当前不在备份范围，新增阅读能力不能暗中改变这一承诺。外部材料中的指令按来源数据处理。
- CardVersion、CAS、Candidate、显式运行和文件权限继续由应用代码保证，不能仅靠提示词约束模型。凡需改变当前产品契约的项目，先完成权威文档与用户决策。
