## 先做：基础卡片与交互

1. [x] **B1 明确选卡、选字、编辑与拖动边界**：沿用现有单击选择、Enter/按钮编辑和多选编号；核对编辑焦点下的全选、复制、撤销与文本拖选，不被画布命令截走。链接、按钮、滚动区不误触移动或连线。若允许预览正文直接选字，先确认文本选择与拖动命中区域，不默认改变单击语义。验收方向：三张材料间操作不误拖、不丢草稿；桌面、键盘与触屏均能区分对象操作和内容操作。
2. [x] **B2 扫读预览与长文读写（合并 R4）**：卡片保留真实正文片段、标题与必要状态，长文明确仍有后续内容，不另生成 AI 摘要替代正文；完整阅读/编辑评估扩展空间与就地返回。验收方向：同一 Card 与版本保存命令，无第二份正文真相；保留 dirty guard、异步 Head 冲突保护，退出返回原卡、原视口与入口焦点；不新增便签卡/文档卡身份或全局工作模式。
3. [x] **B3 可预测尺寸与所选范围整理（合并 R7）**：评估标准宽度、正文换行、有上限的预览高度，以及同宽、对齐、等间距和拖动提示。卡片 resize 与画布 zoom 分清；生成、hover 和状态变化不持续推挤布局。先核对已有对齐能力，再补真实缺口。验收方向：只影响明确范围，不改来源顺序、分组归属或关系；批量尺寸与位置变更的原子性、撤销、跨组步骤和视口规则须先确认。不自动整理全图，也不重启已暂缓的[推导链折叠](chain-collapse-design-todo.md)。
4. [x] **B4 高频操作渐进显示**：评估现有选择工具栏的操作距离；未选中卡片以内容为主，选中时呈现高频操作，多选只显示一套工具栏与明确数量，低频项进入更多菜单。验收方向：不复制另一套 Card/Run 命令，工具栏不遮挡正文、改动卡片尺寸或抢焦点；移动端不依赖 hover/右键，必要状态与入口保持可达。
5. [x] **B5 连续记录与建卡**：评估明确位置新建后直接输入，以及同尺寸、相邻不重叠的连续建卡。先确认空卡取消、未保存退出、保存后继续新建的行为及历史边界。验收方向：普通材料卡不自动连线或启动 Run；失败不丢输入、不留部分批量对象。本项不引入系统剪贴板，外部文本粘贴入板须另行产品决策。

## 再做：来源与 AI 流程体验

- [x] **R1 来源快速预览与编辑中核对材料**：参考 Flowith 的多节点引用与 AFFiNE 的 Center Peek，在不丢失成果草稿的前提下预览已选来源正文，减少详情对象往返切换。先确认单一侧栏槽位内如何承载，不叠加互相遮挡的面板。验收方向：预览不改变有序选择、不写 CardVersion、不启动 Run；关闭后保留草稿、焦点和画布位置，桌面与 390px 均可达。
- [x] **R2 历史输入与当前来源辨识**：参考 Heptabase 对实际读取内容的可见性，区分某次 Run 冻结的输入与来源当前 Head，并解释 stale 原因。验收方向：能核对具体 Run 的来源顺序和版本；来源成员、顺序或正文变化可辨识；缺失历史对象或无法读取当前文件时明确说明，不伪造当前内容或来源。
- [x] **R3 运行到这里的影响预览**：参考 Miro 的剩余步骤提示，在执行前展示预计生成、跳过、阻塞的步骤及明确终点。验收方向：用户能预测当前操作的影响；预览零 Run、零写入，不增加强制确认负担；不得只按当前 stale 数量静态计数，需考虑上游生成后对下游的影响。预览不是执行承诺，每一步仍按最新状态重新校验，复用现有有界编排与 Candidate 门禁。

- [x] **R5 人工教学示例画板与方法展示**：参考 Miro 的成果导向模板和 Cannoli 的示例工作流，展示“材料 -> 各步成果 -> 最终结果”，在方法列表中强化所需材料与预期成果。验收方向：用户能理解用途并在新材料上复用；模板仍只保存已验证方法，不携带具体正文或运行记录；示例内容与模板分开，使用方法仍显式绑定并保持零自动 Run。内置示例的来源、安装与身份策略须另行确认，不把未验证计划冒充正式方法。
- [x] **R6 缩短成果到步骤修改的路径**：参考 Miro 的就近 TASK 操作，评估从成果进入目标说明/指令编辑的操作距离。验收方向：仍编辑对应 Transformation，模型与执行设置不迁入 Card；不增加另一套运行入口或绕过草稿、活动 Run、Candidate 保护。

## 不照搬的设计

本轮类型取舍：保留统一 Card 与现有 Markdown/file-reference 内容区分；材料、想法、约束、草稿、结论用标签/颜色表达，清单、表格、代码先改善 Markdown 呈现。连线继续只表达 Transformation；输入角色、方向与运行状态是呈现，不增加“相关/支持/反驳/包含”等普通关系线。

重启条件：当 PDF/图片等材料成为主要输入且现有阅读能力不足时，单独讨论内容格式、预览和出处；当真实任务持续需要证据与论点关系时，单独讨论论证关系的产品方向。两者都先定义模型上下文、执行和可移植数据边界，不借基础交互改进隐式扩展。

- 不引入全局 run-all、无人值守、条件/循环或任意文件写入来追齐竞品功能。
- 不自动继承整个对话祖先作为上下文，不新增“追问优先/引用优先”全局模式。
- 不用 Card 颜色或特殊文本前缀定义执行语义；不把执行设置迁移到 Card。
- 不把跨位置同步文档直接套用为跨 Board 共享 Card；灵感入板仍遵循独立快照规则。
- 不把“保护人工修改”宣称为独有能力。Heptabase 的 Readwise 同步也有人工编辑保护；Mira 应验证版本、Candidate 和受控重跑的完整体验，而非依据公开资料缺失推断竞品没有保护。
