## 2. R1：独立输出要求

风格负责表达，Skill 负责处理方法，工具负责执行。风格和 Skill 最终都通过指令影响模型，放入 Skill 不增加形式上的强制保证。风格应拥有同等的全文、版本、历史与方法复用能力，不必占用 Skill 名额。

默认“卡片简洁”：直接表达核心观点，短句短段，省略寒暄和重复说明，保留必要事实、限定、不确定性与出处；用户具体要求优先。设计覆盖均衡表达、详细展开和明确调整规则，默认不强制统一字数或点数。

字符上限、格式等可计算约束单独配置并由程序检查；语义保真仍需真实材料评测。检查失败保留正文与诊断，不静默截断或自动重跑，不改变现有 Head/Candidate 写回规则。

workspace 可保存新步骤默认风格，创建时解析并冻结。已有步骤不随默认改变，方法复用原快照；旧数据缺字段沿用原行为，明确升级才采用新规则。规则随步骤、Run、方法、Artifact、备份与 Checkpoint 保留，不携带秘密或执行权限。

## 3. R2：显式 Skill 与依赖

默认不选，每步仍只选一种。内置、自定义和明确导入的纯文本指导可在同一目录阅读、调整、移除及升级，普通运行自动带入冻结文本。不自动扫描本机目录、推荐或叠加 Skill。

Skill 声明必需/可选工具依赖时，用户明确配置范围，不因选中指导自动授予权限。缺必需依赖可以保存草稿/计划，但阻止相关步骤运行。代码、安装说明和工具接入不能成为加载文字的副作用。

## 4. R3：统一工具能力

工具按能力展示，来源标识为内置、MCP 连接或 Python 脚本。用户选具体工具，并确定输入范围和调用方式：

- 模型按需：允许模型在已选范围内调用；未使用不是失败。
- 生成前执行：完整绑定参数，按显式顺序执行确定性工具；必需项失败停止。
- 生成后检查：确定性检查真实成果，输出诊断，不自动修改或再次调用模型。

支持的方式由工具声明并由宿主核对。固定处理是一次普通 Run 内的阶段，不构成新的执行画布、条件/循环或后台 Workflow。

默认只给本次冻结来源与选区。连接内资料、新 URL、额外文件和外部写入分别定义允许范围；超出范围时先进入可见审阅，不先执行再通知。模型、Skill 与服务注解不能自行授予权限。

## 5. R4：MCP

能力管理覆盖远程与本地进程连接、身份验证、握手/目录测试、逐工具可用性、断开、失效与更新。建立连接不等于所有工具可用，更不等于本步全部启用。

连接身份与工具名共同标识能力，方法导入重新绑定；不能仅按名称匹配。凭据属于宿主秘密配置。schema、代码或访问声明变化需重新核对，不能后台扩权。

远端只读声明不是宿主可强制保证。外部读取应说明数据去向并保存必要出处；外部写操作审阅具体目的地/内容，授权绑定本次请求，回包不确定不盲目重放。资源留存与数据包范围须先补核心规格。

## 6. R5：Python

完整设计区分已审阅脚本和模型临时代码。前者明确登记代码、版本/摘要、依赖、输入输出与权限，作为工具选择；后者明确允许生成代码，再审阅实际代码及范围后执行。代码或权限变化使原审阅失效，不自动登记为长期脚本。

运行环境、安装依赖、测试、执行与导出分离。默认只读冻结输入副本、临时输出、受限资源，无真实 workspace/秘密/网络访问；没有可靠隔离的宿主显示不可用，不把 venv 或普通子进程称为安全沙箱。

脚本只返回中间证据或待预览文件，不能直接写 Board/Run JSON。最终成果仍为普通 Card，附件持久化/导出需另有明确契约。

## 7. Run、历史与方法

一次 Run 固定来源、目标基线、风格/Skill、工具集合及策略。记录真实调用、检查与结果；等待代码或操作审阅作为可见活动阶段，继续受活动 Run 门禁保护，不是 Candidate。

停止后不发新调用，迟到结果不改 Head；重启中断不后台续跑。目标变化仍走 Candidate；外部操作已发生不伪称可以撤销。

方法保存规则与能力需求，不保存授权、密钥、机器路径或临时代码批准。应用后一次列出待绑定资源，可先铺计划但阻止缺依赖步骤运行；不自动安装资源。
