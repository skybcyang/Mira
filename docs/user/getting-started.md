# 第一次用 Mira：从验证记录推导交付边界

[返回项目介绍](../../README.md) · [看更多案例](use-cases.md) · [完整手册](user-guide.md)

这个练习从 Mira 的实际验证记录出发，完成「写材料 → 添加步骤 → 生成 → 自己修改」。只用一张材料卡开始，问题仍然需要真实推理：哪些证据支持源码交付，哪些不能证明客户端可用？配套案例已用 Kimi K3 实际生成，你也可以换用自己的模型。预留约 5–10 分钟，模型耗时因服务而异。

## 先打开 Mira

如果已有内部桌面包，打开应用并选择一个可读写文件夹作为工作区。当前桌面包仅用于内部测试；[获取方式与平台说明](../operations/desktop-internal-builds.md)。

从源码运行则先安装 Node.js `>=22.12.0` 与 pnpm，在仓库根目录执行：

```sh
pnpm install
pnpm build
pnpm start
```

在浏览器打开 [Mira](http://127.0.0.1:56300/graphmind/)。默认在仓库内保存数据，需要独立文件夹时参考[工作区配置](user-guide.md#13-standalone三条命令启动)。同一工作区不要同时开启桌面版与另一服务实例。

点击右上角「系统设置 → 模型设置」，填写你使用的服务地址、模型 ID 与所需密钥，先「测试连接」，再「保存设置」。这些网页设置只对当前服务进程有效，退出并重启后可能需要重新填写。

选择来源后，下一步建议也可能调用模型并发送来源全文。本练习只使用下方的项目文档摘要。没有模型也可以完成写卡、编辑与添加步骤；生成需要可用的模型连接。

## 1. 建一张自己的画板

点击顶栏当前画板名称，选择「新建画板」，输入「发布证据初审」，点击「新建并打开」。

你会看到一张空画布。桌面左侧是工作工具栏；窄屏时工具栏位于底部。

## 2. 写下第一份材料

点击工具栏「新建」，或双击画布空白处。把下面整段复制到正文编辑器：

```markdown
# Mira：一份交付证据摘要

## 已记录的事实
- 2026-09-10 源码就绪报告记录测试、类型检查与构建通过。
- 桌面 CI 报告记录 macOS arm64/x64 和 Windows x64 打包与 packed smoke。
- Windows 的构建和启动检查不能替代客户端 UI 验收。
- 桌面包仍为内部 Alpha，未签名、未公证，没有自动更新。

## 来源与边界
来源：docs/validation/2026-09-10-open-source-readiness.md、
docs/validation/2026-09-09-desktop-ci-validation.md、
docs/operations/open-source-release.md。
这是案例作者的阅读摘要，请回到原报告核对范围与日期。
不能据此断言仓库已公开，或正式桌面版已经发布。
```

点击「保存正文」，或按 `Cmd/Ctrl + Enter`。关闭详情回到画布，你应该看到一张有正文的材料卡。材料、草稿与成果使用同一种卡片。

## 3. 告诉 Mira 下一步要什么

单击卡片标题栏选中它，底部会出现来源和成果输入区。确认来源是刚才的材料，再输入：

```text
区分源码可运行、安装包能启动、客户端可用三层证据。
逐项写出当前材料能支持的主张、不能支持的主张与下一项验证。
把事实和你的建议分开；缺少证据就写待核对，不要补造验收结论。
```

点击「添加步骤」。此时你应该看到原材料、一块转化步骤，以及一张等待生成的空成果卡。

![新手操作：选中材料后，在底部描述想得到的成果](../assets/first-step.png)

这一步还没有生成成果。「添加步骤」是在确定做什么；下一步才执行。

## 4. 生成，然后加入你的判断

在刚创建的转化块上点击「运行到这里」。运行时可以查看进度或停止；完成后，正文出现在原来的空目标卡中。

阅读结果，检查它是否把打包成功误当成 Windows 界面验收。点击成果卡上的「编辑内容」，补上你自己的判断，例如：

```text
人工复核：Windows native make/packed smoke 与真机客户端验收必须分开记录。
这里是证据讨论稿，不是执行仓库公开或上传安装包的批准。
```

再次「保存正文」。成果现在既有 AI 的整理，也有你的决定。保存后的正文形成新版本；可以从卡片的版本入口查看历史。

如果运行期间你修改并保存了目标正文，模型返回后可能显示「有一个待比较结果」。打开比较，决定「采用为最新版本」还是「丢弃结果」；Mira 不会静默覆盖你保存的内容。

## 5. 用这份成果继续推进

关闭详情，选中证据分析卡，在底部输入：

```text
把证据缺口变成后续验收清单。每条写清待验证主张、验证方法、需要保留的证据，
以及通过后仍不能推出什么。不要把建议标成已执行，也不要增加新的产品承诺。
```

再次「添加步骤」，然后在新步骤上「运行到这里」。你现在有了一条材料 → 证据分析 → 验收清单的路径，可以逐张修改。

![完整案例：多份真实文档推导证据边界、交付范围与验收清单](../assets/software-iteration.png)

*完整案例把原始文档拆成四张来源卡，经过三步 Kimi 真实推导，再保留人工复核。首次练习只需完成上面的两步；也可以[直接导入完整案例](../examples/README.md)。再次调用模型的措辞与推断可能不同。*

## 再试一个小变化

回到原材料，补充一条你已核对的验证事实并保存，注明出处。之前生成的分析对应步骤会提示「来源已变化」，旧结果仍保留。确认要更新后，在验收步骤点击「运行到这里」，Mira 会检查必要的上游步骤并更新到这里。

两步成果都经过你检查后，可以打开第一步的关系详情，把这段已经走通的路径「保存为方法」。下次从「方法与计划」使用它，手动绑定新材料、确认添加，再按需运行。保存的是方法，不是这次项目的正文。

要留下阶段成果，可以从「画布版本」手动保存一个稳定版本。从旧画布版本继续工作会创建新副本，不覆盖当前画板。

## 卡住时看这里

| 看到的情况 | 下一步 |
| --- | --- |
| 底部没有成果输入框 | 先保存材料并单击卡片选中；详情打开时可先关闭详情 |
| 添加步骤后成果还是空的 | 在转化块点击「运行到这里」 |
| 提示没有可用模型 | 回到「系统设置 → 模型设置」，测试连接并保存；确认服务没有刚重启 |
| 运行失败 | 查看运行详情中的原因，调整服务或材料后重试；原内容仍在 |
| 有待比较结果，无法继续 | 先比较并采用或丢弃结果，再继续运行 |
| 画布太大，找不到卡片 | 顶部搜索卡片名称或正文；桌面也可按 `Cmd/Ctrl + K` |
| 提示工作区已被占用 | 退出另一可写 Mira 实例；异常残留按[工作区锁恢复](../operations/workspace-lock-recovery.md)处理 |
