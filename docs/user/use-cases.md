# 四种工作，四种画板

[返回项目介绍](../../README.md) · [先做新手练习](getting-started.md) · [下载可操作的案例](../examples/README.md)

需求会临时变更，读书会留下疑问，研究会遇到反例，文章也会在编辑到一半时改变方向。下面四张画板停在这些具体时刻，你可以导入副本，接着做下一步。

图片来自当前 Mira 的真实界面。材料、访谈、经历和成果均为人工编写的演示内容；书中片段是读者概括，非原文引文。演示通过本地预写文本适配器走正常运行接口，产生版本、来源变化和待比较状态；没有调用真实模型，不代表模型输出质量或真实项目进展。

| 场景 | 画板怎样组织 | 这次用到的能力 |
| --- | --- | --- |
| [软件需求迭代](#软件需求迭代) | 一个范围分出两条交付支线，新反馈只接到需要它的步骤 | 多来源编辑、来源变化提示、正文版本、画布版本、文件绑定 |
| [读书与学习](#读书与学习) | 按主题摊开摘记、生活观察和未解问题，只连接需要整理的材料 | 灵感池、标签、出处、分组、人工笔记与版本 |
| [研究整理](#研究整理) | 同一份观察支持两种解释，反例参与推理，最后汇合为研究决定 | 来源复用、有序来源、分支汇合、运行输入追溯 |
| [内容创作](#内容创作) | 三步计划走通后继续改稿，人工正文与新结果等待比较 | 计划、已验证方法、Candidate 比较、下游来源变化 |

## 软件需求迭代

### 周三来了新反馈，周二的验收还算数吗？

你负责阅读 App 的离线阅读 1.1：一名开发者、两周，只做单篇下载。周二确认了范围，分别整理出回归清单和内测说明。周三试用者又报告：下载到一半切换飞行模式，页面一直显示“下载中”。

![离线阅读迭代：新反馈加入回归支线，需求已到 v2，内测说明已更新，旧回归清单提示来源已变化](../assets/software-iteration.png)

左边是 F-12 反馈与本期约束，中间是确认的范围，右边分别给测试和试用用户。批量下载放在「下次再讨论」卡里，暂不接入交付步骤。分组只是方便阅读，不会自动参与生成。

这张画板保留了不齐步的进度：你已经把“清理入口统一放在详情页”写进需求 v2，并更新了内测说明；旧回归清单仍是 v1。F-19 作为新增来源接到「推导回归用例」，步骤显示「来源已变化」，提醒你决定何时补测，不会自动重跑。

导入[需求迭代画板](../examples/software.mira-board.json)后，打开「推导回归用例」查看当前两份来源与上次采用的输入。连接模型后再「运行到这里」，检查新清单是否覆盖中断下载、失败提示与重试。清单里的演示勾选不代表真正执行过测试；实现和项目测试仍在开发工具中完成。

### 保留评审现场，再继续改

![画布版本近景：周二的稳定版本与当前画板比较，可从旧版本创建副本](../assets/software-checkpoint.png)

完整演示工作区还保留了「周二评审通过 · 单篇下载」画布版本。打开「画布版本」比较周二与当前状态，查看新增反馈和内容变动；选择「从这个版本创建副本」可以探索另一个方案，当前画板保持原样。单张画板导入不携带检查点，体验这里请使用下方的完整工作区包。

制作案例时，需求卡还绑定了工作区内的 `delivery/offline-reading.md`，人工保存后的正文已写入该文件，方便后续交给开发。下载包会移除文件绑定；在自己的工作区需要重新绑定，原始文件也应独立保存。

## 读书与学习

### 重读《小王子》，留下一张暂时不求答案的卡

这次阅读围绕“关系、时间与责任”。玫瑰与狐狸的片段用自己的话记下；一个问题却还没有答案：“对关系负责，是否意味着总要牺牲自己的边界？”它单独留在右上角，没有被迫变成某一步的输入。

![主题读书画板：片段概括、灵感池生活观察、未解问题、一次小实践和二次修改的周日回看](../assets/reading-notes.png)

左上放书中片段，左下放生活观察和一个小实践，右边放正在变化的理解。只有「玫瑰」「狐狸」「周末的一次散步」三张卡进入「对照书与生活」。实践和周日回看由自己写，不需要再增加两次生成。

「周日回看」已经有两个版本：从“专心就是不看手机”，改成“我仍然急着给建议”。导入[读书画板](../examples/reading.mira-board.json)后，打开它的版本历史，读读这个变化；再把自己的观察写进去。摘记标了片段定位和页码待补，换成自己的书时补上版本、章节和页码，不让 AI 编引用。

### 灵感先记下来，读书时再找回来

![灵感池近景：按关系检索带标签的生活观察，阅读全文后再明确加入画板](../assets/reading-inspiration.png)

散步的观察最初记在工作区「灵感池」，带有「阅读」「关系」「生活观察」标签，之后才明确添加到这张画板。完整演示工作区还放了“反复读到的句子”和“不把沉默解释成结论”两条记录；搜索「散步」或用标签找回来，阅读后再决定是否需要它。

添加后的卡是有出处的独立快照，修改卡片不会改回池记录。单张画板包保留这个出处说明，但不会安装原灵感池；想实际搜索三条池记录，请恢复完整工作区包。颜色与分组是个人整理习惯，不是固定的“摘录卡”“行动卡”类型。

## 研究整理

### 同一段停留，可能是两个完全不同的问题

研究对象是新用户的首次导入。I-01 说不知道哪些配置必填；O-02 先去帮助页找示例，回来才配置；O-03 却跳过帮助直接成功，而且用过类似工具。直接归纳成“新手嫌配置复杂”会丢掉后两条信息。

![研究画板：三条原始记录形成两个竞争解释，O-02 被复用，反例经解释 B 进入下一轮研究决定](../assets/research-synthesis.png)

这里先建立两条独立推理支线：A 检验配置负担，B 检验是否缺少成果预期。O-02 同时参与两条支线，O-03 专门挑战 B；每种解释都写支持、不足和反证条件，再汇入「综合证据与反例」。最后得到的是下一轮任务，不是已证实的结论：先看成果示例能否帮助导入，同时分别观察新手与熟手。

![研究关系近景：核对综合步骤的处理要求、验收标准和来源顺序](../assets/research-evidence.png)

导入[研究画板](../examples/research.mira-board.json)后，点开「综合证据与反例」，沿来源回看 A、B，再追到原始记录。关系详情可以核对当前来源和已采用运行输入，避免后续改了证据，却误以为旧判断依据的也是新材料。

继续工作时，把下一次观察写成新卡，选择真正需要它的解释步骤，补充或调整来源，再明确运行。右下的招募与记录待办只是 Markdown 清单：分开招募新手与熟手、记录中断原因、记录完成后的解释。Mira 不会替你开展访谈，也不会把少量虚构材料变成统计结论。

## 内容创作

### 初稿出来了，但我不想把失败写成成功学

你要写一篇给新项目设计师看的周复盘文章。左边是写作任务与手头素材；先搭「提纲 → 初稿 → 发布前核查」三步计划，逐步完成并检查，再把这一段做法保存到方法库。

![写作画板：三步计划中的初稿正在改写，人工编辑决定独立保留，新结果待比较，下游核查提示来源变化](../assets/content-writing.png)

修改过程中，你决定用自己的失败经历开场，保留“没有立即得出结论也有价值”。右上用独立卡写下编辑决定，正文也已经保存为 v2。此时先前运行的另一版结果才返回，它用了“只需三个动作，就能告别无从下手”的口吻。

### 两版并排，让作者决定

![待比较结果近景：左侧保留人工正文 v2，右侧是迟到的新结果，可查看差异、采用或丢弃](../assets/writing-candidate.png)

导入[写作画板](../examples/writing.mira-board.json)后，点「比较待处理结果」，再打开比较。左边是你已经保存的正文，右边是尚未采用的结果。可以「查看差异」、丢弃这版结果，或者采用为新版本；采用也会保留旧版本。这个案例特意保留待处理状态，供你亲自做一次决定。

第三步「发布前核查」仍提示来源已变化，旧检查单没有因为你修改正文而自动更新。处理完待比较结果，再决定是否重新核查；文章里的待补背景、事实和最终发布仍由你负责。

完整工作区的「方法与计划」中还有「经验文章：提纲 → 初稿 → 核查」。它从已经走通并人工检查的三步内容提取，包含“写作任务”和可绑定多份卡片的“真实素材”输入。下次换一篇文章，绑定新材料后只会铺出计划，目标为空、不会自动运行，也不会复制这次的正文。单张画板导入不会安装方法库。

## 把其中一张变成自己的工作

只想试一个场景，下载对应 `.mira-board.json`，在「管理画板 → 导入画板副本」选择它。导入会创建新身份的画板；不连接模型也能阅读、修改、查版本和处理已有待比较结果。要重新生成，再配置自己的模型服务。

想同时体验灵感池、方法库和画布版本，使用[完整演示工作区包与恢复说明](../examples/README.md)：4 张画板、12 条演示运行、3 条灵感、1 个方法、1 个画布版本。恢复目标必须是新建或空文件夹。
