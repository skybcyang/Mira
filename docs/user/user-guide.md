# Mira 用户使用手册

第一次使用请先做[新手教程](getting-started.md)；寻找使用方向可看[四个场景案例](use-cases.md)。本页用于查阅具体操作，源码与后台服务配置集中在[运行与维护](../operations/development.md)。

- 适用范围：2026-09-09 当前源码，包含统一画板菜单、方法与计划入口、六套外观、画布交互加固、Board 生命周期、
  画板导入导出、完整备份恢复、灵感直接记录/检索、直接计划、普通关系移除与 macOS
  Desktop internal Alpha
- 源码中的 `package.json` 版本：`0.1.0-beta.2`
- 产品规则来源：[产品定义](../product/product-definition.md)与[核心规格](../specs/core-specification.md)

> 本手册描述当前源码。`v0.1.0-beta.2` tag 早于灵感池、直接记录入口和六套外观；旧的
> Beta.2 安装包没有这些入口时，不代表数据损坏。Desktop 仍未签名、未公证、没有自动更新，
> 只用于内部验证。

## 1. Quickstart

### 1.1 选择运行方式

| 方式 | 适合 | 要求 |
| --- | --- | --- |
| macOS Desktop | 内部试用、日常单机使用 | macOS 13+；使用团队提供的对应架构安装包 |
| Standalone | 从源码运行、浏览器访问 | Node.js `>=22.12.0`、pnpm |

无论使用哪种方式，同一个 workspace 同时只能运行一个可写的 Desktop、Standalone 或
DSH/Cordis 实例。

### 1.2 macOS Desktop：最快开始

1. 打开与 Mac 架构匹配的内部 `.app`；也可以先挂载 DMG 再打开应用。
2. 首次启动时选择一个可读写文件夹作为 workspace。取消选择不会创建业务数据。
3. 打开`系统设置 -> 模型设置`，完成模型连接。
4. 点击顶栏当前画板名称，在菜单中`新建画板`，再点击悬浮工具栏的`新建`写下第一份材料。
5. 选中材料，在底部输入想得到的成果，点击`添加步骤`；再在转化块上点击`运行到这里`。

Desktop 会在所选 workspace 中创建 `boards-v2/`、`runs-v2/` 和 `workflows-v2/`。最近
workspace 与窗口状态保存在应用自己的偏好目录中，Card、Run 和方法仍只保存在 workspace。

运行中可从 macOS 顶部的 Mira 应用菜单选择`选择其他工作区…`，或选择`从 Mira 备份恢复…`
并把完整备份恢复到新建/空目录。Mira 会先保存目标目录，再重启到该 workspace；切换或恢复前
确认目标 workspace 没有其他可写 Mira 实例。

关闭最后一个窗口不会退出 Desktop，本地 Host 也会继续运行；从 Dock 再次激活 Mira 会
重新打开窗口。备份数据或改用 Standalone 前，请使用`Mira -> 退出`或 `Cmd+Q`真正停止
Desktop 写者。

当前安装包未签名或公证，macOS 可能显示 Gatekeeper 提示。它不应作为公开发布版本分发；
packed `.app` 自带运行时，目标 Mac 不需要安装 Node.js 或 pnpm。

从源码启动 Desktop：

```sh
pnpm install
pnpm desktop:dev
```

### 1.3 Standalone：三条命令启动

在仓库根目录运行：

```sh
pnpm install
pnpm build
pnpm start
```

打开：

```text
http://127.0.0.1:56300/graphmind/
```

默认使用当前目录作为 workspace。若要把业务数据放到独立目录，必须同时告诉 Mira 已构建
前端位于哪里：

```sh
MIRA_WORKSPACE_ROOT="/absolute/path/to/mira-workspace" \
MIRA_STATIC_ROOT="/absolute/path/to/Mira/dist" \
pnpm start
```

只设置 `MIRA_WORKSPACE_ROOT` 时，Mira 会到 `<workspace>/dist` 查找前端，页面可能无法打开。
Standalone 默认只监听 `127.0.0.1` 且没有用户认证；不要把 `MIRA_HOST` 改为公网地址。
确需跨设备访问时，应在外层反向代理配置 HTTPS、认证和请求来源防护，而不是直接暴露 Mira
端口。完成这些保护也不会解除同一 workspace 只能有一个写者的限制。

### 1.4 连接模型

最短路径是网页内配置：

1. 打开`系统设置 -> 模型设置`。
2. 选择 `Kimi K3`，或选择`自定义 OpenAI 兼容服务`。
3. 填写服务地址、模型 ID 和可选 API Key。
4. 先点击`测试连接`，成功后点击`保存设置`。

网页设置只对当前服务进程有效。服务或 Desktop 退出后，需要通过环境变量重新提供配置，
或再次在网页中设置。读取设置时只返回是否已有密钥，不返回 API Key 本身。

也可以在启动时配置内置 OpenAI-compatible 适配器：

```sh
MIRA_LLM_BASE_URL="https://api.example.com/v1" \
MIRA_LLM_MODEL="your-model" \
MIRA_LLM_API_KEY="your-key" \
pnpm start:llm
```

无需鉴权的本地服务可以省略 `MIRA_LLM_API_KEY`。选中具有可用内容的 Card 后，Mira 会自动
请求下一步建议；配置了模型服务时，建议请求以及显式`生成`或`运行到这里`都会把有序来源的
实际文本发送给该服务。Markdown 来源发送完整正文，file-reference 来源发送当时读取到的文件
全文而不只是路径。请按材料敏感度选择服务，不要把密钥写入仓库。
远程模型服务应使用 `https://`；`http://` 只适合可信本机或受控内网服务，不能用来在
不可信网络上传输 API Key 和来源实际文本。

未配置模型时，画板、Card、版本、标签、计划和方法仍可使用，下一步建议也有内置
回退；显式`生成`或`运行到这里`会以 `MODEL_UNAVAILABLE` 结束，已有内容不会被覆盖。

### 1.5 五分钟得到第一份成果

1. 点击顶栏当前画板名称，选择`新建画板`，输入名称并`新建并打开`。
2. 点击悬浮工具栏的`新建`，或双击画布空白处，写下材料。
3. 点击`保存正文`或按 `Cmd/Ctrl + Enter` 提交内容。
4. 单击一张 Card；需要多来源时按住 `Shift` 继续点击，或使用框选/`多选`。
5. 在底部检查来源顺序，输入`把这些内容变成…`，例如“整理成一页决策摘要”，或直接点击建议。
6. 点击`添加步骤`。Mira 只创建转化步骤和空目标 Card，不会启动模型。
7. 在转化块上点击`运行到这里`生成结果；已搭好多个步骤时，也可以指定一个下游终点，按需生成到那里。
8. 点击结果标题栏的`编辑内容`继续修改，或把它选为下一步来源。

### 1.6 验证本地源码

开发或更新源码后，在仓库根目录运行完整门禁：

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm build
pnpm build:bridge
git diff --check
```

涉及可见 UI 时，还要在真实浏览器检查桌面宽度和 390px 窄屏的焦点、遮挡、溢出与 console。
涉及 Desktop 宿主或打包时，再运行目标架构的 `desktop:make:*` 与
`desktop:smoke:packed:*`；macOS 与 Windows 的目标架构和验收边界见[内部桌面打包](../operations/desktop-internal-builds.md)。

## 2. 认识界面

### 2.1 顶栏与工作导航

- 当前画板名称：打开统一菜单，默认显示常用与已打开；输入名称搜索全部未归档画板。图钉固定常用，当前、运行中和待处理标记帮助定位。
- 撤销/重做：重放当前画板会话中受支持的 Card 操作。
- 悬浮工具栏`新建`：新建 Markdown Card 并开始编辑；也可双击画布空白或按 `N`。
- `文件`：从工作导航打开文件选择器，从目录中选择文件并创建只读引用；工作区外文件会先拷贝备份到工作区 `attachments/`。
- `灵感池`：打开 workspace 灵感池，记录新灵感或从池中筛选并组成工作集。
- `方法与计划`：上部点击`搭一个计划`，填写计划名称、最终成果、每步成果与处理要求；最后一步成果自动跟随最终成果。预览后绑定材料并添加，仍需手动运行。下部查看、使用或删除已经验证的方法；命令搜索也可直达搭计划。
- 悬浮工具栏的`多选`：触屏和持续多选入口。
- `画布版本`：从悬浮工具栏直接保存或查看稳定版本；`管理全部画板`位于顶栏画板菜单底部。
- 顶栏右侧`系统设置`：开关网格线、调整外观或进入模型设置。网格偏好会在本机保留，不改变卡片位置、吸附与历史。

桌面左侧的悬浮工具栏可收起；小于 720px 时移到底部，保留新建、多选与全部工作入口。顶栏中央为搜索，右侧为撤销、重做和系统设置。灵感池与详情以全屏任务打开，关闭后回到原任务。

画板菜单中的关闭按钮只移出本机已打开列表，不归档或删除。关闭当前画板会切到另一已打开画板；关闭最后一项后停留在选择画板空态，刷新也不会新建画板。常用标记保留，可随时搜索重新打开。活动运行或未处理候选结果会阻止关闭；未保存的内容或计划表单须先处理。

`管理画板`是独立弹窗。`工作中`只显示可编辑画板；`已归档`只读但可重命名、恢复、导出或
移入废纸篓；`废纸篓`中的画板可恢复、导出或在明确二次确认后永久删除。永久删除不可撤销，
只移除该画板及其运行记录和画布版本，不影响其他画板、方法或引用文件。归档或移入废纸篓前，
必须先结束活动 Run 并处理待比较结果。当前画板离开工作中后，Mira 会打开另一工作中画板；
没有可用画板时会按普通新建流程创建默认画板。

同一弹窗还提供`导出画板`、`导入画板副本`和`备份 Mira 数据`。导入始终新建 active 副本，
不覆盖或合并；完整备份下载覆盖三个生命周期的 Board、全部 Run、画布版本、workspace 灵感池和方法，但不含 API Key、
页面草稿、撤销历史或 file-reference 指向的文件正文。网页只负责下载完整备份，不覆盖恢复
当前 workspace。

### 2.2 外观

打开`系统设置 -> 外观`，分别选择设计方向和明暗模式：

- `原生工作室`：安静、紧凑，使用克制的半透明 chrome 和柔和层级。
- `编辑部`：正文优先，使用衬线展示标题、平面纸张感和细分隔线。
- `蓝图台`：精确、硬朗，使用方角、等宽元数据和清晰的命令强调。
- `浅色 / 深色`：与上述方向独立组合，因此共有六套完整外观。

三种方向共享全部功能和信息架构。切换外观不会重置画布 viewport、当前选择、详情、草稿或
运行状态；旧的`浅色 / 深色`偏好会迁移到`原生工作室`。Standalone 在同一浏览器 origin
保存选择；当前 Desktop internal Alpha 使用临时 renderer session，应用完全重启后可能回到
默认方向和系统明暗偏好，但不会改变 workspace 数据。

### 2.3 画布与两个命令区

找不到卡片时，使用顶部的`搜索卡片或命令`（`Cmd/Ctrl + K`）；窄屏也可点击顶部搜索图标。输入标题或正文关键词，查看当前画板匹配卡片及命中片段，点击结果或上下选择后按 Enter，即可定位并选中原卡片。搜索不打开详情、不改内容，也不启动生成；Esc 取消不会改变原选择与画布位置。文件卡可按文件名或路径查找，暂不搜索文件正文、旧版本或其他画板。

画布顶部的选择工具栏负责整理 Card：复制、创建副本、粘贴、删除和多选。画布底部的
Context dock 负责推进内容：确认有序来源、选择建议、描述成果，以及`添加步骤`。
两者使用同一组 Card 选择，但不会自动修改你的来源顺序。

点击 Card 的展开或版本命令会打开详情；点击转化块会打开关系详情。桌面使用右侧面板，
窄屏使用全宽 sheet。

## 3. 核心概念

- **画板**：一个课题或项目的空间。
- **Card**：画布上唯一的内容对象。材料、草稿和成果都是 Card。
- **灵感池**：workspace 级独立记录集合，存 Markdown 与标签，不属于任何画板；只有添加到当前画板时才变成普通 Card。
- **版本**：Card 每次已提交内容的不可变记录；画布默认显示最新版本。
- **画布版本**：用户手动保存的整个 Board 稳定检查点；从中继续工作会创建独立画板副本，不覆盖当前画板。
- **转化步骤**：使用有序来源得到一个目标。创建步骤本身不等于运行。
- **Run**：某一步的一次模型执行，会冻结当时的来源与目标基线。
- **待比较结果 Candidate**：模型返回前目标被人工修改时，模型结果进入这里，不覆盖人工内容。
- **来源已变化 stale**：最近采用结果使用的来源不再是当前来源，只提示，不会自动生成。
- **计划**：铺在普通画布上的线性 Card 与转化步骤，不是第二套执行引擎。
- **方法**：从已经走通的线性路径保存的可复用步骤，不复制当前项目正文。

## 4. 日常操作

### 4.1 新建和编辑 Card

- 点击左侧`新建`、双击空白画布或按 `N` 新建 Markdown Card。
- 拖动标题栏移动 Card；正文支持选字和内部滚动，双击正文保留浏览器选词。
- 点击标题栏的`编辑内容`；单选后按 `Enter` 也可进入编辑。
- 点击`保存正文`或按 `Cmd/Ctrl + Enter` 提交；编辑器中的 `Esc` 取消修改，保存进行中不取消。失焦不自动提交，关闭新建空卡不会自动删除。
- 点击标题栏的`阅读完整内容`查看正文；详情可以展开，并在阅读/编辑之间切换，不丢失未保存草稿。标签在`标签`折叠区内。
- 已打开内容、版本或转换详情时，单选内容卡会同步显示它的内容；多选和框选不会打断当前详情。存在未保存修改时，可选择`保存并切换`、`放弃并切换`或`继续编辑`。保存失败会保留当前卡片和草稿。
- 详情顶部只显示当前可用的内容、版本、生成步骤和运行记录入口；文件绑定及出处在`卡片信息`中。
- 点击版本号打开版本历史、差异和恢复命令。

卡片可以有独立名称：点击卡片标题或详情名称旁的`重命名`按钮，填写`卡片名称`并点击`保存名称`。名称最多 120 个字符；留空则继续使用默认标题。改名不改正文、不增加正文版本；搜索、来源列表和副本都会使用这个名称。若其他窗口已改名，当前草稿会保留，核对最新名称后再提交。

Markdown 预览支持标题、粗体/斜体、列表、引用、代码块、链接、图片，以及表格、任务列表、
删除线、自动链接和脚注。宽表格可以在表格区域横向滚动；任务勾选框只读，需要在编辑模式修改
`- [ ]` / `- [x]` 后保存。卡片、完整阅读、来源预览和 `.md` 文件使用相同语法；原始 HTML 不执行。

连续记录时点击`保存并新建`：先保存当前正文，再创建同尺寸、相邻避让的独立空卡。
未保存名称或标签需先保存或取消；正文保存失败会保留输入。若提示新卡状态待核对，重新打开画板检查，
不要直接重复创建。新卡不复制标签或来源，不自动连线或运行。

选择 Card 后，从`整理卡片`设置尺寸预设、宽高数值，或对所选卡片同宽、对齐和等间距。
单选时也可拖动右下角尺寸把手，`Esc` 取消本次拖动。一次整理对应一次撤销，不改变正文版本、
来源顺序或分组归属；同宽以第一张选中卡为基准。

编辑成果时，点击`查看来源`可以在同一详情任务中核对材料，`返回原任务`保留草稿。
关系详情区分已采用 Run 的历史输入和当前来源；无法核对的历史或文件会明确标注。
转化块的`查看运行范围`只预估到该终点的步骤，不生成内容；仍需显式`运行到这里`。
成果卡的更多菜单可直接`修改生成步骤`，但不绕过活动 Run 或待比较结果的限制。

四个通过 Kimi 实际生成的案例见[案例下载与来源说明](../examples/README.md)。
导入后先阅读材料与成果，再显式保存为方法；方法库显示最终成果、材料输入槽与可展开步骤。
使用方法只铺计划，必须绑定新材料，不复制示例正文，也不自动运行。

`文件`通过目录选择器添加，不需要手动输入路径。选择 workspace 内的文件时直接引用原位置；
选择 workspace 外的文件时，Mira 先把它拷贝备份到 workspace 的 `attachments/` 目录（重名自动
加序号），Card 引用的是这份拷贝，不跟踪原文件此后的变化。文件 Card 为只读引用；运行开始时
读取当时的实际内容。文件被移动、删除或不可读时，来源读取会失败。

### 4.2 添加标签

1. 打开 Card 的内容详情，展开`标签`。
2. 选择常用标签，或输入自定义标签并添加。
3. 点击`保存标签`。

每张 Card 最多 20 个标签，每个标签最多 32 个字符，大小写不敏感地去重。标签只用于
检索，不创建 CardVersion，也不触发 stale 或 Run。模型需要知道的约束、事实或技术说明
必须写进 Card 正文，不能只放在标签里。

### 4.3 记录灵感与组成工作集

灵感池是 workspace 级独立记录集合，先记录，不决定它属于哪张画板：

1. 点击`灵感池`。
2. 点击`记录灵感`，输入非空正文。
3. 按需选择`主意`、`约束`、`技术`、`事件`，或输入自定义标签。
4. 点击`保存灵感`。成功后正文清空、标签保留，可以继续记录。

保存只写 workspace 灵感池，不创建 Card、不改变当前画板，也不进入撤销/重做历史。
灵感池条目不携带画布坐标；之后删除或修改灵感池条目，不会影响已经放入画板的独立 Card。

修改已有灵感：点击`阅读全文 → 编辑灵感`，修改正文或标签后点击`保存修改`。修改正文保留旧版本，只改标签不增加正文版本。取消或关闭前会提醒未保存修改；保存失败保留草稿。遇到其他窗口修改，先复制需要保留的文字，再点击`放弃草稿，载入最新内容`重新编辑。

编辑不会替换`已选`里的旧版本，列表会提示池中已有新版。若想改用新版，先移除旧选择，再从结果中选择新版。

从灵感池组成工作集：

1. 点击`灵感池`，输入关键词，并按需选择标签；多个标签使用 AND 语义。
2. 点击结果加入`已选`。摘要/列表、搜索和标签切换都保留选择；阅读全文在同一窗口打开，返回后仍保留原检索位置。
3. 用上移、下移和移除调整顺序。
4. 点击`添加到当前画板（N）`。

每次添加都在当前画板创建独立 Markdown Card，复制正文和标签，并保留`来自灵感池`出处
（池条目与版本 ID）。新 Card 不共享灵感条目身份、版本历史或 Run；灵感池后续变化不会
同步，也不会自动连线或运行。整批添加要么全部成功，要么全部失败。添加后原选择、正在编辑的草稿和画布位置保持不变；新卡在已有内容下方。若无法确认添加结果，先核对画板再重试，避免重复添加。

### 4.4 选择有序来源并创建步骤

- 单击建立第一个来源；`Shift + click`追加或移除。
- 框选或显式`多选`可选择多张 Card。
- Card 上的 `1 / 2 / 3` 和底部 chips 表示来源顺序；可在 dock 中前移、后移或移除。
- 输入成果目标或选择建议后，`添加步骤`只创建步骤和空目标，保持零 Run。
- 之后在转化块点击`运行到这里`启动生成。

如果模型运行失败，步骤和目标仍会保留，可以调整模型或目标后重试。

### 4.5 编辑转化步骤与模型覆盖

点击转化块，在关系详情点击铅笔命令；直接计划中的转化显示`编辑步骤`，普通转化显示
`编辑转化`。可以修改成果名称、生成目标和完成标准。

需要给已有转化补材料时，可以从另一张内容卡的把手拖线到转化块左侧输入端，也可以在关系详情
点击`添加来源`，在画布上依次点选材料后确认。原来源保留，新材料按选择顺序追加；重复连接
不会重复添加。点选工具条也提供可键盘操作的卡片菜单，取消不改变转化。

关系详情的来源列表可用上/下箭头调整顺序，用移除命令移出来源，至少保留一张。
目标卡自身、不可用材料或会形成依赖环的连接会被拒绝；来源变化不自动运行。
展开`来源状态摘要`可查看当前来源与最近已采用输入的对照，点击条目继续只读查看当时或当前正文。

支持网页模型设置的 Standalone 与 Desktop 还可以为这一条 Transformation 选择：

- `继承默认模型`：每次执行时使用当前全局或宿主模型。
- `固定模型 ID`：只覆盖这一条步骤；连接地址和密钥仍使用全局设置。

宿主不支持步骤覆盖时，这一区域只读。固定模型必须由当前适配器真实支持；无法解析时会在
创建 Run 前明确失败，不会静默退回默认模型。保存编辑不会自动运行，并保留目标 Card、
计划/方法来源和既有 Run 历史。存在活动 Run 或待比较结果时，先停止/等待或处理 Candidate。

### 4.6 明确分支

从所选 Card 的 handle 拖到画布空白处会进入`新方向`，再通过底部 dock 创建新的独立目标，
落点即新目标卡的位置。卡到卡之间不能直接连线；拖到已有转化块输入端只追加来源，不创建
新方向。重新生成、stale 和 Candidate 都不会自动创建分支。

### 4.7 运行到这里

在任一转化块或关系详情点击`运行到这里`。Mira 会：

1. 找到该步骤的全部上游依赖。
2. 从最上游逐步检查。
3. 跳过已经最新的成果。
4. 只运行空目标或来源已变化的步骤。
5. 在你点击的目标步骤完成后停止。

遇到待比较结果、失败、停止、来源不可用、状态无法确认或切换画板时，序列立即停止，
后续步骤不会启动。刷新页面不会恢复整条客户端序列；已经启动的单个 Run 仍按普通恢复规则
跟踪。

目标 Card 正在生成时，点击卡片右下角的方形`停止生成`按钮可中断当前 Run；停止是终态，
不会被迟到结果覆盖。生成失败时，目标 Card 显示`重试`；点击后会按最新画板状态重新执行
`运行到这里`。停止后也可回到转化详情再次点击`运行到这里`。每次重试都是新的 Run，
不会改写旧运行记录或已有内容。

运行中的目标 Card 同时提供`查看运行进度`。运行详情会显示当前阶段、最近 20 条公开事件，
并在有可用的脱敏说明或可靠时间时显示说明、已用时间和最后更新时间；刷新页面后，已经持久化的单个 Run 事件仍可查看。进度时间线不会
展示模型思维过程、原始 Prompt、密钥或完整工具内容。旧 Run 没有事件时保持可用，只显示已有
状态，不会补造历史。

### 4.8 处理来源变化和待比较结果

`来源已变化`只表示最近采用的成果已落后，不会自动重跑。点击当前或下游步骤的
`运行到这里`即可按依赖顺序更新。

运行期间人工编辑目标时，人工版本保持为最新，模型输出显示为`待比较`。打开运行详情，点击`查看待比较结果`，可完整阅读或查看逐行差异；宽屏并排、窄屏纵向。打开时固定当前版本，如果后来又有编辑，需要点击`重新核对并比较`，不会悄悄更换你已读的基线。超长正文保留完整阅读，停止计算逐行差异。

- `稍后处理`：关闭窗口，结果保持待比较。

- `采用为最新版本`：把模型结果追加为新版本。
- `丢弃结果`：保留当前人工内容。

来源预览与详情展开保留同一份编辑草稿；窄屏来源使用`返回正文`回到编辑位置。

处理前不能重跑、编辑或删除对应转化；`运行到这里`遇到它也会停下。

### 4.9 直接搭计划

1. 点击悬浮工具栏的`方法与计划`，再点击`搭一个计划`；窄屏从底部工具栏进入。
2. 填写计划名称、最终成果和至少一个步骤的处理要求；中间步骤单独填写成果名称，最后一步跟随最终成果。
3. 添加、删除、上移或下移步骤，点击`预览计划`。填写中的表单在返回或关闭前会提示继续编辑或放弃。
4. 从内容 Card 连到`起始内容`槽，或先选 Card 再点击`使用已选`。
5. 必填内容满足后，在第一步点击`添加计划`。

预览草稿只存在于当前页面；取消、切换画板或刷新都会清空。`添加计划`一次性创建全部
普通 Card 与转化步骤，不创建 Run，也不会自动保存成方法。点击具体步骤的`运行到这里`
才开始生成。

### 4.10 保存和使用方法

保存方法：

1. 先让一条线性路径的每一步都拥有可用当前成果；人工写成的成果也有效。
2. 点击路径中的转化块，在关系详情选择`保存为方法`。
3. 检查将保存的步骤和外部输入，填写方法名称与可选说明。
4. 保存。方法只记录步骤，不复制当前正文、Card、版本或 Run。

使用方法：

1. 打开`方法`并点击某项的`使用`。
2. 在画布骨架中手动绑定每个具名输入；系统不会根据当前选择或位置猜测。
3. 点击`添加步骤`。完整计划一次写入，仍为零 Run。
4. 在需要的目标步骤点击`运行到这里`。

当前方法模板不可直接编辑。要修改方法，请回到画板调整步骤、重新走通并保存为新方法。
删除方法需要二次确认，不影响已经添加到画板的计划。

### 4.11 版本与恢复

点击 Card 底部的版本号查看时间线和 diff。`恢复为最新`会复制所选历史内容并追加一个
新版本，不移动指针，也不删除当前版本。计划绑定只使用当前 Head；若要从历史内容开始，
先把该版本恢复为最新。

整个画布的里程碑从悬浮工具栏的`画布版本`进入；也可以在`管理画板`的任一画板行点击 History
图标，查看 active、archived 或废纸篓画板的历史：

1. 在没有活动 Run 和待比较结果时点击`保存画布版本`，填写名称与可选备注。
2. 从列表选择一个版本，查看当时的只读缩略画布及与当前画板的 Card、正文、布局、结构和 Run 摘要。
3. 需要继续旧方向时点击`从这个版本创建副本`，确认新画板名称。Mira 会创建并打开全新 active 画板；原画板和检查点不变。
4. 单个画板最多保存 20 个版本；满额时先显式删除不再需要的版本，不会自动淘汰。

活动 Run 会引导`查看运行`，未处理 Candidate 会引导`比较待处理结果`。归档和废纸篓画板
不能新建版本，但仍可预览、导出、重命名、删除或创建副本。画布版本不是自动编辑日志，
也不会替代当前页面会话的撤销/重做。

### 4.12 复制、删除和有限撤销

卡片颜色与分组也属于当前会话内可撤销的整理操作。选择一张或多张卡后，从顶部调色板设置默认或六个预设颜色，从分组入口建立命名组、移入已有组或移出分组。组内每张卡仍可单独设色，组色不覆盖卡色。

拖动卡片无论多远都只改位置，虚线框自动贴合，不会自动退组或转组。拖动组标题会移动整组及内部转化块；标题只选择组，点击“选择组内卡片”才把成员放进普通来源选择。组工具栏提供重命名、框色、复制整组和解组；解组不删除任何内容。

普通复制保留正文、颜色和布局，不复制分组。明确“复制整组”再粘贴才创建新的组和卡片，并为整组避让已有内容；仍不复制转化、运行或历史。整理历史只在当前画板会话内有效，分组或成员已变化造成的失效项会提示后移出历史，不阻挡更早操作。

选择工具栏支持：

- `复制`：保存当前 Head、尺寸与组内相对位置到 Mira 页面内剪贴板。
- `创建副本`：在附近生成独立 Card，不覆盖已有剪贴板。
- `粘贴`：在当前视口附近创建独立 Card；同一页面会话可跨画板粘贴。
- `删除`：先检查全部选择，再显示带数量的二次确认。

复制不会带走 Card/Version ID、完整历史、Transformation、Run 或方法来源。页面
刷新或关闭后内部剪贴板清空，也不会读写系统剪贴板。

只要任一 Card 仍被 Transformation 引用，整批删除都会拒绝。先显式删除相关
结构；删除 Transformation 只删步骤，目标 Card、版本和已有 Run 会保留。

撤销/重做最多保留当前画板会话的最近 50 条受支持操作，包括已提交 Markdown 正文、Card
位置，以及界面记录的文件/复制/当前 Board 灵感创建和无引用 Card 删除。需要注意：

- 正文撤销和重做都会追加 CardVersion，不改写历史。
- 撤销首次正文提交会回到空正文，但不会把已经提交过版本的 Card 当成全新空 Card 删除。
- 撤销删除只恢复当前服务进程刚删除的精确 Card；刷新、切换画板或服务重启后不可继续。
- 撤销创建仍受结构引用门禁；Card 已连入步骤时不会强制删除。
- 标签、Transformation、Run、Candidate、计划、方法和模型设置不在历史中。

浏览器保留最近 50 条历史命令，Bridge 按 Board 保留最近 50 个删除批次的精确回执；批次内
Card 数量不额外消耗窗口。更旧批次或服务重启后的撤销会返回 `CARD_RESTORE_CONFLICT`，并整批
拒绝而不会只恢复一部分；这不是通用导入或强制恢复入口。确定永久失效的条目会移出历史栈，
再次撤销可以继续处理更早命令；网络或存储等暂时错误仍保留当前条目以便重试。

快捷键在输入框、编辑器、表单和按钮焦点之外生效。

| --- | --- |

| `Enter` | 编辑唯一选中的 Markdown Card |
| `Cmd/Ctrl + Z` | 撤销最近一项受支持操作 |
| `Cmd/Ctrl + Shift + Z` | 重做 |
| `Ctrl + Y` | Windows/Linux 重做 |
| `Cmd/Ctrl + A` | 选择当前画板全部 Card |
| `Cmd/Ctrl + C` | 复制到 Mira 内部剪贴板 |

## 6. 数据与安全边界

- Standalone 默认把当前目录作为 workspace；Desktop 使用你明确选择的目录。
- 业务数据位于 `boards-v2/`、`runs-v2/`、`workflows-v2/`、`board-checkpoints-v1/` 和灵感池文件。
- 同一 workspace 同时只能有一个可写实例。Node-backed Desktop/Standalone 会取得 `.mira-workspace.lock`；异常残留锁按[恢复说明](../operations/workspace-lock-recovery.md)处理。DSH/Cordis 当前仍依赖宿主保证单写者。
- 优先从`管理画板 -> 备份 Mira 数据`下载一致的完整备份。若要直接复制整个 workspace，仍须先退出 Desktop 或停止 Standalone，避免得到跨文件时点不一致的副本。
- 不要手工批量改写 Board/Run JSON。画板导入只接受 `.mira-board.json` 并创建副本；完整备份恢复只允许新建或真实空目录。
- Desktop 首次启动或没有有效 workspace 时可选择`从 Mira 备份恢复`，已有 workspace 时也可从 Mira 应用菜单选择`从 Mira 备份恢复…`；Standalone 离线恢复使用 `pnpm restore:backup -- --input <backup> --workspace <empty-dir>`。这些入口都在 Host 写入前完成校验，不覆盖正在使用的 workspace。
- 网页保存的模型设置和 API Key 只在当前服务进程内，不写入 Board、Run、Workflow 或 workspace。
- Standalone 默认无认证，不应直接监听公网；跨设备部署必须由外层提供 HTTPS、认证和请求来源防护。
- Desktop 使用随机 loopback 端口和每次启动凭据；关闭窗口不等于退出应用或释放 workspace 写者。

## 7. 当前范围与限制

- 计划严格线性，没有条件、循环、并行、timer、webhook 或无人值守后台执行。
- 没有无明确目标的`运行全部`；只能对具体步骤使用`运行到这里`。
- 方法不可原地编辑，也没有方法市场、团队权限或发布审批。
- 画板废纸篓支持恢复、导出和明确二次确认后的永久删除；永久删除不可撤销，也没有系统剪贴板互通。
- 灵感快照不与来源实时同步；标签不进入模型上下文。
- 页面内计划草稿、内部剪贴板和有限撤销历史都不会跨刷新保留。
- 浏览器历史与服务端回执都按最近 50 个删除批次计数；单批 Card 数量不提前消耗容量，服务重启会使旧回执失效。
- Desktop 仅支持 macOS 13+ internal Alpha；没有签名、公证、自动更新、Windows 或 Linux 版本。

## 8. 常见问题

### 生成提示模型不可用

打开`系统设置 -> 模型设置`，重新测试并保存。若部署显示`当前部署不支持网页模型设置`，需要
由宿主或启动环境提供模型适配器。

### 页面打不开，但服务已经启动

若使用独立 workspace，确认同时设置了 `MIRA_STATIC_ROOT`，且它指向执行 `pnpm build` 后
仓库中的 `dist`。默认地址被占用时，停止另一个服务，或用 `MIRA_PORT` 选择其他端口并打开
启动日志打印的 URL。

### 来源不可用或来源已变化

空 Card、悬空版本和不可读文件不能作为运行来源。先完成正文或修复文件路径。`来源已变化`
不是错误；在需要的目标上重新点击`运行到这里`。

### 不能重跑、编辑或删除步骤

先打开运行详情处理`待比较`结果。存在活动 Run 时先等待或停止；Mira 不允许结构变化隐藏
仍待处理的模型输出。

### 不能删除 Card

Card 仍被 Transformation 引用。先点击相应转化块，确认只删除结构，
再回到选择工具栏删除 Card。

### 撤销删除提示 CARD_RESTORE_CONFLICT

该删除批次的精确回执已经不在当前服务进程中，常见原因是服务重启，或后续删除超过最近
50 个批次。页面刷新会直接清空浏览器历史，而不是清除仍在运行的 Bridge 回执。Mira 不会用
页面提交的对象强制恢复。永久失效项会从历史栈移出，再次撤销可继续处理更早命令；网络或存储
等暂时错误仍保留原项以便重试。旧回执不能找回；需要数据级恢复时使用此前下载的完整备份，
并只恢复到新建或空 workspace。

### Desktop 再次要求选择 workspace

最近目录可能被移动、删除或变成不可写。重新选择一个可读写目录；Mira 不会静默改用仓库、
主目录或新建的隐式 workspace。

### macOS 阻止打开 Desktop

当前 internal Alpha 未签名、未公证。先向团队确认安装包来源、架构和校验信息，再按团队批准的
内部安装流程从 Finder 打开；不要关闭 Gatekeeper 或降低系统安全设置。需要公开分发时，必须
先完成 Developer ID 签名、公证和干净目标机验收。

## 9. 本地开发与后台运行

前端热更新需要先保持 Standalone 后端运行，再在第二个终端执行：

```sh
pnpm dev
```

打开 Vite 终端实际打印的 URL。开发代理默认连接 `http://127.0.0.1:56300`；其他后端地址
通过 `MIRA_BRIDGE_ORIGIN` 指定。

macOS 可以把已经构建的 Standalone 安装为当前用户 LaunchAgent：

```sh
pnpm build
pnpm service:install
pnpm service:status
```

管理命令为 `service:start`、`service:stop`、`service:restart`、`service:logs` 和
`service:uninstall`。卸载服务会保留日志与 workspace 数据。该脚本固定使用仓库根目录作为
代码和数据 workspace；安装前确认没有 Desktop 或其他 Standalone 正在写同一目录。
