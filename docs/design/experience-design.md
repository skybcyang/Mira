# Mira 体验设计

## 项目入口与打开恢复（2026-09-14）

主界面上层显示项目名及项目菜单，下层保留画板选择器；项目菜单提供项目总览、最近项目、新建和打开项目，备份恢复为次级操作。桌面默认继续上次成功打开的项目；没有可用项目时用原生项目入口选择目录，取消返回入口，明确退出才结束应用。切换时保留旧界面，显示进行中；成功才换入目标项目，失败或取消保留原项目。

没有打开画板时，画布区域显示项目总览：项目名、项目内活动画板列表、搜索、新建画板、管理全部画板，以及材料/灵感池/方法入口。不存在画板和搜索无结果分别说明原因；读取失败单独显示重试，不当作空列表。打开一张画板后返回现有画布，项目菜单可再次进入总览，查看总览不关闭其他已打开画板。关闭最后一张、归档最后一张或首次打开空项目均不自动创建画板。

打开记录按项目分别记忆；上次关闭全部画板，下次仍显示总览。恢复只选择记录中仍 active 的画板，不因重启重新打开所有最近使用过的内容。没有画板时可阅读方法库；“使用方法”和“搭计划”显示先打开或新建画板的提示。

项目切换先经过既有草稿保存/放弃/继续编辑流程，再核对整个项目的活动 Run 与 Candidate；活动状态不确定时停止切换，错误附近提供返回处理入口。系统菜单和页面菜单使用同一离开保护，不通过原生重启绕过草稿。规则及验收见[项目打开规格](../specs/project-opening.md)。

## 步骤工具与能力管理（2026-09-14 确认）

步骤详情在输出要求、处理指导之后增加“工具能力”摘要，进入同层编辑页。目录可搜索并筛选内置/MCP/Python；已选实例按生成前、模型按需、生成后展示，参数与明确 URL 范围、排序和移除可键盘操作。活动 Run/Candidate 时只读；未保存草稿遵守原离开保护。Skill 必需/可选依赖以能力 ID 明确显示，缺依赖允许保存计划、阻止 Run。

能力管理复用既有入口与导航，加入 MCP 连接、Python 环境和脚本。MCP 连接测试只发现目录，新增工具默认停用；用户分别核对项目启用与只读声明。凭据仅本次 Host 会话，重启需重填；本地程序显示命令、参数、目录和环境名称。Python 准备环境、测试全文代码、登记版本是独立明确动作，缺可靠 Docker 隔离时显示不可用。

Run 记录展示冻结工具配置、实际调用参数/结果和未调用项。等待审阅仍属活动 Run，用户查看完整请求或代码后执行一次，或拒绝并停止；关闭详情不取消 Run，返回记录仍可操作。停止/重启/超时使审阅失效，外部不确定结果不可盲目重发。附件先预览、明确下载，备份不携带附件或安装宿主资源。对象、预算与错误以[工具执行契约](../specs/tool-execution.md)为准。

## 1. 体验原则

Mira 的主界面让用户感觉自己在推进内容，而不是配置 AI 或编排自动化。

1. **默认内容优先，明确计划也可开始**：空画板仍以输入材料为主；用户已知道步骤时可直接搭计划，但不会进入另一套模式。
2. **意图明确、命令分层**：Context dock 的“添加步骤”、搭计划与使用方法统一只创建结构；运行永远由用户在步骤上显式触发，创建与启动是两个可审计命令。
3. **一个步骤一种行为**：流程中的步骤与普通 Transformation 使用同样的选择、状态、版本和命令。
4. **计划完全可见**：应用模板前预览，应用后在画板上铺出全部线性步骤。
5. **停下永远安全**：用户可以在任一步编辑、离开或删除未使用计划，没有隐藏后台工作。
6. **分支是用户动作**：系统不因 rerun、stale、Candidate 或流程应用自动创造方向。

## 2. 信息架构

### 2.1 App bar

从左到右：

1. `mira.` 字标与统一画板菜单构成左侧定位区。
2. 菜单触发器展示当前画板；菜单内提供搜索、常用、已打开、新建与管理全部画板。
3. 保存状态，仅在保存中或失败时显示文字。
4. `搜索卡片或命令`：在顶栏几何中心，桌面和 Compact 常驻并支持 `Cmd/Ctrl + K`；空查询显示原有命令，非空查询优先显示当前画板匹配 Card，再显示匹配命令。卡片结果按当前 Head 的标题、全文或引用文件名/路径进行不区分大小写的字面匹配，标题命中优先，显示标题与命中附近片段；不读取历史版本、其他 Board 或引用文件正文。键盘上下选择、Enter 定位，中文输入法选字不触发定位。结果选择只选中原卡片并以可读缩放定位，避让侧栏、选择工具栏和 Context dock，不自动打开详情、不改正文或创建 Run。关闭搜索保留原选择与视口并返回入口焦点；已有 modal、移动 sheet 或未保存详情草稿时不得打开搜索。
5. 顶栏最右侧为`撤销 / 重做 / 系统设置`，窄屏仍直接可达；历史只覆盖当前 Board 页面会话内受支持的 Card 操作。
6. `系统设置`集中提供显示网格线、六套外观和模型设置入口。网格默认显示，只保存本机偏好，不写 Board、不影响吸附或撤销历史。

悬浮工作工具栏依次为`新建 / 多选 / 画布 / 灵感池 / 方法与计划 / 文件 / 画布版本`。Desktop 距左侧 16px、距顶栏 20px，宽 148px，图标与文字同行，可收为 54px；Compact 使用 54px 图标栏；Mobile 使用距屏幕边缘 12px 的底部悬浮工具栏。新建在视口中心创建普通 Markdown Card；画布入口只收起任务并保留选择和视口。所有工作入口直接平铺，不设更多或重复搜索；管理画板位于顶栏画板菜单内，外观与模型归入顶栏系统设置。导航与显示偏好仅存本机 UI，不写 Board。

画布顶部按来源点选、普通选择工具栏的顺序互斥显示；无选择时新建与多选统一从悬浮工具栏进入；显式多选始终有退出命令。来源点选期间隐藏普通 Context dock。Mobile 全屏任务打开后底部导航和 dock 一并退出可交互层。

`系统设置`是一个临时 popup：点击外部或按 `Esc` 关闭，关闭后焦点回到触发按钮，执行任一命令前先关闭自身。它不与命令菜单、文件选择器、灵感选择器、画板管理或移动 sheet 叠加。

`材料`提供`已收纳材料 / 导入文件 / 读取公开网页`。明确导入项目内外文件均复制原件，导入后回到材料库；PDF 可以继续阅读。材料库与当前画板无关，关闭所有画板后仍可导入、阅读，只有`添加到画板`不可用。列表显示原名称、大小、时间与网页出处，错误就地显示，读取或提交时阻止重复操作；原文过长时在任务内滚动，键盘焦点保持可见。添加材料创建普通独立 Card，不跟踪源文件变化。项目工作区契约见[规格](../specs/project-workspace.md)。方法库仍使用同一产品模型。

### 2.2 Canvas

Canvas 从 App bar 下方延伸至悬浮工具栏背后，Desktop 右侧仍避让任务面板：

- 双击空白或按 `N` 新建 Card，并立即打开正文详情编辑。
- 空画板主命令、悬浮工具栏`新建`、`N` 与双击空白共用同一创建意图；命令一次只创建一张 Card，创建后无需再次点击编辑。空状态必须位于 React Flow 可命中的交互层。
- 连续从同一视口锚点新建 Card 时，在锚点附近确定性寻找首个无碰撞位置，不把新 Card 叠在已有 Card 上。
- 单击 Card 选中并建立来源上下文，详情关闭时不自动打开；内容、版本或转换详情已打开时，明确单选内容卡同步到该卡的阅读视图。`Shift + click`、显式多选、框选和来源点选不触发跟随。按 `Enter` 或点击 Card 标题栏的阅读/编辑命令可打开详情。
- 拖动 Card 表达空间关系。
- 拖动单张 Card 接近其他 Card 的边缘或中心线时，显示对齐参考线并轻磁吸（阈值内吸附）；吸附只发生在拖动会话内，松手后的位置仍是用户的表达。多张 Card 一起拖动时不吸附，保持组内相对布局。
- 有 Card 选择、内部剪贴板内容或显式多选状态时，在画布顶部显示选择工具栏。
- 选中对象时才显示连接 handle。
- 从内容卡把手拖线到空白画布发起新方向，落点即新目标卡位置；拖到已有转化块输入端则追加该卡为来源，保留原顺序，新来源排在最后，重复连接不重复添加。输入端显示可接入或拒绝状态，拒绝时给出具体原因。Card 到 Card 的直连与转化块发起的连接仍拒绝，零写入。
- 点击 Transformation 打开关系详情。
- Transformation 在来源与目标之间显示为紧凑步骤块；块内只显示成果名称、来源数量、状态和`运行到这里`命令。模型与详细设置只在右侧 drawer 显示。
- 点击一条 Transformation 后，关系详情从该步向下提取最大无歧义线性路径，并提供`保存为方法`。
- 直接计划或方法骨架以虚线步骤和空目标投影在同一 Canvas；绑定和确认期间不写 Board，也不改变 Card 的选择语义。
- 有超过 6 个节点的 Board 首次打开时聚焦最左侧 2-3 张可读内容卡，不把完整画板压成缩略图。
- PlanDraft 落地后使用服务返回的真实对象发出一次性聚焦意图，只保证一个起始来源、第一步 Transformation 与第一目标可读；不能为了显示完整长计划把内容缩成缩略图，也不能在用户已经主动平移后夺回视口。
- 选中 Card 后只保持两跳内的当前来源、步骤和结果为完整对比度；其他节点和连线降低强调。方法连接和多选期间不启用该淡化。

### 2.3 Context dock

Context dock 是一次局部推进的入口，位于画布底部：

1. 有序来源 chips。
2. `把这些内容变成…`自定义输入。
3. `添加步骤`主命令：只创建结构，保持零 Run。

自定义输入旁提供`添加分支`命令。进入后可连续填写 2–16 个成果目标，显示分支序号和添加/删除操作，达到 16 个后添加命令禁用；确认后一次性创建这些共享来源的普通 Transformation 与空目标 Card，保持零 Run。分支之间没有隐含顺序，也不创建 Group 或新的计划对象。

没有选择时隐藏；单来源、多来源和手动新方向使用同一个 dock。不显示固定或模型推荐，选卡及来源版本变化零推荐请求。自定义成果和分支确认提交期间锁定同一组创建控件，快速重复触发只能形成一次命令；失败后恢复输入以便重试。已有 Transformation 的`运行到这里`位于转化块和关系详情。

单卡 dock 与内容详情提供明确的`提取为多张卡片…`入口。进入同一个右侧内容任务面板，自由填写要求，默认空白且不预设章节/观点等选项。`添加提取步骤`只创建结构，随后明确运行获得普通 Markdown 清单；清单详情提供`拆成卡片…`。

拆分预览显示条目数量、全选/取消全选、标题与两行摘要；展开可编辑本次新卡的标题/正文，上下移动有可键盘操作的按钮。预览绑定清单版本，支持伴随阅读原文；清单更新不替换草稿，提交旧版本被拒绝。零选择禁用创建，确认按钮显示`创建 N 张卡片`，整批成功后回到清单并通知数量，原卡与清单保留；失败保留编辑，响应不确定时禁止直接重试，先刷新核对已有批次，再由用户明确允许新的创建。退出有修改的预览只提供继续或放弃，不能借“保存并离开”隐式建卡。

重跑先处理普通 Run/Candidate，再从新清单明确拆卡。此前批次提供卡片链接和清单版本，显示再次确认会创建新卡而不更新旧卡。Desktop 复用现有侧栏，390px 同层全屏，底部操作保持可达；迟到结果不抢占用户新导航。

### 2.4 Detail drawer

右侧 drawer 默认关闭，使用轻量悬浮详情面板承载当前对象。桌面面板宽 `380px`，距顶栏、右边和底边各 `12px`，连同右边距占用 `392px`；展开时也保留边距。Canvas 在剩余空间继续平移和缩放，不改变已保存 viewport；MiniMap、Controls 和底部 Context dock 都以剩余 Canvas 为边界。Compact 使用覆盖层与模态焦点约束；移动端使用全屏 sheet：

- `内容`：Markdown 正文阅读与原位编辑、文件正文、Card 标签与灵感出处；正文通过显式保存追加一个新 Version，取消修改保留当前 Head。
- `关系`：Transformation 的来源、目标、目标说明、验收、当前步骤模型和 stale。
- `版本`：Card 历史、来源、恢复和 diff。
- `运行`：进度、错误、停止和 Candidate。

生成失败的卡片仅在运行错误明确允许重试时显示`重试`：使用已保存设置与当前来源明确重跑这一步，不走跳过最新成果的`运行到这里`，也不重跑上游。提交中与其他活动 Run 期间禁用，未保存输入仍走既有离开保护。拒绝执行、结果不确定等不可直接重试的错误显示`查看原因`，先打开该次运行记录；核对后仍可从生成步骤明确重新运行并重新审阅工具请求。

详情导航只展示当前可达入口：Card 的`内容`与`版本`，有生成步骤时显示`生成步骤`，有已载入运行时显示`运行记录`；当前视图即使对象失效仍保留，以显示恢复信息。保留 tablist/tab/tabpanel 和方向键、Home、End，不显示无用途的禁用页签。正文默认阅读，单一编辑入口原位进入编辑；名称仅在面板顶部显示一次并直接改名，标签使用紧凑摘要，出处与文件绑定归入卡片信息。

名称、正文或标签存在未保存修改时，Head 的异步变化不得覆盖本地草稿。关闭按钮、页签切换、画布中的对象切换、桌面 Esc 和移动 scrim 使用同一离开意图，支持保存后继续、放弃修改和继续编辑；切卡时明确标记保存并切换。依次保存仍脏的字段，任一步失败或上下文改变就停止，留在原卡片；已经成功保存的字段不回滚，其余草稿保留。切卡取消时恢复原卡片选择与编辑焦点。textarea 内的第一次 Esc 只处理当前编辑，不得冒泡并同时关闭详情。

转换设置中的成果名、生成目标、完成标准和模型修改也参与离开保护：切换前可继续编辑并保存，或明确放弃；仅打开编辑而未修改时无需确认。运行详情保持运行上下文，不因卡片选择自动跳转。

详情 drawer、`方法`库、`搭计划`与`模型设置`共享同一个右侧栏槽位，任一时刻只存在一个：用户显式打开任一面板会关闭详情 drawer，显式打开详情 drawer 也会收起面板。异步创建或 Run 结果只在该槽位仍为空闲时自动打开；若用户等待期间已经打开其他详情或面板，结果通过通知与画布状态保持可达，不得抢走当前焦点。Compact 与移动 sheet 使用完整模态焦点约束，通知进入任务内；面板互换后重新建立初始焦点，关闭后回到真实触发入口。

画板切换期间，旧 Canvas 与已打开的右侧任务暂时只读，避免用旧画板上下文提交新动作。切换失败时恢复原画板与原任务，并以通知告知失败；不展示可写的旧画布与“未打开画板”错误态的混合界面。

带 `planRef` 的关系在`关系`详情顶部显示计划名称、步骤序号和同一计划导航；带 `workflowRef` 时再显示模板名称与 `applicationId`。两者都不增加第四种对象或“运行全部”。

### 2.5 方法库

工作导航合并为`方法与计划`，不再单列`搭计划`；顶栏命令搜索保留直达`搭一个计划`。同一悬浮面板上部固定`搭一个计划`，下部是`已保存的方法`；加载或空列表不阻止从零搭计划。计划表单分别填写计划名称、最终成果、每步成果与处理要求；最后一步只读映射最终成果，增删和排序后仍由当前位置决定最后一步。预览前不创建对象，确认绑定仍由原画布草稿流程处理。有修改时返回、关闭和切换对象/画板须先明确放弃或继续编辑。

方法与计划从工作导航打开。桌面端使用右侧宽面板，窄屏使用全屏 sheet；当前 Board 保持在背后，不进入另一套工作区。已保存方法的底层对象仍是 WorkflowTemplate。

列表项展示名称、可选说明、完整有序步骤和删除命令。v1 模板不可直接编辑；需要修改时回到画板调整并重新保存。点击删除先进入行内二次确认，明确提示`不影响已有步骤`，只有`确认删除`才提交删除。用户点击`使用`后，临时骨架直接出现在当前画布。

### 2.6 灵感选择器

灵感池从工作导航的`灵感池`打开。桌面端使用覆盖当前 Canvas 的宽弹窗，窄屏使用全屏 sheet；当前 Board 与原编辑任务保留在背景中。灵感记录独立于 Board，只有用户明确提交`保存灵感`或`添加到当前画板`才发生对应写入。

已有条目从`阅读全文 -> 编辑灵感`进入正文与标签表单，保存后返回该条目全文。取消返回原内容，未保存时离开需确认；保存失败或冲突保留草稿，冲突可显式重新载入最新内容。检索结果更新但已选版本不自动替换。

标题区提供`记录灵感`命令，在同一弹窗内切换到专用记录表单，不嵌套第二个 modal。表单包含正文 textarea、常用标签、自定义标签以及`返回检索 / 保存灵感`；自定义标签输入中尚未点击加号的有效文字也随保存一并确认。保存目标是 workspace 灵感池，用户不切换画板也不处理坐标。成功后清空正文、刷新灵感池结果并通过 `aria-live=polite`确认，新记录不自动加入`已选`；失败保留草稿和标签并显示可重试错误。

`Esc` 在记录模式中只返回检索，第二次才关闭选择器；关闭选择器不回滚已经明确保存的灵感。保存灵感时不创建 Card，也不进入 CanvasHistory；只有确认添加到当前 Board 时，灵感才以独立 Card 快照进入当前 Canvas，并形成一条可撤销的 `create` 会话历史。

弹窗顶部包含灵感池状态、关键词输入和标签筛选。结果默认静态摘要、可切换紧凑列表，密度只存本机 UI；右侧为有序`已选`列表。点击结果按顺序加入选择，筛选和全文同层阅读保留已选快照。编号表示添加顺序，不自动成为画布的来源选择。

底部固定显示`取消`和`添加到当前画板（N）`。确认时，灵感池条目作为独立版本快照一次写入当前 Board，并保留轻量 pool 出处。成功后关闭弹窗并通知数量，按核心规格 INSP-08 保留原选择、编辑、drawer、分支草稿与视口；不自动聚焦新 Card。失败保留查询与选择，不出现部分 Card。记录表单有未保存内容时，返回与关闭使用同层继续编辑/放弃确认。

灵感选择器内部不使用`导入`，避免把“放入工作集”与 BoardArtifact 导入混淆。搜索结果本身没有连接 handle，也不自动创建 Transformation 或 Run。

### 2.7 画板管理

顶栏仅显示`当前画板名 ▾`，没有并列的管理图标和原生 select。下拉默认分组显示`常用 / 已打开`，同一画板去重；输入名称搜索所有 active 画板，支持方向键、回车和 Esc。列表限定高度滚动，显示匹配数量；当前项标记`当前`，任务项显示`运行中 N / 待处理 N`，普通项不重复显示正常状态。行内提供固定常用与关闭已打开画板，关闭常用项不取消固定。底部始终提供`新建画板 / 管理全部画板`；归档和废纸篓在完整管理中查看。

`管理画板`是独立延迟加载的管理弹窗，从顶栏画板菜单的`管理全部画板`打开，不嵌套复杂表单。弹窗按`正在使用 / 已归档 / 废纸篓`分段显示生命周期列表，并提供：

- 新建与重命名；重命名保留 Board ID，冲突时保留输入并允许基于最新标题重试。
- 归档、移入废纸篓与恢复；破坏性命令必须显示完整画板名和状态影响。活动 Run 或 Candidate 阻止操作时，用户返回原画板处理，不出现强制隐藏入口。
- `导出画板`与`导入画板副本`；导入先展示格式版本、对象数量、文件依赖和不会覆盖现有内容的确认摘要，提交失败保留选择的文件与报告。
- `备份 Mira 数据`；界面明确列出生命周期、Run、方法、画布版本和已收纳原件，排除 API Key、页面草稿和未收纳文件。
- `导入卡片到当前画板`；在管理弹窗内选择卡片包，预览数量和携带原件数后确认。仅向预览时的 active Board 追加独立卡片，失败保留文件和报告，不自动重试。导出入口位于所选卡片的`更多卡片操作`。复制出处只读，不跳转到可能同名的本地对象。
- 每行使用 `History` 图标进入该 Board 的画布版本；archived/trashed 版本只能预览、导出、创建副本、重命名或删除。

archived 与 trashed Board 不进入普通画板切换或灵感来源。面板允许恢复和导出，不把只读 Board 偷偷打开为可编辑 Canvas。当前 Board 离开 active 集合后切换到另一个 active Board；若没有，则通过普通创建流程建立默认画板。

### 2.8 画布版本

`画布版本`是独立延迟加载面板，从悬浮工具栏或 BoardManager 行内的 `History` 入口打开。列表先读取名称、备注、保存时间和 Card/步骤/Run 数量；只有选中一项后才加载完整只读预览。首版只比较所选版本与该 Board 当前状态，不支持版本树或任意两版比较。

active Board 无活动 Run、无未处理 Candidate 时可填写名称和可选备注并手动`保存画布版本`。保存不增加 Board revision；达到 20 个时明确提示先删除，不自动淘汰。活动 Run 时引导`查看运行`，Candidate 待处理时引导`比较待处理结果`。

预览明确显示`这是只读版本，不会改变当前画布`。主命令`从这个版本创建副本`要求确认新标题，成功后切换到全新 active Board；失败保留原 Board、所选版本和标题草稿。重命名冲突同样保留草稿。删除使用行内二次确认且不可撤销，不进入 CanvasHistory。

## 3. 内容卡与转化

### 3.0 已确认的卡片交互增量（2026-09-07）

以下规则覆盖旧章节中同一呈现的描述，不改变 Card/Transformation 对象语义：

1. Card 标题栏用于拖动，正文用于原生选字与内部滚动。无文字拖选的单击仍选卡；Shift/显式多选维持有序选择。正文选区存在时画布删除、复制 Card、移动等快捷键不执行，文本复制保持原生。编辑按钮与 Enter 仍明确进入正文编辑，正文双击不再承担另一种隐藏动作。
2. 内容详情提供阅读/编辑与展开/收回，同一草稿保持；宽屏来源辅助视图与成果并列，窄屏同层返回，不嵌套 modal。异步读取绑定 Board/版本与预览代次，来源更新不清空用户的成果目标草稿。阅读草稿明确标注未保存。
3. 选择工具栏增加尺寸、同宽、对齐与等距入口，依核心规格原子保存和撤销；旧尺寸不自动迁移，运行或 hover 不调整卡片外框。删除仍先引用预检再明确确认。
4. 编辑器提供次级“保存并新建”，先保存成功才新建；两次操作独立，创建结果不确定时停止并核对，禁止盲目重试。普通保存、新建及空卡删除边界不变。
5. 来源预览、历史输入对照、可选运行范围预估和修改生成步骤使用同一详情/命令入口。预估不是执行授权，文件状态未知不能标为最新；Run 每步仍重查。方法列表突出需要材料、最终成果和步骤数，完整步骤可展开，使用仍零 Run。

### 3.1 Card

Card 默认显示可阅读的正文、最多两个用户标签、必要的版本号和低干扰状态。更多标签以 `+N` 汇总，完整列表使用明确的 group/list 语义提供给辅助技术；标签的编辑仍在详情中完成。不存在固定 TEXT/OUTPUT 类型标签。

新建后立即聚焦详情中的正文编辑器；Markdown Card 标题栏使用明确的`编辑内容`命令，file-reference 使用`查看文件内容`。正文草稿通过`保存正文`或 `Cmd/Ctrl + Enter` 提交，追加一个新 Version，取消修改保留当前 Head。恢复历史会创建新版本。方法应用生成的空目标 Card 使用稳定尺寸，并显示`等待生成`，不显示加载动画。

卡片详情提供独立的`卡片名称`输入与保存/取消命令；清空并保存恢复自动显示。卡片标题与详情名称旁直接提供`重命名`入口，进入同一名称编辑区。名称草稿参与离开保护；冲突保留草稿并提示核对最新名称。标题栏优先显示人工名称，正文完整呈现。

Markdown Card 的正文详情同时显示`本地文件`绑定区。用户可绑定一个工作区内文件；正常保存、恢复或采用结果后自动同步。状态至少区分`已同步`、`待同步`、`本地有修改`和`文件缺失`。检测到外部修改时，文件不被覆盖，用户在详情中明确选择`用 Mira 版本覆盖`或`导入本地修改`；后者追加一个 human Version。file-reference Card 仍只读，不能绑定。

### 3.2 选择

- 单击选中一张 Card，并让已打开的卡片详情跟随；`Shift + click`、显式多选和框选建立有序来源上下文。`Enter` 与 Card 标题栏的阅读/编辑命令打开内容详情。
- 桌面使用 `Shift + click`追加或移除；触屏或需要持续选择时，先从悬浮工具栏或选择工具栏进入显式多选。
- 框选建立多卡选择；`Cmd/Ctrl + A`选择当前画板的全部 Card。
- 多选时 Card 显示 1/2/3 顺序标记，dock 同步显示。
- 历史 Version 默认仅预览；要以旧版开始应用流程，必须先将该版本恢复为最新。

同一组选中 Card 同时服务两类工作：Context dock 把它们解释为有序来源，选择工具栏对它们执行画布整理。两套命令分处画布底部与顶部，不能互相遮挡或暗中改变选择顺序。

### 3.2.1 颜色与分组整理

颜色与分组行为以产品定义 5.2.1、核心规格 4.4.2 为准。选择工具栏提供颜色色板和分组菜单；颜色包含默认及六个预设，混合选择不伪装为统一色。分组菜单支持创建命名组、加入/转入已有组、批量移出。操作提交成功保留原选择与来源顺序，失败保留输入。

虚线框标题是组选择和拖动把手，不是 Card。单击标题选择组并展示组命令；明确“选择组内卡片”才按成员顺序形成普通来源选择。组菜单提供重命名、框色、选择成员、复制整组及解组。解组只移除框；不提供含糊的“删除组内全部内容”快捷入口。

拖动 Card 永不自动进出组，框随位置预览；拖动标题整体移动，松手原子保存。不存在边缘退组阈值或必须分步移动的限制。菜单、Esc、外部点击和键盘焦点有明确关闭路径，移动端所有命令至少 44px 且不依赖右键或 hover。组不折叠、不隐藏运行或待比较结果。

### 3.3 画布基础操作

选择工具栏显示`已选 N 张`，提供复制、创建副本、删除、粘贴、多选开关和取消选择。选择清空或切换画板后，只要当前页面会话的内部剪贴板仍有内容，工具栏继续显示`已复制 N 张`并保留粘贴入口。

- 复制只读取每张 Card 的当前 Head、尺寸和组内相对位置。粘贴创建新的独立 Card，不复制 ID、完整 Version 历史、Transformation、Run 或 `workflowRef`。
- 粘贴以当前视口中心为锚点，保留组内布局；连续粘贴轻微错开并自动选中新 Card。创建副本放在原选择附近，不替换用户已有的内部剪贴板。
- 内部剪贴板可从一个画板带到另一个画板，但只存在于当前页面会话；刷新或关闭页面后不保留，也不读写系统剪贴板。
- 多卡粘贴、成组移动和成组删除各自作为一次原子 Board 变更提交。失败时不留下部分副本或部分删除，移动失败则恢复到已保存位置。
- 点击删除先检查整组 Card。只要任一卡被 Transformation 作为来源或目标引用，就不进入确认并提示先删除相关结构；全部可删时，工具栏变为`删除 N 张卡片？`，用户再次点击`确认删除`才提交冻结的选择集合。
- App bar 的撤销/重做只覆盖当前 Board 页面会话内已记录的正文、Card 位置和部分 Card 创建/删除。正文重放追加 Version；删除重放只使用本进程按批次保存的精确回执恢复原对象。永久失效的删除历史明确提示后移出栈顶，使更早历史仍可执行；暂时错误保留以便重试。标签、转化、Run、Candidate、计划、方法和模型设置不在历史范围。
- 直接记录到灵感池不进入这套历史；将灵感添加到当前 Board 形成的 Card 创建进入当前 Board 的 undo/redo 栈。

桌面快捷键在非输入、编辑和表单焦点下生效：

- `Cmd/Ctrl + A`：选择当前画板全部 Card。
- `Cmd/Ctrl + Z`：撤销最近一项受支持的 Card 操作。
- `Cmd/Ctrl + Shift + Z`，以及 Windows/Linux 的 `Ctrl + Y`：重做。
- `Cmd/Ctrl + C`：复制到 Mira 内部剪贴板。
- `Cmd/Ctrl + V`：粘贴到当前视口中心。
- `Cmd/Ctrl + D`：在原选择附近创建独立副本。
- `Delete/Backspace`：进入删除确认；不会直接删除。
- 方向键：微移 5px；`Shift + 方向键`微移 20px，并将整组位置一次保存。

会话历史最多保留 50 条，切换 Board、刷新或关闭页面后清空；它不是持久审计记录或完整对象图回滚。Mira 也不把复制内容写入操作系统剪贴板。

### 3.4 Transformation

单来源和多来源都先连接一个紧凑转化块，再连接目标 Card。多来源可以在来源数量过大时折叠入向边，但转化块始终显示真实来源数量并可打开详情。转化块不参与 Card 选择、复制、版本或正文编辑。

转化块固定为约 `232 × 124px`，与内容 Card 使用统一的边框、圆角、选中态和交互反馈，但保持更紧凑的中型步骤形态。默认显示成果名称、`N 个来源`、状态和`运行到这里`命令。模型 ID 不占用画布空间；点击块体后在关系详情查看和修改。拖动块体可以独立整理其画布位置；点击运行命令从上游按需生成到该 Transformation，不能误触拖动转化块或移动内容 Card。

尝试状态和 Candidate 从最近 Run 派生；stale 从最近已采用 Run 派生：

- 未运行：中性线和`等待生成`。
- 运行中：低调流动指示与停止命令。
- 成功：保持中性状态，不用成功色长期占据注意力。
- 失败：目标端错误标识和可操作原因。
- stale：琥珀点和`来源已变化`。
- Candidate：目标卡显示`有一个待比较结果`。

关系详情的编辑表单提供`继承默认模型`与`固定模型 ID`。平台不支持步骤模型覆盖时，该设置只读并说明由当前宿主决定；不得允许保存一个运行时会忽略的值。

## 4. 核心推进流程

### 4.0 从灵感池组成工作集

1. 用户打开`灵感池`；需要捕获时进入`记录灵感`，保存正文与可选标签到 workspace 灵感池后返回检索。
2. 保存后弹窗继续打开，新记录不自动进入`已选`，也不增加 CanvasHistory。用户返回检索后输入关键词、点选标签；多个标签表示结果必须全部包含。
3. 用户从不同筛选结果中持续挑选，右侧列表显示稳定的 `1..N` 顺序；刚记录的灵感不自动进入该列表。
4. 用户点击`添加到当前画板`；全部候选一次创建为当前 Board 的独立 Card 快照。
5. 弹窗关闭，保留原选择、编辑任务和视口，通知新增数量。用户从内容卡拖线到空白处发起新步骤，或直接在 Context dock 描述想得到的成果。

取消未提交的记录草稿、按 `Esc` 退出记录模式或关闭选择器、灵感池读取失败或批量放入失败都不得留下新的 Card、Transformation 或 Run；记录模式中的 `Esc` 不直接关闭选择器，已经明确保存的灵感也不因关闭弹窗而回滚。

### 4.1 直接搭计划

1. 用户打开`搭计划`，填写计划名称、最终成果和至少一个有序步骤；可添加、删除、上移或下移步骤，最终成果作为最后一步的成果名称。
2. 提交只把 PlanDraft 放到当前 Canvas，不写 Board；已有选择可帮助定位第一步，但不会自动绑定。
3. 用户把内容卡连到`起始内容`槽，或在槽内明确点击`使用已选`。
4. 用户在第一步点击`添加计划`后，全部 Card 与 Transformation 一次写入，第一步关系详情打开，并提示`已添加 N 个步骤，尚未生成`。
5. 后续编辑、`运行到这里`、Candidate、stale、删除与人工分支全部使用普通对象规则；所有预定成果可用后才可将完整计划保存为方法。

### 4.2 从材料到第一份成果

```text
新建 Card 并提交 v1
  -> 选中来源
  -> 输入成果目标
  -> 添加步骤：创建空目标 + Transformation，保持零 Run
  -> 用户在转化块点击“运行到这里”启动该步 Run
  -> Run 成功，目标建立 v1
  -> 用户原地编辑并继续推进
```

所有创建入口（自定义目标、提取、搭计划、使用方法）统一只铺结构，运行时机完全交给用户，避免“创建即消耗模型”的意外。底层创建与启动仍是两个可审计命令。

### 4.3 多来源

来源 chips 始终展示数量、标题和顺序，可重排和移除。创建前无需进入额外确认页，但主命令附近要能回答“这次会使用哪些内容”。

已有转化的关系详情提供独立来源管理：有序列表支持上移、下移与移除，至少保留一个来源；每次操作明确保存，不要求重新选齐原材料。`添加来源`暂时收起详情并进入画布点选模式，可依次选择多张卡，也可通过可键盘操作的候选菜单添加。确认前只保存页面草稿，取消、切换画板或刷新均零写入；确认后按点击顺序追加并返回该转化详情，退出时恢复原画布选择。

全部来源编辑复用普通 Transformation PATCH 与当前 Head 校验，保留目标、历史和出处；不得加入目标自身、不可用来源或形成依赖环。活动 Run、未处理 Candidate、来源变化或并发编辑冲突明确提示，失败不改变原结构。来源变更保持零自动 Run，已有采用结果按普通 stale 规则提示。

### 4.3.1 B7 输入范围体验（已确认）

范围是每一步、每个来源的设置。首版从`生成步骤 → 来源列表 → 输入范围`进入，普通推导和提取共用；来源行显示`全文`、`已选 N 段`、`范围已变化`或`待选择范围`，不把“选择来源卡”误作已选择其中的段落。新建步骤仍保持零 Run，配置范围后再明确运行；不增加常驻的全局选区工具或额外摘录卡。

范围任务复用右侧详情槽，包含来源标题、读取状态、`全文 / 限定片段`两个明确选项、原文、已选列表与实际输入预览。原文以只读文本提供稳定选字位置；支持鼠标和 Shift+方向键选中，再点`加入所选片段`。有真实 Markdown 标题时可从章节列表选择，加入后仍显示准确原文，不猜测主题。新增片段按选择顺序排列，可上移、下移、移除；重复或重叠当场解释，不静默合并。

限定片段初始为空，旧已保存范围则还原为明确草稿；零选择不能确认，也不自动退回全文。用户可在`本步实际输入`中完整查看所有片段及其顺序，范围外正文不进入该预览。主命令`保存输入范围`仅保存设置，副命令`返回生成步骤`不运行；明确选回`全文`并保存才解除限制。保存成功返回来源行并恢复入口焦点。

读取失败可重试，保留已有片段草稿；原文 Head 或文件内容变化时显示`原文已变化，请重新核对范围`，旧选区作为待核对草稿可读，不自动移动到新文本。重新载入只提供新原文，不视作确认；用户重新选择并保存后解除运行阻挡。保存失败/并发冲突保留草稿，响应不确定先核对当前设置；迟到回包不切换用户已打开的新对象。关闭、切页、切卡、切画板统一走既有离开保护。

方法复用的已确认规则：来源角色需要选区时，应用后显示`待选择范围`，该步不能运行；用户可以选定范围，或明确改用全文。尚未生成的上一步成果先提示`先生成来源，再选择范围`。运行到这里因上游更新导致下游选区失效时，停住并定位到需核对的步骤，保留已完成结果。

Desktop 使用现有可展开详情，Compact/Mobile 同层全屏；原文和已选列表可独立展开，但不叠第二层 modal。底部保存区避让键盘与 safe-area，390px 下长标题、长词和片段编号不撑宽页面。所有添加、删除和排序操作有可见按钮与键盘路径；原生文字复制仍由浏览器处理。

### 4.4 运行中、失败和停止

Run 中目标保持固定尺寸，显示阶段、`查看进度`和停止按钮。`查看进度`直接打开运行详情；用户仍可浏览和编辑其他内容，编辑目标会使返回结果进入 Candidate。

运行详情顶部显示状态、当前公开阶段、可选脱敏细节、可靠耗时和最后更新时间，下方按发生顺序展示最近 20 条公开事件。新事件使用 `aria-live=polite`，不抢走当前焦点。终态缺少可靠结束时间的旧 Run 不显示持续增长的耗时；没有事件的旧 Run 显示低干扰空态，不伪造时间线。

事件只描述环境准备、任务启动、内容进展、工具使用、自动重试、结果检查和终态；不展示 reasoning、原始 Prompt、密钥、完整工具参数、工具输出或底层会话信息。`运行到这里`的全局进度通知显示依赖路径中的第 `X/N` 步和成果名，单个 Run 详情仍只记录自己的事件。

失败后显示`生成未完成`、人类可读原因、`重试`和`调整目标`。停止后显示`已停止`，迟到结果不能让界面回到成功或失败。

### 4.5 stale 与重新生成

来源 Head、来源成员或来源顺序相对最近已采用结果改变后，只出现`来源已变化`。后续失败、停止或 Candidate 尝试不能把这个提示抹掉。用户可直接在当前或任一下游 Transformation 点击`运行到这里`：系统从上游开始检查，只重新生成空结果或来源已变化的步骤，并停在用户点击的位置。系统不因素材变化自动运行、不生成额外 Card，也不创建分支。

### 4.6 Candidate

冲突时保持当前 Head，并提示`有一个待比较结果`。关系详情的主命令变为`比较待处理结果`，比较视图展示当前版本和模型结果；用户只能`采用为最新版本`或`丢弃结果`。采用前再次校验 Head。

本地文件冲突与 Candidate 是两类独立状态：文件冲突不改变 Card Head，也不阻止 CardVersion 历史追加；详情提供`用 Mira 版本覆盖`与`导入本地修改`两个明确命令，不能把本地改动静默丢弃。

Candidate 未处理期间，`运行到这里`、编辑 Transformation 和删除 Transformation 均禁用，并说明`先采用或丢弃待比较结果`。若上游检查遇到 Candidate，整次运行停在该处并打开比较入口。处理完成后这些命令才恢复；不得让新 Run 或结构变化使 Candidate 从产品中不可达。

## 5. 从实践保存流程模板

### 5.1 入口出现条件

当用户选中一条 Transformation 时，Mira 从该步向下寻找最大无歧义线性路径：

- 第一步可以有多个来源。
- 后续每一步必须以上一步目标为线性骨架，也可以读取额外外部来源。
- 遇到 fan-out、缺失或已访问步骤时停止；额外来源会被提取为具名输入槽，不视为 merge 截断。
- 路径中每一步目标都必须有当前 Head，且 Head 的 Markdown 去除空白后非空，或 file-reference 结构有效且路径非空。仅有 headVersionId、悬空引用或空白正文都不算完成。人工写成的成果有效，不要求成功 Run。

至少一条已经产生目标内容的有效 Transformation 才可使用`保存为方法`。如果下游某一步仍为空，预览在该步前停止并说明只保存到当前已完成步骤。入口位于关系详情，不放进空画板主工具栏。

### 5.2 保存确认

关系详情展开的行内确认表单包含：

- 模板名称和可选说明。
- 所有外部来源及可编辑的输入槽名称、说明、必填与数量约束。
- 按顺序编号的步骤标签、目标说明和验收条件。
- 提示：`模板只保存方法，不复制当前卡片内容和运行记录。`

若路径因分支或合并被截断，在步骤列表末尾明确说明停止原因。用户可以取消、调整画板路径后重试，系统不能自行选择另一条分支。

v1 在保存前允许修改名称和说明，不直接编辑步骤正文。保存成功后模板正文不可变；方法有变化时，从调整后的画板路径重新提取。

### 5.3 保存结果

成功后关闭表单，当前 Board、Card、Version 和 Run 完全不变。轻量通知显示方法名称和步骤数；用户可随时从工作导航的`方法`打开方法库，不强制跳离当前工作。

## 6. 应用流程模板

直接计划和方法应用共用 PlanDraft 的虚线投影、显式绑定、取消和原子确认。区别只在草稿来源：直接计划由用户填写计划名称、最终成果和至少一个有序步骤，方法应用由 WorkflowTemplate 预填步骤和具名输入槽。

### 6.1 进入与选择

用户从方法库点击`使用`。Canvas 显示不持久化的方法骨架、空目标轮廓和具名需要内容；内部的“上一步成果”连接预先可见，所有外部输入保持未绑定。系统不得根据当前选择、位置或上一次应用自动绑定内容。

选择模板后进入应用预览：

- 每个输入槽的名称、说明、必填/数量约束和当前手动绑定的 Card Head。
- 模板全部步骤。
- 即将在画板上创建的空目标和关系数量。
- 明确提示：`只添加步骤，不会自动生成。`

若任何 SourceRef 已不是 Head，预览必须刷新并要求用户重新确认；不得静默替换。要从历史 Version 开始，用户先把它恢复为最新。

### 6.2 放置与确认

用户从 ContentCard 连线到步骤上的输入槽；`one` 槽替换已有绑定，`many` 槽按连线顺序追加。触屏和键盘通过槽内`使用已选`使用当前 Card 选择完成同一操作。草稿可取消，取消或切换 Board 不留下对象。

第一步骨架节点内显示必填完成度、`取消使用方法`和`添加步骤`，不再使用常驻底部草稿 dock。必填槽未满足时确认禁用；确认后一次性铺出完整线性计划，保存失败时不留下半条路径。确认区明确说明不会自动生成。

### 6.3 应用后的第一状态

应用完成后：

1. 打开第一步 Transformation 的关系详情。
2. 每张目标 Card 显示`等待生成`。
3. 轻量提示显示已添加步骤且尚未生成。
4. 每条关系提供`运行到这里`；用户可以直接选择当前需要的下游成果。

不存在素材变化触发的自动 Run、倒计时或后台队列。只有用户点击具体步骤后，当前页面才按上游依赖顺序检查到该步骤。

### 6.4 运行到这里

用户在任一转化块或关系详情点击`运行到这里`：

```text
定位当前 Transformation 的全部上游依赖
  -> 从最上游开始检查目标是否为空、来源是否变化
  -> 已是最新的步骤跳过
  -> 需要更新的步骤逐一生成并等待终态
  -> 到用户点击的 Transformation 后停止
```

下游命令不因直接来源尚为空而禁用；系统会先运行能够由现有素材完成的上游步骤。若最上游素材缺少可用 Head，或途中出现 Candidate、失败、停止、状态无法确认，则停在该步并明确提示，不启动后续。

来源变化只显示 stale，不自行运行。用户再次点击下游`运行到这里`时，stale 上游先重新生成；它的新 Head 会让依赖它的下游成为 stale，并在同一次有界操作中继续更新。目标已有人工内容但从未产生已采用 Run 时保持不变。

用户手动修改任一步 instruction、来源或关系后，该对象仍可执行；界面提示`已调整当前步骤，保存的方法保持不变`，模板本身不变。

编辑表单以打开时的 Transformation revision 提交。若另一窗口已经修改，保留当前表单内容，刷新画板基线并提示`转化已在其他窗口更新，请刷新后重试`；不得用旧表单静默覆盖新修改。

### 6.5 计划识别与删除

同一次应用的步骤在 Transformation 标签中使用轻量编号 `1/N`，不添加包裹 Card 的大容器。点击该关系打开详情，可看到来源模板、本次 `applicationId` 和同计划步骤导航。

删除方法前必须二次确认，并明确`不影响已经添加的步骤`。删除后，已有步骤继续保留原 `workflowRef`，方法详情显示`方法已删除`，仍可按普通 Transformation 运行到目标。删除计划中的对象继续遵循普通 Card/Transformation 规则；v1 不提供隐式级联删除整条计划。

## 7. 手动分支

用户从一张或多张来源的连接 handle 拖到空白位置：

1. Context dock 进入`新方向`状态，并保留松手位置。
2. 用户填写成果目标。
3. 用户确认后在该位置创建独立目标和 Transformation。
4. 新关系创建后仍保持未运行。

这也是流程计划中产生新方向的方式。rerun、Candidate、stale 和错误恢复都没有`自动分支`操作。

## 8. 生命周期、导入导出与归档边界

产品内`归档`只表示 Board 内容与运行的可逆只读状态，仍允许在 BoardManager 重命名、导出、恢复或移入废纸篓；产品内`删除`第一批只表示移入可恢复废纸篓，此时只允许恢复和导出。两者都不同于仓库 `archive/` 中已经退出生产运行时的 legacy v1 数据。

导出 Board 时，若该 Board 仍有活动 Run，命令不可用并提示先等待或停止。成功下载使用可辨识文件名和 `.mira-board.json` 后缀。导入使用系统文件选择器读取 `.mira-board.json`，先在内存和 staging 中验证，再提交为全新 active Board；预览明确显示终态 Run、包外出处和只作解释而不会安装的方法 provenance，不提供“冲突覆盖”“合并到当前画板”或“恢复原 ID”。

完整备份使用 `.mira-backup.json`，覆盖 active、archived、trashed Board、Run、方法、灵感池与全部画布版本。当前画板管理面板只负责下载。Desktop 在 Host 启动前的 workspace chooser 提供`从 Mira 备份恢复`，用户依次选择备份和新建/空目录；成功后才启动该 workspace，失败则留在 chooser 且原 workspace 不变。Standalone 使用显式离线 restore 命令并同样拒绝非空目标目录；运行中的 workspace 不提供覆盖恢复。旧 V1 备份仍可恢复并显示为没有画布版本。

旧 v1、Action 和 chain 数据不属于 Mira 的产品体验。App bar、更多菜单、设置、HTTP API 和 bridge 均不提供查看、兼容或迁移入口。

需要恢复历史内容时，由操作者在产品之外运行显式离线工具：只读归档输入，生成独立并经校验的 v2 文件，再由操作者决定是否导入。离线恢复不会自动生成 WorkflowTemplate；有效方法必须回到当前画板重新走通后保存。

## 9. 响应式与无障碍

### Desktop `>= 1100px`

- App bar 高 58px，左侧悬浮工具栏宽 84px（可收为 54px）；Detail drawer 含右侧边距默认占用 392px，展开时面板与右侧边距合计 `min(800px, W - N - 360px)`，Canvas 控件与底部 dock 在剩余空间内布局。
- Context dock 最大宽 760px。
- 选择工具栏位于画布顶部中央，与 Context dock、Card 和 drawer 保持可操作间距。
- 方法库宽 392px，打开后 Canvas 正确缩小。
- 画布版本面板宽 360px，打开后 Canvas 正确缩小并保持当前对象可见。
- 应用预览保证计划和确认命令同时可见。

### Compact `720px..1099px`

- 悬浮工具栏宽 54px；搜索在顶栏中央保持输入栏形态，右侧为撤销/重做/系统设置。
- drawer、方法库与画布版本使用覆盖层，背景 inert；通知在当前任务内可读、可关闭。
- 多来源 chips 横向滚动。
- 选择工具栏保持单行；宽度不足时只在自身内部横向滚动。
- 第一步方法节点内显示输入完成度与“不会自动生成”提示，不增加第二个底部操作面。

### Mobile `< 720px`

- drawer、方法库和画布版本使用全宽 sheet；列表、预览和确认在同一层切换，不叠加 modal。
- Context dock 可折叠；触控目标至少 44px。
- App bar 保留字标、统一画板菜单、中央搜索图标、右侧撤销/重做/系统设置；底部悬浮工具栏直接展示新建、多选与五项工作入口，窄于 390px 时允许工具栏自身横向滚动。设置收纳网格、外观和模型。
- 所有主路径按钮、菜单项和 drawer 页签的触控目标至少为 44px。
- 选择工具栏按钮至少 44px，宽度不足时只在工具栏内部横向滚动。
- 模板步骤纵向展示，不把完整计划压成不可读缩略图。
- 开始使用方法时只聚焦第一步；只有用户已经显式选择内容时才同时保留该内容卡，后续步骤通过平移查看。
- 转化块保持稳定紧凑尺寸和至少 44px 的运行命中区；步骤详情使用全宽底部 sheet，打开时隐藏 Context dock，避免两层底部操作面重叠。
- 灵感选择器使用全屏 sheet；记录模式替换而不是叠加结果主体，软键盘打开时`保存灵感`仍固定可达；检索模式的`结果 / 已选`使用分段视图，底部`添加到当前画板（N）`固定可达，确认后 sheet 关闭并保留原上下文。

所有图标按钮必须有 accessible name 和 tooltip。画布版本 dialog/sheet 关闭后焦点返回触发入口，保存、删除和创建副本的结果通过 `aria-live=polite` 通知但不抢走编辑焦点。状态不能只依赖颜色；新增计划和 Run 终态同样通过 `aria-live=polite` 通知。

## 11. A3–B8 批次体验增量（2026-09-13 已确认）

产品和命令分别见产品定义 §5.11 与核心规格 §11；本节只定义可发现入口与交互。不把草案当成已实现界面，B7 继续使用已确认的 §4.3.1。

### 11.1 网页/PDF 阅读与剪藏

工作工具栏`材料`打开 §2.1 的同一个材料任务，默认展示导入文件的目录浏览，可切换到`已收纳材料`；导入成功后进入材料库。网页输入带可见 URL 标签和明确读取命令，空输入不请求。PDF 文件卡的`查看文件内容`进入同一阅读任务，不直接把 PDF 二进制送给模型。网页可以单独`收纳完整网页正文`，保存摘录时也保留同一冻结正文原件；只读预览不持久写入。

读取成功后在当前任务内显示标题、地址或相对路径、采集时间、全文字数、页数及阅读限制。原始 HTML 不执行；PDF 按物理页提供上一页、下一页、直接页码输入和按需原页预览，文本与原页同源。原页在 Desktop 可并排，窄屏`提取文字 / 原页`同层切换，保留滚动位置和选区。失败页/扫描页在页列表中有文字标记，不仅用颜色，不能在关闭警告后变成完整成功。

保存范围由`完整可读内容 / 选择页或片段`明确选择，初始不隐含保存。原生选字后点`加入所选片段`，章节/页选择和多段排序复用 B7 的范围列表、原文预览与键盘操作。全部原文可阅读，底部显示本次将保存的范围与字数。用户只有浏览时可随时返回，零内容写入。

两个保存目的均直接可见：

- `保存为材料卡`：在确认区写明当前画板名、创建一张独立卡片，以及“所选正文会保存在 Mira，并随画板导出和备份”。没有 active Board 时不可用，说明先打开画板；不自动新建画板。
- `剪藏到灵感池…`：在同层切换到引用、个人备注和标签预览。无 Board 也可用，引用不可伪装为用户修改后的原句；个人解释写入备注。主命令为`保存剪藏`，不调用模型、不加入画板。成功仍停留在当前阅读任务，并提供明确返回灵感池入口，不自动选中记录。

一次预览只完成一个保存意图，成功后显示已保存对象链接；要再次保存需明确重新读取。网页或 PDF 重新读取前保护现有选区/备注草稿，读取成功不会自动保存。预览过期保留可复制草稿，提示重新读取并核对；不能把新正文套入旧坐标。保存中禁用相反命令，错误和不确定结果有不同提示；不确定结果先检查已保存内容，不能鼓励直接连点重试。

### 11.2 当前步骤的可选指导

`生成步骤`的设置在用户目标与完成标准之后提供`辅助指导（可选）`折叠区，默认`不使用`，不出现在选卡 dock 推荐位置。可明确选择`证据对照 / 精读 / 修订`，先显示用途和完整指导，再`应用到此步骤`。用户要求不自动填入，证据对照需要填写检查标准；修订说明将生成独立修订稿。

已选择时显示指导名称、版本、是否调整过及`查看 / 调整 / 移除`。新版可用只在该区说明，`查看新版差异`后才能明确替换；不自动下载或运行。保存仍只是配置，原`运行到这里`与`重新生成`语义保持不变，已有成果不因修改指导而自动刷新。运行历史单独展示“本次指导”，旧方法复用显示其冻结版本。

该指导区的未保存文本复用步骤的离开保护。加载失败保留原设置和用户目标，不能静默选择“不使用”。全部选择项有可访问名称，长指导可滚动、可复制，隐藏区不吞掉焦点。

### 11.2.1 输出要求（2026-09-14，第一实施批）

生成步骤在指导旁显示独立“输出要求”摘要，进入同层设置页。可选择卡片简洁、均衡表达、详细展开或原有表达；查看/调整完整规则与版本，选填字符上限、正文结构。旧步骤初始显示原有表达，不自动迁移。提取步骤结构只读显示由提取格式确定。

设置页显示完整旧规则与调整差异，取消零写入，保存复用步骤 CAS、活动 Run/Candidate 门禁与离开保护；保存后返回步骤，不运行。运行记录可展开本次冻结规则与约束，检查失败显示实际值并保留全文。未配置约束不显示“通过”，不把检查当作质量保证。Workspace 默认管理与新工具入口随对应批次交付，第一批不显示可操作的占位按钮。

### 11.2.2 项目默认与指导目录

能力管理第二批从系统设置打开同层侧栏，不依赖当前 Board。分别管理新步骤默认风格和指导目录；默认展示完整规则，可明确调整，保存说明只影响新步骤。指导目录以平铺行列出名称、来源、版本和停用状态，可新建、明确导入 `.md`/`.txt` 文本、查看全文、保存新版本、停用及恢复；导入只读所选文件，先填入草稿再保存。长文本滚动，错误与草稿保留，切换目录项/关闭沿用统一离开保护。步骤内选择新版先核对旧规则和全文差异，保存后不运行。MCP/Python 尚未接入时不显示可操作占位项。

### 11.3 重跑清单与旧卡对照

清单详情在已有历史批次旁提供`与上次拆分对照…`。先明确选择旧批次，再进入同一任务面板的平铺列表；显示新清单版本与批次时间。旧卡丢失、旧清单版本不可用或当前清单结构损坏都有明确状态，不能继续假定对应。

每行展开后依次阅读旧条目、旧卡当前内容、新条目与本次拟采用正文；宽屏并列比较，390px 纵向。非完全一致项必须从可搜索列表明确指定旧卡，显示“待指定对应”；多个新条目可加入同一更新草稿，但不会自动合成。差异计算过大时退回完整阅读，不能提示无差异。

更新按钮为`采用到「卡片名」`，一次只更新一张卡；旁边提示将追加版本，原卡人工内容以当前栏完整可读。新条目另行勾选后用既有`创建 N 张新卡片`批量保存，数量与动作分开，不能用“同步全部”掩盖写入粒度。未出现的旧项保持可达且没有默认删除动作。

目标或来源在预览后变化时保留草稿，显示`内容已变化，请重新比较`；重新比较更新阅读基线但不自动采用。每张卡保存后独立显示结果，下一个失败不撤销前一个。离开未保存修改时继续/放弃，不隐式采用。Candidate 沿用原运行比较入口，不与人工对照草稿混名。

### 11.4 设备与更新体验

Desktop 系统设置提供低频`版本与下载`入口，展示当前版本、系统/架构与官方发行入口；选择查看发行页不关闭当前工作区或丢失草稿。手动更新说明先保存并退出应用、替换应用程序、重新选择原 workspace；回退说明必须区分应用回退和数据恢复，不能一键覆盖 workspace。实际发布策略见平台适配器 A4 草案。

A3 的软键盘、旋转、safe-area 与选字/拖卡边界必须在真实触屏记录设备和版本。Desktop/390px 验证继续覆盖所有新增任务的固定 footer、滚动末项、键盘焦点、退出回到入口和零 console 新错误；这部分是实现检查，不替代 A3。

## 12. 体验验收

- 新建 Card 后无需第二次点击即可输入。
- 连续新建 Card 不发生实质重叠；计划落地只聚焦起始来源、第一步与第一目标并保持可读。
- 单卡和多卡使用同一 Context dock；方法连接的确认与取消位于第一步节点内，不增加第二个 dock。
- 直接计划和方法应用共用同一 Canvas 草稿；不存在内容/Workflow 全局模式切换。
- Context dock 添加步骤和创建 WorkflowPlan 后均为零 Run；运行只由“运行到这里”显式启动。
- 用户添加步骤前能说出需要的内容、绑定内容和步骤数，添加后能看见完整计划。
- 素材变化本身不会启动任何步骤；用户点击下游后只运行到该目标。
- 最新步骤会被跳过；空目标或来源已变化的步骤按上游顺序运行。
- 任一步 Candidate、失败、停止或来源不可用都会阻止后续步骤启动。
- 任一步人工编辑都受 Version/Candidate 保护。
- 方法删除后，已添加步骤仍可继续运行到目标。
- fan-out 和 cycle 不被系统猜测为线性模板；线性步骤的额外来源被显式保存为输入槽。
- 失败或取消应用不留下半条计划。
- 取消直接计划、切换 Board 或原子创建失败时不留下 Card、Transformation、Run 或模板；成功添加后仍是零 Run。
- 只有用户手动画线或显式创建目标才产生分支。
- 从灵感选择当前 Board 的离屏 Card 后，第一张所选 Card 完整进入视口并保持选中；只有整组仍可读时才聚焦整组。
- success/info 通知自动消失，progress 被终态替换，error/attention 持续可达；通知在 1440、1024 和 390px 不遮挡工具栏、drawer、dock、面板底部命令或其 hit target。
- 重命名、归档、移入废纸篓和恢复不改写 Board 内部对象；活动 Run 或 Candidate 始终阻止 Board 离开 active。
- BoardArtifact 重复导入产生互相独立的 Board；无效或超限文件不产生可见半写。
- 备份清楚展示包含与排除项，损坏成员不会被静默遗漏；完整恢复只进入新建或空 workspace。
- 稳定 active Board 可手动保存画布版本；Run/Candidate/上限门禁清楚可解释，版本预览只读且恢复只创建独立副本。
- active、archived、trashed Board 的画布版本入口均可达；1440、1024 和 390px 下列表、预览、确认和固定命令区不重叠。
- 复制并粘贴多张 Card 后，当前 Head 内容、尺寸和相对布局保持一致，但 Card/Version 身份与所有关系、运行和 Workflow provenance 都是独立的。
- 内部剪贴板可跨画板、不可跨页面会话；复制粘贴不改写系统剪贴板。
- 批量创建、移动和删除只能整体成功或整体失败；有任一卡被 Transformation 引用时整批删除拒绝。
- 删除必须经过带数量的二次确认；桌面快捷键与触屏显式入口都能到达同一组命令。
- 撤销/重做只重放当前 Board 会话内约定的 Card 操作；正文重放继续追加 Version，切换 Board 或刷新后不可继续。
- 整个生产路径只有当前画板与方法库，不存在 v1/Action/chain UI 或运行时入口。
- 灵感筛选和选择零写入；直接记录只写 workspace 灵感池且不进入工作集。添加到当前 Board 产生可撤销的 `create` 历史；批量放入失败零半写，成功后选择顺序与弹窗一致并复用现有 Context dock。
