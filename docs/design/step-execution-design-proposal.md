# 步骤执行设置完整交互方案

- 日期：2026-09-13。
- 状态：2026-09-14 用户确认整体设计并授权分批实施。独立输出要求已实现，见[第一批验证](../validation/2026-09-14-output-policy.md)；本文其余工具、能力管理和依赖交互保留为后续方案，不代表已实现。已实施规则以产品、核心规格、体验设计和 UI 系统为准。
- 需求与验收：[步骤执行设置需求](../refactor/generation-controls-requirements.md)。本文负责页面与状态，当前权威仍为产品、核心规格、体验设计和 UI 系统。
- 范围：输出要求、Skill、内置工具、MCP、Python、能力管理、运行记录、错误和方法复用；演示数据不作为实际集成证据。

## 1. 信息架构

只有三种步骤配置概念：输出要求、处理指导、工具能力。MCP 和 Python 是工具来源；连接、代码与运行环境维护放在宿主能力管理。

| 位置 | 内容与入口 |
| --- | --- |
| 画布转化块 | 成果名、输入数量、真实状态、运行；点击进入既有生成步骤详情，不添加新节点类型 |
| 生成步骤 | 目标/完成标准、有序输入、输出要求、处理指导、工具能力、模型；摘要行进入具体设置 |
| 设置子页 | 选择列表、完整规则、依赖、访问范围、代码与差异；同一任务内返回，不叠弹窗 |
| 运行记录 | 冻结设置、真实调用、检查、结果和等待审阅；运行中可查看 |
| 系统设置 → 能力管理 | 新步骤默认风格、指导目录、MCP 连接、Python 环境与脚本 |

桌面沿用 380px 详情与已有扩展阅读机制；复杂工具/代码页可明确展开为大详情。390px 使用同层全屏任务与返回，保留滚动、焦点和草稿。对话原型采用并列局部导航方便评审；生产普通窄详情采用摘要行深入，内容和状态一致。

## 2. 步骤主面板与保存

顺序为成果与要求、有序来源、输出要求、处理指导、工具能力、模型。摘要如“卡片简洁 · 300 字符”“证据对照 · 1.0.1”“2 项 · 仅已选材料”，无需每次重新配置。

```text
生成步骤                            ×
提炼访谈中的产品约束
目标与完成标准                  编辑
输入材料                2 张 · 已限定
─────────────────────────────────────
输出要求         卡片简洁 · 不限字数  ›
处理指导         证据对照 · 1.0.1    ›
工具能力         2 项 · 仅已选材料    ›
模型             继承默认模型        ›
─────────────────────────────────────
检查本次输入与设置          运行到这里
```

读态显示运行命令。有未保存编辑时底部改为“取消 / 保存设置”，运行需先保存；不做含混的“保存并运行”。子页选择均属于同一草稿，取消不写 Board。进入能力管理并返回保留草稿，切换对象/关闭遵守统一离开保护。

活动 Run 期间设置只读，可核对本次快照；首版不同时编辑下一次配置。Candidate 存在时优先展示比较入口，修改和重跑继续受既有门禁约束。

## 3. 输出要求

### 选择与约束

单选“卡片简洁 / 均衡表达 / 详细展开”，每项一条用途说明；选中后可查看完整规则和版本，明确调整后标“已调整”，可恢复该版本原文。

“输出约束”默认折叠：字符上限可留空；结构可选跟随任务、段落、条目或表格。计数口径拟定为 Unicode 码点，包含标题、标点和空白；字段标为字符而不是 token 或汉字，组合表情可能占多个码点。实际结果显示计数口径供核对。

提取清单采用既有必要协议，结构项显示“由提取格式确定”，风格不能移除条目身份和出处。自然语言与显式字段若矛盾需要核对，不能承诺程序识别所有语义冲突。

### 强度与默认值

风格与 Skill 都作为生成指导生效；Skill 不是更强的约束容器。两者同样保存实际文本/版本。规则优先次序为应用安全与必要协议、用户具体任务和显式约束、方法指导、默认表达偏好；无法同时满足的要求应指出冲突。

程序检查可计算的字符数和格式；模型负责精炼与语义保真。界面称“约束检查”，不称“质量保证”。未通过时保留正文和实际值，允许调整或明确重跑，不自动截断/调用模型；普通 Head/Candidate 写回语义不因诊断改变。

能力管理设置“新步骤默认风格”，只在创建时解析成快照。已存在步骤不随默认改变，方法使用自己的规则并显示来源；旧数据为“原有表达”，查看新旧规则后明确启用。升级只影响后续明确运行，已有成果不自动改写。

## 4. 处理指导（Skill）

目录单选“无指导”或一项，维持每步一种的现行约束。内置、自定义、明确导入用来源文字区分。名称、用途、版本直接可见；全文、调整、升级差异和所需完成标准在同一详情展示。不增加推荐标记、自动选择或后台匹配请求。

依赖区域区分必需与可选能力，提供“查看所需工具”。用户逐项设置范围，不因选择指导授予权限。缺必需依赖时可以保存草稿/计划，步骤摘要提示待配置，阻止对应 Run；可选能力未启用不能冒充已完成其操作。

导入文本中的脚本、安装和联网说明只是材料，不被执行。代码和工具资源须分别登记与审阅。升级同时展示依赖变化；移除指导不暗中移除用户已选工具或改变输出偏好。

多 Skill 并用仍需独立定义顺序与冲突，本次不以无序复选框改变现有语义。

## 5. 工具能力

目录支持搜索和“全部 / 内置 / MCP / Python”筛选，行内显示能力名、用途、来源、状态和访问摘要。勾选加入本步草稿，保存后生效。已选项可明确移除，不因筛选隐藏而失去选择。

每项详情展示输入绑定、访问范围、调用方式、输出类型、是否有外部副作用及资源预算。代码和权限必须直接可审阅；schema、技术身份和摘要放技术详情。来源包含连接稳定身份和工具名，不能按显示名称混淆能力。

| 调用方式 | 配置与行为 |
| --- | --- |
| 模型按需 | 用户选允许集合与范围；模型可调用但不保证使用，未调用不算失败 |
| 生成前执行 | 完整绑定参数与显式顺序；确定性工具执行后再生成，必需项失败停止 |
| 生成后检查 | 仅支持确定性检查器；检查真实输出，不修改、不自动重跑 |

不支持的方式禁选并解释原因。同一工具不同阶段使用时保存为独立配置实例。固定列表支持按钮/键盘排序，不引入条件、循环或新的工作流画布。强制前处理不依赖模型“记得调用”。

默认范围是本次冻结来源与选区。额外文件、URL、连接内资料分别指定边界，材料中出现的链接/路径不自动获准。远程只读仍会发送查询数据，摘要需显示服务商和数据类别。

已授权范围内的只读调用不重复弹确认。扩大范围、临时代码和外部写操作进入可见审阅；写操作显示目的地和完整拟写内容，授权绑定该次请求。回包不确定显示待核对，不能无条件重试。

## 6. 能力管理与 MCP

连接列表显示名称、远程/本地、状态、已核对工具数量。新增远程连接填写地址与认证；新增本地连接显示程序、参数、目录和环境变量名，说明连接可能启动进程。凭据使用秘密输入和宿主安全存储，不进入领域数据包。

“测试连接”只握手和发现目录，不调用业务写工具。发现成功后逐工具指定本 workspace 可用性；连接成功、workspace 可用与本步启用是三个独立状态。

未配置、连接中、需要登录、已连接、离线、能力变化和不兼容都有明确恢复动作。schema/权限声明更新显示差异；新增工具不进入旧步骤。断开保留历史，旧步骤显示资源缺失。换 workspace 应重新绑定，不能凭同名连接自动复用。

MCP resources/prompts 不直接伪装成 tools；读取资源和导入指导经相应入口明确处理。服务只读注解是线索，未经验证不能显示为宿主保证。官方依据：[MCP 工具定义及注解](https://modelcontextprotocol.io/specification/draft/server/tools)。协议不自动提供 Mira 的事务和可信执行保障。

## 7. Python 环境与脚本

### 已审阅脚本

能力管理提供明确导入：展示来源、代码全文、入口、输入输出 schema、依赖、版本/摘要和权限。环境页显示实际运行时和隔离状态。安装依赖、测试脚本、保存为工具是独立动作；测试也必须核对输入与范围。

登记后进入统一工具目录，步骤填写必要参数。执行前核对代码、依赖及环境身份；实质变化使旧审阅失效，不后台安装依赖或更新代码。

默认只读冻结输入副本、临时输出目录，禁止真实 workspace/环境秘密/网络访问；限制时间、内存、进程数和输出大小。缺少可靠隔离时显示不可用；venv 不构成文件/网络隔离，macOS 与 Windows 分别取得原生证据。

### 模型临时代码

工具页提供“允许生成临时 Python 代码”，默认关闭。开启只允许提出代码；实际代码产生后 Run 进入等待审阅，显示全文、依赖、输入输出、网络/文件范围与资源上限。

按钮为“执行这份代码 / 拒绝并停止”，审阅绑定代码摘要与权限；代码被修改后重新审阅。执行显示真实阶段、耗时和停止，stdout 不作为模型思维。异常/超限保留代码与诊断，不提权、不自动无限修正。长期保存需另一次明确登记。

### 结果

文本与结构化数据作为中间结果/检查证据，最终仍生成普通目标 Card。图表/CSV 等先预览再明确保存文件，不自动创建新型卡片，不直接写真实 workspace。附件持久期限、大小、导出和删除范围须补核心规格；未实现时不可宣称可移植。

## 8. 运行记录与异常

顶部展示 Run 状态、目标和实际模型，“本次设置”展开冻结风格、Skill、输入和工具策略。事件包含时间、动作、来源、真实结果摘要，展开可核对允许留存且脱敏的参数/证据。未执行的阶段不生成成功事件；已选但未用的工具显示未调用。

顺序可为准备输入 → 固定前处理 → 模型生成 → 按需工具 → 继续生成 → 约束检查 → 普通写回。等待操作/代码审阅属于活动 Run 的公开阶段，沿用 running 门禁保护，不是 Candidate，不成为后台续跑入口。等待上限与过期行为须在核心规格明确。

| 情形 | 呈现与处理 |
| --- | --- |
| 草稿未保存 | 保存/取消，先保存再运行 |
| 模型不兼容或缺依赖 | 指向具体问题，阻止启动，不静默去掉工具 |
| 输入范围失效 | 回到来源核对，不能退回全文 |
| 等待审阅 | 具体代码/请求与范围可见，执行或拒绝并停止 |
| 按需只读工具失败 | 结构化失败返回模型；再次调用受明确次数/费用策略限制 |
| 必需前处理失败 | 停止，不能把缺失结果当空文本继续 |
| 检查未通过 | 保留正文与实际值，普通写回继续，失败不能冒充通过 |
| 停止或超时 | 不发新调用，迟到结果不改 Head；已发生外部副作用不伪称撤销 |
| 外部写入回包不确定 | 保存操作身份并核对；无核对 API 时人工核对，不盲目重放 |
| Head 并发变化 | 模型结果进入既有 Candidate，不绕过 CAS |
| 进程重启 | 中断，不后台恢复调用；外部不确定结果单列核对 |

全部调用有轮次、总次数、时间和结果大小预算；费用无法准确预估时说明未知，不显示虚构金额。真实运行记录与设计演示必须明确区分。

## 9. 方法与可移植性

步骤保存实际规则和工具配置，Run 冻结有效设置与实际调用证据。历史保存必要 schema/代码身份，不把引用文件正文、密钥、环境秘密或本机批准装入数据包。

方法保存规则、输入角色、能力需求和固定顺序，不保存具体材料、机器路径、连接凭据或临时代码批准。应用后一次列出待绑定资源，可先铺计划，阻止缺依赖步骤运行。代码作为可执行资源需要独立安装/审阅，不能由导入方法触发。

中间证据与附件的留存、体积、清理、导出、备份和 Checkpoint 范围进入核心规格。冻结不等于无差别保留全部工具输出；未保留正文与不可复现的外部响应必须如实标记。覆盖旧数据缺字段、默认升级、重复应用和同名工具重绑定。

## 10. 视觉与可访问性

沿用现有六套外观、语义 token、Lucide 和连续详情面。来源为低强调文字，状态有文字，不做能力卡片墙或五种并列模式。

普通详情紧凑，长规则/代码明确扩展阅读；390px 单列，搜索/筛选/按钮换行，代码仅自身横向滚动。触屏命中至少 44px；选择、排序、返回、移除与停止有键盘入口。

footer 预留正文空间、scroll-padding 和安全区；软键盘不挡输入/主按钮。返回原焦点，关闭先保护草稿；通知不抢任务，等待审阅与 Candidate 从画布/运行记录保持可达。

## 11. 评审与验证边界

一次设计全部入口、状态及兼容关系，实际生产只开放已实现能力。对话原型使用局部演示状态，不访问服务、不执行 Python、不证明隔离有效。

评审关注用户是否能预测本步使用的方法、输入、操作与写入，能否区分默认/快照/方法，能否在等待和失败时找到恢复路径。实现前补对象/API/错误/配额/认证/隔离规格并确认产品语义；工程、真实质量、人工修改成本、服务行为与原生隔离分别验收。
