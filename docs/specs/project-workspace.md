# 项目工作区与受管材料

状态：2026-09-13 用户确认设计后进入实施。实现完成度见[交付记录](../refactor/project-workspace-plan.md)。本规格扩展核心规格的 workspace、文件与可移植数据契约；旧的“不携带 file-reference 正文”仅继续适用于未收纳的历史外部引用，不适用于本规格的受管材料。

## 1. 项目与画布

一个项目目录对应一个 workspace，多个 Board 共用材料、灵感池和方法库。Card 仍是唯一画布内容对象。跨画布复制创建独立 Card/Version；材料原件可以共用，正文、Head、Run 不共享、不自动同步。跨 workspace 复用通过显式导出/导入携带材料，不依赖原目录，不自动运行。

Node 新工作区在项目根创建 `.mira/workspace.json`，记录 `{ format: 'mira-workspace', formatVersion: 1, id, name, createdAt }`；内部 Board/Run/Workflow/Checkpoint/池/事务保留既有逻辑名称，物理位于 `.mira/`。受管原件位于 `materials/`。现有项目的代码、文档、Git 与任意其他文件不移动、不扫描、不自动进入上下文。稳定身份随项目目录移动保留；从备份恢复的新工作区获得新 workspace 身份，原 Board/Run 身份遵循备份原规则。

已有根级 v2 数据仍能打开，不能因升级自动搬迁。格式未知、损坏或新旧布局同时包含业务数据时拒绝猜测。旧布局转换使用显式离线命令，在源锁保护下复制到全新目标，原数据不改写；不处理 v1/archive。材料收纳只针对明确选择的文件，不把旧路径的当前字节冒充历史版本内容。目标中新布局提交必须原子完成，失败零可见半工作区。

## 2. 材料收纳

用户确认“导入材料”后，无论文件原来在项目内外，均保存不可变字节副本；已是受管材料则核对完整性后复用。文件名只是显示信息，稳定 ID 与 SHA-256 绑定字节；同字节原件在 workspace 内只保留一份。不同内容同名不覆盖，同一来源的新内容产生新快照，旧卡继续指向旧副本，除非用户明确替换其来源版本。

材料记录包含格式版本、ID、相对路径、原始显示名称、字节数、SHA-256 与采集时间；网页另保留实际 URL、标题和采集时间。不得存储 API Key、认证头或浏览器登录信息。文件副本先写临时位置并重读校验，再原子提交材料记录/原件；失败不出现半条目。复用、阅读、模型输入与导出必须核对受管字节摘要；外部篡改返回明确损坏错误，不能自动接受或覆盖。

Node 首版限制单个原件 64 MiB；任意扩展名可以收纳，是否能解析按实际读取能力显示。网页保存实际取得的正文快照，不承诺离线复制整站。只读预览零持久写入；明确导入网页或保存网页材料时才收纳。PDF 文件导入先完成原件收纳，再按需阅读；取消阅读不撤销已经明确完成的导入。

材料库不依赖当前 Board，可以导入、列出、预览，再明确添加为普通 file-reference Card。添加多次可生成独立卡片而共用原件，零 Run。删除 Card/Board 不删除材料。首版不提供自动垃圾清理；原件删除须另外定义全历史引用检查及确认，不通过系统自动清理绕过此边界。

自动文件绑定不得写入 `.mira/`、受管 `materials/` 或既有内部业务目录。项目成果仍可明确绑定到 `docs/` 等项目文件；外部变更继续走原有文件冲突与 human Version 导入。外部工具不得直接改写 `.mira/` JSON 来修改卡片。

## 3. 可移植数据

BoardArtifact V2 在既有 BoardArtifact 内容上增加受管材料字节及其严格元数据；只携带该画板所有版本/材料出处需要的受管资产，按 ID 去重，不额外读取其他项目文件。旧 V1 继续读取和导入，未收纳的历史文件路径显示为外部依赖。导出所选卡片只包含当前 Head、尺寸、相对布局和必要材料，不携带原结构/Run/完整历史；在目标画布创建新身份，并保留只读复制出处。

MiraBackup V3 包含全部受管原件（包括尚未加入画布的材料）及 V2 的全部对象；V4 再携带项目执行设置，字段与校验以[核心规格](core-specification.md)“项目执行设置与指导目录”为准。旧 V1/V2 继续恢复并按无受管资产处理；V1–V3 没有项目执行设置，打开时沿用缺省行为。锁、缓存、API Key、运行时会话和未导入的代码/项目文件不携带。完整恢复只向全新/空目标；新布局、材料、全部受管对象一并 staging 校验后，以目录 rename 提交。

首版沿用有界 JSON envelope，资产字节为规范 base64；Board 包 64 MiB、完整备份 256 MiB 的序列化总量上限继续生效，不能拆包后伪装整次原子操作。先校验总量、资产个数、路径、名称、base64 规范、实际长度与 SHA-256；文件路径只允许规定的受管路径，不接受包中任意写入目标、软链接或路径穿越。未知版本、缺资产、重复 ID/路径、哈希不符整包拒绝。空白/非文本字节不得被文本归一化改写。

同工作区相同资产复用，跨工作区安装为相同内容地址的本地副本；冲突已有字节不覆盖。先验证包和所有目标碰撞，再提交。失败不能留下可见半 Board 或材料；重启可恢复的事务必须记录完整材料提交边界，不依赖进程内回滚。并发导入、备份、材料收纳复用同一 coordinator；不建立绕过单写者或 snapshot 的第二写入通道。

## 4. 用户操作与验收

既有“材料”任务入口内提供“已收纳材料”、明确导入文件/网页，以及阅读/添加到画布；不新增全局工作模式。显示原名称、大小、导入时间与完整性错误，导入成功文案明确“已复制到项目”。只读阅读、导入完成和添加卡片分别显示真实结果；失败保持选择/草稿，不自动重试创建。

所选卡片提供导出入口，画板提供导入卡片入口，预览数量与携带材料后确认。原 Card 修改不联动已复制 Card。跨工作区复制出处仅解释来源，不把源 ID 绑定到目标同名对象。重跑/版本恢复/撤销/Candidate 与绑定安全规则不变。

必须覆盖：新项目不污染代码目录；旧格式不自动迁移；格式损坏拒绝；单写者与失败释放锁；内外文件导入后删除/修改原文件仍可读；同名/同字节/并发/超限/坏哈希/符号链接；无 Board 导入；跨画布材料复用且卡片独立；跨 workspace 复制原件及出处；导出/备份/恢复/Checkpoint 全历史材料闭合；事务故障、重启、取消、重复提交；桌面与 390px 浏览器交互；Mac make/packed smoke。全部测试使用临时项目，不能迁移或改写用户当前工作区。

## 5. 对象与命令

原件位于 `materials/<sha256>/original.txt|pdf|bin`，扩展名由字节判定；同目录 `record.json` 保存不含正文的材料记录。包内记录增加 `data`（规范 base64）。记录字段为 `formatVersion: 1`、`id`、`path`、`name`、`byteLength`、`sha256`、`createdAt` 和可选网页 `source: { url, title, capturedAt }`。网页收纳的是已取得正文；同字节去重沿用首次记录的显示名称和来源，不声称覆盖所有相同内容的网址。

HTTP 路径均以 `/graphmind/api/v2` 为前缀：

| 命令 | 输入与结果 |
| --- | --- |
| `POST /files/import` | `{ path }` → `{ path, copied, asset }`；已收纳路径核对后可复用 |
| `GET /materials` | `{ assets }`，不返回 base64 正文 |
| `GET /materials/:id/content` | `{ text }`；只允许最多 1,000,000 字节的 UTF-8 文本预览 |
| `POST /materials/previews/:id/original` | 将冻结网页正文或一致 PDF 原件收纳；重复同预览复用结果 |
| `POST /boards/:id/cards/export` | `{ cardIds }`，1–100 张；返回带 `selection: true` 的 BoardArtifact V2；与普通批量撤销上限一致 |
| `POST /boards/:id/cards/import` | `{ artifact, baseRevision, position: { x, y } }` → `{ board, cards }`；目标 CAS，新增身份 |

所选卡片只读 `copiedFrom: { workspace, board, card, version }` 为包外出处字符串，不能解析成目标工作区对象；无 Head 时 version 为空，旧布局 workspace 标为 `legacy-workspace`，不伪造稳定身份。导入一次构成一个当前会话 create history；撤销仅移除新卡，材料仍保留。

原件与索引整目录 rename；跨资产/Board 的 journal 记录本次新资产 ID，追加卡片还记录目标 Board 前态。失败恢复先恢复旧 Board，再撤销本次新增资产，已有共用原件不删除。进程重启先完成 journal 恢复再开放应用。响应丢失时 UI 保留结果待核对状态，不自动重试；跨进程请求不宣称幂等。

损坏原件为 `MATERIAL_CORRUPT`，路径/包内容非法为 `MATERIAL_INVALID`，超限为 `MATERIAL_LIMIT`；PDF 冻结预览与收纳字节不一致为 `MATERIAL_PREVIEW_CONFLICT`，禁止把新字节挂到旧摘录。目标 Board 改变仍为 `BOARD_CONFLICT`，不增加强制覆盖入口。布局错误为 `WORKSPACE_FORMAT_INVALID`，迁移参数/状态错误为 `WORKSPACE_MIGRATION_INVALID`。

旧 Backup V1/V2 恢复继续生成原根级布局，V3/V4 恢复生成新项目布局和全新 workspace 身份。备份中的 Checkpoint 保留独立完整 artifact，因此其原件也计入序列化总量；不承诺 JSON 包跨检查点压缩去重。旧外部引用仍是外部依赖，不凭路径为其补写原件。
