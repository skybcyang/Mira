## 产品命题与真实生成

案例要展示从有出处的材料逐步推导、人工核对与继续工作，不能用预写结果冒充模型运行。四张画板分别处理发布证据、斯密原典、AI 编程研究与证据文章。

通过正常 Node Host / HTTP / Transformation / Run 路径调用用户指定的 Kimi 服务。服务地址为 `https://api.kimi.com/coding/v1`，请求和响应模型均为 `k3`。13 次生成全部成功，12 次初次结果直接采用，写作重跑的第 13 次结果因运行期间人工改稿进入 Candidate。

[脱敏运行凭据](evidence/2026-09-10-kimi-example-receipts.json)记录提供方 response ID、模型、起止时间、usage、对应 Run ID 与原始输出 SHA-256。本批 13 次生成的提供方 total_tokens 合计 51,409（不含连接测试）；这不是费用账单。每次响应正文与 Mira Run 输出的 SHA-256 相同，原始 AI CardVersion 正文也与对应 Run 输出逐字相同。凭据是本次客户端采集记录，不是提供方签名证明。

密钥只传入生成进程环境与内存设置，未写入脚本、截图、凭据或导出包。生成后关闭含密钥的 Host，浏览器验收使用不配置模型的临时预览 Host。

## 文档治理与复用

四个原公开包与完整备份替换为真实 Kimi 数据；移除 `examples/card-workflows/` 下三份旧人工简单包及重复说明，统一从 `docs/examples/` 下载，Git 可恢复旧素材。未删除用户画板、Run 或归档数据。旧验证报告只追加 superseded 注记。

制作入口为 `scripts/real-example-sources.mjs` 与 `scripts/generate-real-examples.mjs`。生成脚本会真实调用模型并在隔离 workspace 成功后更新案例文件，需环境变量 `MIRA_LLM_API_KEY`；默认 endpoint / model 如上，可用 `MIRA_LLM_BASE_URL`、`MIRA_LLM_MODEL` 覆盖。来源说明与编辑修订针对本批基线，不应无审阅地套到未来输出。

`scripts/review-real-examples.mjs <isolated-host-url>` 记录本批的人工版本追加与布局/导出过程；并非自动模型评测器，也不是一般用途的内容改写服务。重新制作后需要重新人工复核、截图与验收，不直接复制本报告的成功结论。
