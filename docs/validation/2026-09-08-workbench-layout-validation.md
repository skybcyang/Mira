补齐的契约一致性：Candidate 采用显式携带打开比较时的 `baseVersionId`；池快照请求只传 `poolSource` 与标签，服务端解析指定不可变版本、正文、出处及批内不重叠落位。普通单卡/批量创建拒绝伪造池出处，单卡入口拒绝误传池快照。所有成员验证完成后才进入一次 Board 原子更新；不生成 Transformation 或 Run。

没有增加依赖、领域对象或第二套桌面 UI；正文编辑仍追加 CardVersion，方法仍只铺计划。比较组件留在既有详情懒加载块，CSS 保持既有 18 个 owner 模块。

## 4. 真实浏览器记录

### 布局与编辑

- 1280×800：导航 84px；展开详情 800px；剩余画布 396px；body 无横向溢出。保存区保持在视口内。普通/展开间不重置正文。
- 最终构建断点测量：1440→详情 800、导航 84；1100→656/84；1099→800/54；720→634/54；719→全宽 719。所有测量中正文相同，body 无横向溢出。该记录核对布局和文本，不代表每个断点都独立完成全套流程。
- 800px 详情内来源 240px，与编辑器并列；来源返回恢复原普通宽度。656px 与 390px 详情改为同层阅读，编辑组件保留，返回原草稿并聚焦正文。
- 1024×768：方法任务右侧 392px，背景不可交互；Shift+Tab 从关闭按钮回到任务内最后一个命令。文件窗口加载临时目录，正常关闭；未导入文件。
- 390×844：详情全宽全高，无 body 横向溢出；最终构建保存正文/保存并新建按钮为 44px 高，底部 828px。关闭任务后底部导航恢复。
- 390×420：先复现保存区超出视口和编辑器被压缩，再修正动态高度与内部滚动。修正后文本区高度 160px，保存区处于 360–420px；聚焦正文可见。此为浏览器可视尺寸模拟，未唤起真实手机软键盘。
- 编辑与来源任务保留时打开灵感池，Escape 只关最上层池窗口；来源与草稿仍在。切换方法经过统一脏草稿确认，“继续编辑”保留正文。

### 候选比较与真实 API 冲突

临时目标卡 `card-d3wpejmts7lovq`、运行 `run-r5uwqimts7lovv`：运行期间先写入人工 v1，使固定模型输出成为 Candidate。

1. 打开比较读取 v1；比较保持打开时，通过临时服务写入人工 v2。
2. 点击采用仍提交 v1 基线，被服务端 409 拒绝；人工 v2 未覆盖，Candidate 保留。窗口仍显示原先已读 v1，决策暂停。
3. 显式“重新核对并比较”后才显示 v2，并恢复合法操作。
4. 1280px 下完整正文并列、差异显示新增/删除和行号；390px 下上下阅读且决策区可见。
5. 采用成功追加 v3，回到版本历史；v1/v2/v3 均可查。后续编辑验收另追加了 v4，不把该测试文本视为模型结果。

### 灵感与原上下文

- 在未保存、已展开的正文任务上打开池；全文阅读、选择并添加 1 条后，Card 数量由 3 变 4，池关闭，原草稿仍在；没有自动选中新卡或全图适配。
- 记录“只留在灵感池的测试记录”：池由 8 条变 9 条，Card 数量不变；保留记录模式，清空正文，不自动选中。未保存记录关闭时显示同层确认，“继续编辑”保留原文。
- 选中 3 条后用“生活”标签隐藏其中一条，再排序：已选项持续可达，最终顺序为“共做一道菜 / 留一个空座位 / 一张可以带走的菜单”，添加数量仍为 3。
- 390px 下摘要为单列，结果、已选与全文同层往返；底部添加区保持可见。宽屏静态摘要/列表结构正常，无漂浮动效。

### 外观与负载

- 通过外观入口切换 Studio、Editorial、Blueprint 的浅/深两种模式；六套 tokens 生效，导航与页面无横向溢出。对主要桌面、窄屏、编辑/来源、比较和池窗口做截图目视检查；没有对每个主题的每种状态都生成完整截图，也没有做自动对比度测量。
- 最终构建使用独立 50 卡片画板：DOM 确认 50 个节点；反复打开/关闭灵感池 3 次后仍为 50 个节点、0 个打开的 dialog，焦点回到灵感池按钮，未观察到明显卡顿。未做长期内存或帧率剖析。
- 开发期与最终构建收尾的浏览器 warning/error 日志均为空。最终预览已恢复正常浏览器尺寸。

## 6. 已知限制与交付边界

- 真实手机键盘、旋转、safe-area、中文输入法和打包 Electron UI 留待对应设备验证。本轮未改桌面宿主，不把 Web 结果当作 packed Desktop 发布验收。
- 未做真实模型质量或线上服务测试；临时模型只验证运行/人工更新/Candidate 的实际 API 链路。
- 池批量添加返回失败或结果未知时，本次窗口保留选择并禁用再次添加，提示关闭后核对画板；没有新增自动重试或幂等协议。该保守策略避免在未知写入结果下重复创建。
- 已产生的错误通知依照原通知策略保留，用户可关闭；重新比较或成功采用不会自动清除之前的错误历史。
- 验证结论限于上述实际证据；真机与长期性能部分不作为“全部验收通过”对外发布。
