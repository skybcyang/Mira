## 产品命题

表达风格独立于处理指导，二者共同进入模型请求。新步骤默认卡片简洁，可明确更换均衡表达/详细展开，阅读和调整完整规则，或使用原有表达。第一批默认随应用发行；workspace 默认管理未实现。

可计算的字符与 Markdown 结构约束由程序检查。失败保留完整正文与诊断，不自动截断、重跑或改变普通 Head/Candidate 规则。规则放入指令不保证语义保真，本批没有以更短或检查通过冒充质量提升。

## 实现正确性

- 先写失败测试：创建默认冻结、无效配置原子拒绝、方法与直接计划、Store 转发、Run 诊断；补充 UI 导航缺陷和空列表误判的失败回归，再做修复。
- 领域目录为三种 `1.0.0` 规则，全文 SHA-256 校验、严格字段与边界；创建/批量创建/直接计划解析一次。旧对象及旧方法缺字段不补默认，PATCH 缺字段保留、null 明确移除。
- Run 使用冻结输出要求和指导拼装 adapter 入参。运行中修改被拒绝；人工修改目标后，完整模型结果与检查进入 Candidate，不能覆盖人工 Head。
- 方法提取/应用、BoardArtifact 重映射、备份及 Checkpoint 保留规则与检查；坏摘要、正文篡改、检查数字不符会被拒绝。沿用现有原子提交与存储失败回归。
- 结构检查覆盖段落、标题、编号列表、空列表、GFM 表格、伪表格和代码围栏；字符包含空白并按 Unicode 码点计数。未配置的项目不显示“通过”。
- UI 保存导航曾漏比较 `drawer.output`，造成保存后留在原子页；新增导航意图测试复现并修复，迟到异步结果不能夺回已离开的面板。目录异步加载完成后焦点落到风格选择。
- Bridge 构建测试捕获 Markdown 实体依赖选择浏览器实现、无 DOM 启动报错。构建改为 neutral 解析条件；现有可执行 Cordis bundle 测试与最终构建均通过。

## UX 可发现性与浏览器证据

在本机 Codex 内置真实浏览器中运行 production Web 构建，后端为 Node runtime。演示 workspace 位于 `/tmp/mira-output-check.JzOOfP/workspace`，画板名明确为“输出设置验收 · 演示材料”；不使用实际用户 Board。模型适配器是固定文本测试替身，无 Kimi 请求、费用或外部工具操作。

- 桌面 1440×900 / 1280×720：从步骤进入输出要求，选择风格、展开全文并修改、设置字符/结构、保存返回和重新打开；输出与“材料精读”指导独立共存。
- 未保存时返回出现统一离开保护，继续编辑保留草稿；负数字符上限显示错误并禁用保存。保存后焦点返回输出入口，重新进入后聚焦风格选择。
- 390×844 深色/浅色：同层全屏设置和 Run 记录，无横向溢出；全文可滚动，返回和保存按钮可达，键盘焦点可见。1024×768 浅色详情也无横向溢出。工具截图在当次会话中检查；本报告未附持久截图文件。
- 成功运行一次，固定回复为“验证材料只能支持已表达的结论。未明确的条件继续保留，不扩大推断。”；检查显示 `32 / 10` 字符超限、条目结构未通过，32 字符完整正文仍保存为目标唯一版本。
- 保存下一次上限为 12 后，历史仍显示 10。直接读取临时持久文件也确认当前上限 12、Run 上限 10、冻结指导“材料精读”、两项检查 false、结果 applied、目标版本数 1。
- 最终验收页控制台 warn/error 为空。未验证真实触屏、软键盘或原生 Electron UI；浏览器证据不替代这些项目。
