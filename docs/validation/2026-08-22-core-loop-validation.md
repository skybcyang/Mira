# Mira 核心闭环验证记录

- 日期：2026-08-22
- 验证对象：`选择内容 -> 指定下一份成果 -> 生成可编辑产物 -> 继续转化 / 安全更新`
- 验证性质：技术狗食与专家验证
- 结论状态：部分结构成立，但不能据此声称已完成用户验证

> **当前解释（2026-08-23）**：本文保留重构前的时间点事实。报告中的“多来源被接口阻断”和“人工编辑会被直接覆盖”已由后续 v2 多来源、不可变 Version、compare-and-swap 与 Candidate 实现解决，证据见 [`2026-08-23-slice-implementation-validation.md`](2026-08-23-slice-implementation-validation.md)。报告中曾讨论的“一键分支”和旧 Workflow/Action 心智已被当前产品定义取代；现行规则是只有用户手动画图才创建分支，WorkflowTemplate 只从已验证路径提取，应用后铺出零 Run 的线性计划。本文不能作为当前功能规格。

## 1. 研究边界

本轮由开发环境中的专家操作者、直接 API 诊断、代码级诊断和已有运行记录共同完成。它不是外部用户研究，也没有招募目标用户、盲测、无引导任务或统计样本。因此，本轮只能回答“当前产品结构能否表达核心闭环、哪里被实现阻断”，不能回答以下问题：

- 普通用户是否自然理解“选中内容，再决定下一份成果”的使用方法；
- 用户能否在五分钟内独立得到第一份有效产物；
- 建议语言、选择反馈和版本提示是否足够可发现；
- 目标用户是否认为产物有实际价值，并愿意继续使用。

证据分为四类：实时狗食运行（RT）、直接 API 诊断（API）、历史成功运行（HIST）和代码级直接诊断（DIAG）。历史记录只用于证明已经发生过的结构行为，不替代当前端到端验证。

## 2. 判定维度

| 维度 | 本轮判定问题 | 不得混淆为 |
| --- | --- | --- |
| 产品命题 | 内容卡、局部转化、可编辑产物和连续演化这组对象是否能表达目标工作方式 | 用户已经需要或喜欢该产品 |
| 交互可发现性 | 专家是否能找到并操作入口；当前界面是否展示必要反馈 | 未经提示的普通用户也能发现 |
| 产物质量 | 实际成功输出是否遵守材料与目标，能否继续加工 | 所有模型、课题和用户都能得到高质量结果 |
| 实现阻断 | API、运行时、数据模型或写回规则是否使课题无法完成或造成数据风险 | 产品命题本身不成立 |

## 3. 总结

| 课题 | 产品命题 | 交互可发现性 | 产物质量 | 实现阻断 | 本轮结论 |
| --- | --- | --- | --- | --- | --- |
| T1 单卡到第一版 | 路径对象已创建，但闭环未完成 | 只证明专家可操作自定义入口 | 无实时产物，无法评价 | 两次 `kimi-coding/k3` 生成均 `TIMEOUT` | 未验证，不是否定命题 |
| T2 多卡合成 | 目标结构尚未通过产品接口建立 | 多选后没有可执行入口 | 无多卡产物，无法评价 | 建议与转化 API 都明确拒绝三来源 | 实现阻断 |
| T3 连续转化 | 历史 run 证明“产物再作来源”的结构成立 | 当前画板链不完整，不能评价完整交互 | 三次历史输出与各自目标相符 | 删除后早期节点和转化不在当前 board | 结构成立，当前追溯不完整 |
| T4 人工编辑安全 | “人工编辑优先”当前未满足 | 未做端到端 UI 诊断 | 不适用；人工内容被替换 | 代码级诊断证明同一目标被无提示覆盖 | 安全硬失败 |

总体上，只能确认 Mira 的单卡转化对象和单卡连续转化结构有可行性。多卡主路径、稳定生成、当前画板中的完整追溯，以及人工编辑保护均未形成可对外验证的闭环。

## 4. T1：单卡模糊想法到第一版

### 4.1 课题与材料

材料摘要：远程团队的会议决定散落在聊天、文档和个人记忆中；用户希望减少重复确认，但尚未决定做模板、机器人还是每周摘要，也不希望引入额外维护系统。

用户任务：把单张想法卡推进为一页、可发给合作者讨论的方案，包含目标用户、核心问题、最小形态和待验证问题；不得替用户提前决定具体产品形态。成功后应能人工加入“暂定名称：回声”。

### 4.2 实时证据

| 证据 | ID |
| --- | --- |
| Board | `board-22vi9fmt4015t3`（验证 T1 · 模糊想法到方案） |
| 来源卡 | `card-oqfaqxmt404m6z` |
| 转化 | `transform-vi7cb3mt406eu7`，`runCount: 2` |
| 目标占位卡 | `card-10fcxkmt406eu7`，最终 `artifactState: failed` |
| 第一次实时运行 | `run-zc3uhxmt406eug` |
| 第二次实时运行 | `run-dhlnspmt40bfwk` |

两次 run 都正确冻结了唯一来源卡，并进入生成阶段。实时 DSH 会话显示使用 `kimi-coding/k3`；每次运行都经历两次自动重试，最终以 `TIMEOUT` 和“模型请求超时，已自动重试；请稍后再次生成”失败。两个 run 均无 `outputNodeId` 和产物正文。

### 4.3 四维结论

- 产品命题：专家成功创建了“单来源 -> 自定义转化 -> 目标占位卡”，说明对象与入口能表达预期动作；没有生成结果，不能判定完整命题成立。
- 交互可发现性：只证明熟悉目标的专家能够选择卡片并填写自定义下一步。没有外部用户，不能得出“入口自然可发现”的结论。
- 产物质量：两次都没有实时产物，不能评价内容是否完整、是否避免替用户做决定，也未执行“加入暂定名称”的编辑验证。
- 实现阻断：当前 provider/model 的超时使第一份产物无法到达。错误被记录且来源未丢失，但“稍后再次生成”在连续两次失败后不是充分恢复路径。

## 5. T2：三张材料形成一页决策

### 5.1 课题与材料

Board `board-32w5ugmt40gblg` 包含三张来源卡：

- `t2-interviews`：12 位上海新居民访谈；8 人不会串联景点，7 人希望两小时内，5 人关心厕所与遮雨/树荫，只有 3 人愿意安装新 App。
- `t2-constraints`：两周内、1 名编辑、无开发资源、预算 2000 元、只做徐汇 1 条路线、必须有雨天替代方案。
- `t2-success`：招募 30 人，至少 12 人走完、8 人愿意推荐，并记录中途放弃点与原因。

用户任务：同时使用三张材料，形成包含载体建议、范围、执行步骤、成功门槛和风险的一页试点决策。

### 5.2 直接 API 证据

| 证据标签 | 请求与结果 |
| --- | --- |
| `T2-API-SUGGEST-3SRC` | `POST /boards/board-32w5ugmt40gblg/suggestions`，传入三张来源卡 ID；返回 HTTP 400、`SUGGESTION_SOURCE_INVALID`、`first slice requires exactly one source card` |
| `T2-API-CREATE-3SRC` | `POST /boards/board-32w5ugmt40gblg/transformations`，传入三张来源卡 ID；返回 HTTP 400、`TRANSFORMATION_SOURCE_INVALID`、`first slice requires one source card` |

这两个请求都在创建 run 之前被拒绝，因此没有多来源 transformation ID 或 run ID。该 board 后续留下的单来源失败转化不是 T2 多卡结果，不纳入多卡证据。

### 5.3 四维结论

- 产品命题：本轮没有建立“三来源 -> 一产物”的产品对象，不能判断多材料合成是否为有效用户方法。
- 交互可发现性：当前建议面板仅在恰好选中一张内容卡时渲染；专家选择多卡也无法进入目标输入与执行路径。这是入口不存在，不是用户没发现。
- 产物质量：没有多卡运行和产物，不能评价约束保真、冲突处理或决策质量。
- 实现阻断：建议 API 与转化创建 API 都硬编码单来源限制。底层快照构建已按 `sourceNodeIds` 循环读取来源，但产品接口尚未开放这项能力。

- 产品命题：三个成功 run 的目标/来源 ID 首尾相接，证明内容产物无需变成 Action，即可再次作为下一轮唯一来源；连续转化的数据结构成立。

- 产物质量：专家检查显示三份输出分别对应材料清单、问题提炼和方案，且后一步实际读取了前一步正文。它只能证明这一个历史课题的输出可继续加工。
- 实现阻断：运行历史仍在，但当前 board 因删除不再保存完整链。追溯体验缺少删除保护、墓碑或从 run 历史恢复关系的机制。

## 7. T4：人工编辑后的安全更新

### 7.1 课题与诊断范围

协议材料是一张 Beta 发布基础方案卡：9 月 15 日发布、100 位现有付费客户、邮件通知、负责人林岚、登录错误率超过 2% 回滚。预期先生成检查清单，再把产物人工改为“首批仅 20 人”并加入不可丢的法务审批信息；来源变化后，系统只能提示过期，并通过明确的再生成或分支选择保留人工编辑和旧版。

本轮没有伪造 T4 board 或 run。证据 `T4-DIAG-DIRECT-WRITE` 是无持久 run ID 的代码级 direct diagnostic，不是端到端 UI 运行：

1. 调用前，目标卡 `target.text` 精确为 `[manual decision] keep me`。
2. 直接调用 `writeExecutableArtifact({ board, executableId, outputText: "regenerated output" })`。
3. 返回同一个 target ID，`created: false`。
4. 调用后，目标卡 `target.text` 精确为 `regenerated output`。

实现位置为 `bridge/executable-model.js:54-61`；已有目标卡时，无条件执行 `target.text = outputText`，没有比较最近生成版本、当前人工文本、输入指纹或目标指纹。

### 7.2 四维结论

- 产品命题：“人工编辑优先、重新生成可恢复、分支保留原卡”是核心安全要求；当前行为直接违反这一要求。
- 交互可发现性：本轮没有运行 stale 提示、覆盖警告、版本查看或分支 UI，因此不能评价这些交互是否可发现。当前数据模型也没有支撑完整入口。
- 产物质量：无关。即使新输出质量更高，也不能无提示替换用户的人工决定。
- 实现阻断：这是确定性的数据安全缺陷。任何“再次生成”或运行中目标卡被编辑的情况，都可能在写回时静默丢失人工文本。

## 8. 设计与整理输入

### P0：先消除人工内容丢失

1. 为每次成功生成记录来源快照指纹、生成正文指纹和目标版本 ID；目标卡人工编辑后必须能与最近生成版本区分。
2. 写回前对比运行开始时的目标指纹与最新目标指纹。发生变化时不得调用无条件覆盖，转入显式 `conflict` / `needs_review` 状态。
3. 来源变化只标记 stale，不自动运行。提供“保留当前”“再生成新版本”“从这里分支”三个清晰结果，而不是一个含混的“再次生成”。
4. 再生成必须保留旧版完整正文；分支必须创建并行目标，原卡与人工编辑不动。
5. 增加代码级和端到端回归：唯一人工标记不得静默消失；运行期间编辑目标也必须触发冲突保护。

产品决策注记（2026-08-22）：验证中的“一键从这里分支”仅用于暴露数据安全要求，不进入最终默认交互。vNext 默认展示最新版本；分支只能由用户在画布上手动创建新关系与新目标，系统不得因再生成、来源变化或冲突自动创建分支。

### P1：补齐核心闭环并恢复可验证性

1. 多卡端到端：建议和创建 API 接受有序的 1..N 个内容来源；选择面板明确列出本次上下文；一条 transformation 连接全部来源与一个目标。
2. 运行可靠性：把 `kimi-coding/k3` 的超时、重试和最终失败作为可观测运行状态；提供可操作的重试入口，并在开始外部用户研究前建立稳定成功率基线。

   当前 `runs/` 中 transformation executable run 的开发期样本为 `4 succeeded / 13 failed / 1 interrupted`。该目录混合了功能开发、故障诊断和误触运行，不能当作产品成功率，但足以说明在用户验证前需要建立隔离课题、固定模型与明确分母的新基线。

3. 连续转化追溯：定义删除来源、产物或转化时的产品语义。至少保留可见墓碑或可从 run 历史恢复的关系，避免“run 在、画布链断了”。
4. 失败占位卡：明确保留、重试和删除规则，避免失败卡与有效产物混淆。
5. 外部用户研究：完成以上阻断后再招募至少 5 名目标用户，执行无教学任务，记录首份有效产物耗时、求助次数、多卡上下文正确率、第二次转化率和任何人工内容丢失。

## 9. 最终判断

本轮支持的最强结论是：Mira 的“内容 -> 局部转化 -> 内容产物 -> 再次局部转化”在历史单卡数据结构上成立。它尚未证明普通用户会自然采用这套方法，也尚未形成可稳定验证的完整产品：实时单卡生成被模型超时阻断，多卡被 API 阻断，当前连续链追溯不完整，人工编辑则存在已被 direct diagnostic 证实的静默覆盖风险。

在 P0 安全保护完成前，不应把“再次生成”作为面向用户的正式能力；在 P1 多卡、运行可靠性和追溯完成前，不应宣称 Mira 的核心闭环已经通过用户验证。
