# 项目打开与画板恢复验证

日期：2026-09-14，Asia/Shanghai。实现分支 `codex/project-opening`，基线 `main` 的 `5949147`；产品确认 `d0b1aaf`，宿主 `f8dd40b` / `73ab872`，前端集成 `eb123af`。当前是本地实现，未合入 main、推送、发布或替换安装版。

## 产品命题

默认继续上次成功打开的项目；每项目恢复自己的打开项、常用和当前画板。没有记录或关闭全部画板时进入项目总览，零自动 Board / Run。总览可以阅读材料、记录灵感和查看方法；写入画板与应用方法仍需要明确目标。规则唯一来源为[项目打开规格](../specs/project-opening.md)。

切换先处理页面草稿，再等待导航保存并核对整个项目的运行与待处理结果。宿主排空已接收写入、拦截新写入，验证候选项目的路径、锁、runtime 和完成恢复的 renderer；成功后才提交本机记录并关闭旧项目，失败保留旧项目。原生菜单与页面菜单走同一离开入口。

## 实现正确性

- 定向 Store 回归先观察原自动建 Board、恢复忽略宿主记录、归档后打开未选画板等失败，再实现通过。覆盖空项目、无记录、总览与 opened 并存、项目 A/B 隔离、恢复读取失败、偏好保存失败与重试，以及 1000 项边界不淘汰已打开画板。
- 真实 React 组件和 hook 覆盖总览搜索/空/错误状态、无 Board 方法禁写、键盘菜单、页面与原生意图的相同草稿门禁、重复点击、取消/失败保留项目及焦点返回。
- Bridge 临时文件系统和真实 HTTP 覆盖项目身份、严格导航校验、任一画板的 Run/Candidate、损坏 Run 拒绝切换、已接收写入排空、旧宿主与候选宿主的写入门禁、取消后恢复写入。未以 mock UI 替代这些集成测试。
- Desktop 临时状态覆盖跨重启隔离、最近 10 项、串行原子写入、损坏记录、真实锁冲突、目标 renderer 失败回退、提交失败后重试。迟到导航等待候选提交后保存，不覆盖较新记录；renderer 就绪检测等待项目/画板恢复，读取错误立即失败。
- 独立审阅发现并修复导航容量与失败队列重试问题；最终跨模块复查没有未解决的实际缺陷。
