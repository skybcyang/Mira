# 三个可导入的内容工作流示例

先导入 `interview.mira-board.json`，从左到右阅读四张卡，约 5 分钟。

这些是开发时编写、静态核对的教学样本，不是真实用户材料。所有输入情境、人物和技术方案均为虚构；所有中间成果与最终成果均以人工内容路径保存（`origin: human`）。没有实际模型执行，`runs` 始终为空，不包含伪造的 AI 输出历史、性能实测或用户研究结果。

## 选择示例

| 文件 | 三步路径 | 练习重点 |
| --- | --- | --- |
| [interview.mira-board.json](interview.mira-board.json) | 提取证据 → 归纳主题 → 产品建议 | 区分材料、推断和待验证计划 |
| [technical-comparison.mira-board.json](technical-comparison.mira-board.json) | 明确约束 → 比较方案 → 决策记录 | 保留估计与未知，明确转向条件 |
| [writing.mira-board.json](writing.mira-board.json) | 组织提纲 → 完成初稿 → 编辑成文 | 内容逐步完善，不新增无依据事实 |

每份文件只有四张普通 Markdown Card 和三条线性 Transformation。每一步仅引用上一张卡；需要传递的依据保留在相邻成果中。它们不包含文件引用、外部资料、密钥、分组、运行记录或方法出处，也不会安装 WorkflowTemplate。

## 导入与阅读

1. 打开 Mira 的“管理画板”，选择“导入画板副本”。
2. 选择一个 `.mira-board.json` 文件，核对预览中的 4 张卡、3 个步骤和 0 条 Run。
3. 点击“导入新副本”，进入新画板。重复导入会再次创建全新身份，不覆盖已有画板。
4. 阅读材料、各步成果与步骤说明，人工判断这条方法是否符合你的任务；示例的非空正文不等于已经通过实际业务验证。

## 明确保存与复用方法

1. 选中第一条转化步骤，在关系详情点击“保存为方法”。从第一步开始才能包含完整三步路径。
2. 核对步骤、成果和验收条件，填写方法名称与具名材料输入槽，明确保存。模板只保存方法，不复制示例正文或 Run。
3. 在另一张画板准备自己的材料，从“方法”打开该模板并点击“使用”；先检查计划草稿，再显式绑定新材料、添加步骤。
4. 需要生成时，再在目标步骤点击“运行到这里”。添加方法计划本身始终是零 Run；实际模型运行需要你已配置可用模型。

直接在这份已填好的示例上点击“运行到这里”，不会重写从未有已采用 Run 的人工成果。需要测试完整生成时，使用上面的“保存方法 → 新材料 → 新计划”路径；不要删除或清空原示例来假装已有运行。

## 验证边界

自动测试通过真实导入服务、磁盘 staging 与领域校验，在临时 workspace 连续导入两次，核对身份独立、引用闭合、正文 digest、零 Run、零模板安装、可重新导出，以及源文件不变。临时目录由测试清理，不访问真实 Mira workspace。

这只证明可移植格式和读写路径。材料与成果是人工路径的演示内容；模型生成效果、实际场景有效性和浏览器易用性需要另外验证，不能由格式测试代替。
